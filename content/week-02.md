# 1️⃣ 1교시 \| AI 발전의 흐름과 머신러닝의 기본 구조
## 1. 인공지능 발전의 흐름
AI의 발전은 하나의 기술이 직선적으로 좋아진 과정이 아니다. 문제를 표현하는 방식, 사용할 수 있는 데이터의 양, 컴퓨팅 성능, 알고리즘이 함께 바뀌면서 접근법도 달라졌다.
초기에는 사람이 논리 규칙을 직접 작성하는 방식이 중심이었고, 이후 데이터에서 패턴을 학습하는 머신러닝이 확산됐다. 대규모 데이터와 연산 자원의 증가, 신경망 학습 기법의 발전은 딥러닝의 성장을 촉진했다.
### 역사에서 배울 점
- 새로운 AI 기술은 데이터와 컴퓨팅 환경의 영향을 크게 받는다.
- 시연에서의 성공과 실제 운영에서의 안정성은 다를 수 있다.
- 기술에 대한 기대가 실제 성능보다 지나치게 커지면 과도한 투자와 실망이 반복될 수 있다.
## 2. 규칙 기반 시스템(Rule-Based System)과 전문가 시스템(Expert System)
규칙 기반 시스템은 사람이 조건과 행동을 명시적으로 정의한다. `IF 조건 THEN 결과` 구조가 대표적이다. 규칙이 명확한 문제에서는 설명이 쉽고 결과가 일관적이라는 장점이 있다.
전문가 시스템은 특정 분야 전문가의 지식을 지식베이스(Knowledge Base)에 저장하고 추론 규칙으로 판단을 지원하는 초기 AI 방식이다.
### 한계
- 예외가 많아질수록 규칙 관리가 복잡해진다.
- 새로운 상황마다 사람이 규칙을 추가해야 한다.
- 이미지·음성처럼 특징을 언어 규칙으로 표현하기 어려운 문제에 약하다.
## 3. 머신러닝(Machine Learning)으로의 전환
머신러닝은 사람이 모든 판단 규칙을 직접 작성하는 대신 데이터에서 패턴을 학습해 모델을 만드는 접근이다.
**문제 정의 → 데이터 수집 → 특징 구성 → 학습 → 모델 → 새로운 입력 → 예측**
예를 들어 스팸메일 분류에서 모든 스팸 문구를 규칙으로 나열하는 대신 정상·스팸 사례를 학습시켜 모델이 패턴을 찾도록 한다.
### 핵심 의미
머신러닝은 ‘사람이 규칙을 쓰지 않는다’는 뜻이 아니다. 어떤 데이터를 사용할지, 어떤 특징을 볼지, 무엇을 정답으로 정의할지, 어떤 오류를 더 중요하게 볼지는 사람이 설계한다.
## 4. 대표 학습 방식
### 지도학습(Supervised Learning)
입력과 정답이 함께 주어지며 둘의 관계를 학습한다. 분류와 회귀 문제에 많이 사용된다.
### 비지도학습(Unsupervised Learning)
정답 없이 데이터 안의 구조와 유사성을 찾는다. 군집화, 이상 탐지, 차원 축소 등에 활용된다.
### 강화학습(Reinforcement Learning)
행동 결과로 보상(Reward)을 받고 장기적으로 더 큰 보상을 얻는 전략을 학습한다.
### 선택 기준
학습 방식은 ‘더 고급인 방식’을 고르는 문제가 아니라 정답 데이터의 존재, 목표의 형태, 피드백 방식에 따라 달라진다.
## 5. 딥러닝(Deep Learning)과 인공신경망(Neural Network)
딥러닝은 여러 층의 인공신경망을 이용해 복잡한 표현을 학습하는 머신러닝의 한 분야다. 기존 방식에서는 사람이 특징을 직접 설계하는 비중이 컸지만, 딥러닝은 데이터에서 유용한 표현을 단계적으로 학습할 수 있다.
### 확산 배경
- 대규모 디지털 데이터 증가
- 그래픽처리장치(Graphics Processing Unit) 등 연산 성능 향상
- 학습 알고리즘 개선
- 클라우드·분산학습 인프라 확대
### 주의점
딥러닝이 항상 더 좋은 것은 아니다. 데이터가 적거나 설명 가능성이 중요하고 규칙이 명확한 문제에서는 더 단순한 모델이 적합할 수 있다.
## 6. 특징(Feature), 라벨(Label), 손실함수(Loss Function)
특징은 모델이 판단에 사용하는 입력 정보이고 라벨은 모델이 맞혀야 하는 목표 값이다. 고객 이탈 예측에서는 가입 기간, 이용 횟수, 문의 횟수가 특징이 될 수 있고 이탈/유지가 라벨이 될 수 있다.
손실함수는 모델의 예측과 정답 사이의 차이를 수치로 표현한다. 모델은 학습 과정에서 손실이 줄어들도록 내부 값을 조정한다.
### 중요한 질문
- 특징이 실제 예측 시점에 사용할 수 있는 정보인가?
- 라벨이 해결하려는 문제를 제대로 나타내는가?
- 손실을 줄이는 것이 실제 업무 목표와 일치하는가?
---
### 심화 해설 \| 학습 문제를 분류·회귀·군집 관점으로 구분하기
머신러닝 과제는 단순히 ‘AI를 만든다’가 아니라 어떤 형태의 결과를 원하는지에 따라 문제 구조가 달라진다. 분류(Classification)는 정해진 범주를 예측하고, 회귀(Regression)는 연속적인 숫자 값을 예측하며, 군집(Clustering)은 정답 라벨 없이 비슷한 대상을 묶는다. 고객 이탈 여부는 분류, 매출액 예측은 회귀, 고객 유형 탐색은 군집 문제로 볼 수 있다.
문제 유형을 잘못 정의하면 모델의 성능이 높아도 업무 목적을 달성하기 어렵다. 예를 들어 ‘이 고객이 이탈할 것인가’를 예측해야 하는데 고객을 단순 군집으로만 나누면 직접적인 의사결정에 필요한 결과가 나오지 않을 수 있다.
### 심화 해설 \| 특징 공학(Feature Engineering)의 의미
특징 공학은 원시 데이터에서 모델이 학습하기 좋은 입력 변수를 설계하는 과정이다. 고객의 최근 구매 횟수, 평균 결제금액, 마지막 방문 이후 경과일처럼 원시 기록을 업무 의미가 있는 변수로 변환할 수 있다.
딥러닝에서는 특징을 자동으로 학습하는 비중이 커졌지만, 어떤 데이터를 입력하고 어떤 기간을 사용할지 결정하는 일은 여전히 중요하다. 특히 미래 정보를 특징에 섞으면 데이터 누수가 발생할 수 있으므로 실제 예측 시점에 사용할 수 있는 정보인지 확인해야 한다.
### 심화 해설 \| 학습률(Learning Rate)과 반복 학습의 직관
모델은 한 번의 계산으로 최적의 상태가 되는 것이 아니라 여러 번 데이터를 보면서 내부 값을 조금씩 조정한다. 학습률은 한 번의 업데이트에서 얼마나 크게 값을 바꿀지 결정하는 대표 설정이다.
학습률이 지나치게 크면 좋은 지점을 지나치며 불안정하게 움직일 수 있고, 너무 작으면 학습이 매우 느리거나 충분히 개선되지 않을 수 있다. 이 개념은 세부 수식을 계산하기보다 ‘모델 학습도 조정 폭과 반복 횟수의 균형이 필요하다’는 직관으로 이해한다.
### 심화 해설 \| 편향(Bias)과 분산(Variance)의 균형
단순한 모델은 복잡한 패턴을 충분히 학습하지 못할 수 있고, 지나치게 복잡한 모델은 학습 데이터에 과도하게 맞춰질 수 있다. 전자는 높은 편향, 후자는 높은 분산 문제와 연결된다.
좋은 모델은 학습 데이터에만 맞는 것이 아니라 새로운 데이터에서도 안정적으로 작동해야 한다. 따라서 모델 선택은 ‘가장 복잡한 모델’을 고르는 것이 아니라 일반화 성능이 좋은 모델을 찾는 과정이다.
### 심화 해설 \| 베이스라인(Baseline)을 먼저 만든다
새 모델의 성능을 평가하려면 비교 기준이 필요하다. 이를 베이스라인이라고 한다. 예를 들어 고객 이탈률이 10%라면 모든 고객을 ‘이탈하지 않음’으로 예측해도 정확도는 90%가 된다. 이 상황에서 정확도 91%인 모델은 숫자만 보면 높아 보이지만 실제 개선은 매우 작을 수 있다.
베이스라인을 설정하면 AI 모델이 단순 규칙이나 기존 방식보다 실제로 개선되었는지 확인할 수 있다.
# 2️⃣ 2교시 \| 학습 데이터 분리와 모델 성능 평가
## 1. 머신러닝 개발의 기본 흐름
머신러닝 개발은 모델을 한 번 학습하고 끝나는 과정이 아니다. 문제 정의, 데이터 준비, 학습, 평가, 배포, 운영 모니터링이 연결된 반복 과정이다.
1. 문제 정의
2. 데이터 수집·정제
3. 특징·라벨 구성
4. 데이터 분리
5. 모델 학습
6. 검증과 조정
7. 시험 데이터 평가
8. 서비스 적용
9. 운영 중 성능 감시
## 2. 학습 데이터(Training Data)·검증 데이터(Validation Data)·시험 데이터(Test Data)
학습 데이터는 모델이 패턴을 배우는 데 사용하고, 검증 데이터는 모델 구조와 설정을 비교·조정하는 데 사용한다. 시험 데이터는 최종 모델이 처음 보는 데이터에서도 잘 작동하는지 확인하는 용도다.
시험 데이터를 반복해서 확인하면서 모델을 조정하면 실제로는 시험 데이터 정보가 개발 과정에 스며들어 공정한 평가가 어려워진다.
### 실무 원칙
- 각 데이터의 역할을 분리한다.
- 동일 사용자의 기록이 여러 집합에 섞이지 않도록 주의한다.
- 실제 서비스 환경과 유사한 기준으로 시험 데이터를 구성한다.
## 3. 데이터 누수(Data Leakage)
데이터 누수는 실제 예측 시점에는 알 수 없는 정보가 학습 과정에 포함되어 성능이 비정상적으로 높게 보이는 문제다.
예를 들어 퇴사 예측 모델에 ‘퇴사 처리 완료 여부’를 특징으로 넣으면 정확도는 매우 높게 나올 수 있지만 실제 예측에서는 사용할 수 없는 정보다.
### 점검 질문
- 이 정보는 실제 예측 시점에 존재하는가?
- 정답 이후에 발생한 정보가 포함되지 않았는가?
- 전체 데이터를 먼저 가공한 뒤 분리하면서 시험 정보가 섞이지 않았는가?
## 4. 과적합(Overfitting)과 일반화(Generalization)
과적합은 모델이 학습 데이터의 패턴뿐 아니라 우연한 잡음까지 지나치게 학습해 새로운 데이터에서 성능이 떨어지는 상태다. 일반화는 학습하지 않은 새로운 데이터에서도 안정적으로 성능을 내는 능력이다.
### 과적합의 대표 신호
- 학습 성능은 매우 높지만 검증 성능이 낮다.
- 데이터가 조금만 바뀌어도 결과가 크게 변한다.
- 모델이 복잡해질수록 검증 성능이 오히려 떨어진다.
### 대응
정규화(Regularization), 교차검증(Cross-Validation), 조기 종료(Early Stopping), 데이터 다양성 확보 등을 활용할 수 있다.
## 5. 혼동행렬(Confusion Matrix)
이진 분류에서는 예측 결과를 참양성(True Positive), 거짓양성(False Positive), 거짓음성(False Negative), 참음성(True Negative)으로 나눈다.
이 네 결과를 구분하면 단순 정확도만으로는 보이지 않는 오류의 종류를 파악할 수 있다.
### 사례
질병 선별에서는 실제 환자를 놓치는 거짓음성이 큰 피해를 만들 수 있고, 스팸 필터에서는 정상 메일을 스팸으로 막는 거짓양성도 중요하다.
## 6. 정확도·정밀도·재현율·F1 점수
정확도는 전체 예측 중 맞힌 비율이다. 그러나 양성 사례가 매우 적은 불균형 데이터에서는 높은 정확도가 좋은 모델을 의미하지 않을 수 있다.
정밀도는 모델이 양성이라고 판단한 것 중 실제 양성의 비율이고, 재현율은 실제 양성 중 모델이 찾아낸 비율이다. F1 점수는 정밀도와 재현율을 함께 고려하는 지표다.
### 지표 선택의 원칙
- 어떤 오류가 더 큰 피해를 만드는지 먼저 정의한다.
- 하나의 지표만으로 모델을 평가하지 않는다.
- 전체 성능뿐 아니라 집단별 성능 차이도 확인한다.
## 7. 교차검증(Cross-Validation)과 데이터 드리프트(Data Drift)
교차검증은 데이터를 여러 부분으로 나눠 반복적으로 학습·평가해 특정 분할에만 의존하지 않는 성능을 확인하는 방법이다.
데이터 드리프트는 서비스 운영 중 입력 데이터의 특성이 학습 시점과 달라지는 현상이다. 계절, 정책, 사용자 행동, 시장 환경이 변하면 모델 성능도 달라질 수 있다.
### 운영 관점
좋은 모델은 출시 시점의 점수만 높은 모델이 아니라 시간이 지나도 성능 변화를 감지하고 재평가할 수 있는 모델이다.
## 8. 적용 실습 \| 모델 성능 해석
두 분류 모델의 혼동행렬을 비교하고 정확도·정밀도·재현율·F1 점수를 해석한다. 이후 의료 선별, 스팸 차단, 이상거래 탐지 중 한 상황을 선택해 어떤 모델을 사용할지 근거를 제시한다.
### 제출 내용
- 모델별 지표 비교
- 더 중요한 오류 유형
- 선택한 모델과 이유
- 추가로 확인해야 할 데이터 조건
## ### 심화 해설 \| 데이터 분리 방식은 시간과 사용자 구조를 고려한다
데이터를 무작위로 나누는 방식이 항상 적절한 것은 아니다. 미래를 예측하는 문제에서는 과거 데이터를 학습에 사용하고 이후 시점 데이터를 시험에 사용하는 시간 기반 분리가 더 현실적일 수 있다. 동일 사용자의 기록이 학습과 시험에 동시에 들어가면 모델이 사용자의 고유 패턴을 이미 본 상태에서 평가될 수 있다.
따라서 데이터 분리는 단순 비율이 아니라 실제 서비스에서 ‘처음 보는 상황’을 얼마나 잘 재현하는지가 중요하다.
### 심화 해설 \| 클래스 불균형(Class Imbalance)
사기 거래, 희귀 질환, 설비 고장처럼 실제 양성 사례가 매우 적은 문제에서는 클래스 불균형이 발생한다. 1만 건 중 사기가 100건뿐이라면 모든 거래를 정상으로 예측해도 정확도는 99%다.
이 경우 정확도만 보면 모델이 매우 좋아 보이지만 사기 탐지 목적은 전혀 달성하지 못한다. 그래서 정밀도, 재현율, F1 점수와 함께 업무상 어떤 오류가 더 큰 비용을 만드는지를 판단해야 한다.
### 심화 해설 \| 임곗값(Threshold)이 결과를 바꾼다
분류 모델은 종종 0과 1을 바로 출력하는 대신 ‘양성일 가능성’에 해당하는 점수를 계산한다. 이 점수가 어느 수준 이상이면 양성으로 판단할지 정하는 기준이 임곗값이다.
임곗값을 낮추면 더 많은 양성을 잡을 수 있지만 거짓양성이 늘 수 있고, 높이면 불필요한 경고는 줄지만 실제 양성을 놓칠 수 있다. 따라서 임곗값은 모델의 고정된 속성이 아니라 업무 위험과 비용을 반영해 설정하는 운영 결정이다.
### 심화 해설 \| 교차검증(Cross-Validation)의 목적
한 번의 학습·검증 분할만 사용하면 우연히 특정 데이터 구성이 유리하거나 불리할 수 있다. 교차검증은 데이터를 여러 번 다른 조합으로 나누어 모델의 성능이 안정적으로 유지되는지 확인하는 방법이다.
교차검증 결과의 평균뿐 아니라 변동 폭도 살펴보면 모델이 데이터 구성에 얼마나 민감한지 이해할 수 있다.
### 심화 해설 \| 모델 드리프트(Model Drift)와 운영 모니터링
서비스가 시작된 후 시장, 사용자 행동, 정책, 상품 구조가 바뀌면 학습 시점의 패턴과 현재 데이터가 달라질 수 있다. 이때 모델의 실제 성능이 점차 떨어질 수 있다.
운영 단계에서는 입력 데이터의 분포, 예측 비율, 오류 사례, 사용자 피드백을 지속적으로 관찰해야 한다. 필요하면 모델을 다시 학습하거나 임곗값과 업무 규칙을 수정한다. AI 개발은 배포가 끝이 아니라 운영과 재평가가 이어지는 생애주기다.
### 심화 해설 \| 오프라인 평가와 온라인 평가
시험 데이터에서 좋은 성능을 내는 것을 오프라인 평가라고 볼 수 있다. 실제 서비스에서는 사용자 행동과 업무 결과를 관찰하는 온라인 평가가 필요하다. 추천 모델의 클릭률, 상담 분류의 처리시간, 오류 수정률 등이 예가 된다.
오프라인 성능이 높아도 실제 사용자가 결과를 이해하지 못하거나 검토 부담이 늘면 업무 성과는 낮아질 수 있다. 따라서 모델 지표와 서비스 지표를 함께 봐야 한다.
## 🔎 핵심 정리
- AI의 발전은 규칙 중심에서 데이터 학습 중심으로 확장됐으며 머신러닝과 딥러닝은 문제와 데이터 조건에 따라 선택해야 한다.
- 모델 개발에서는 특징·라벨·학습 목표를 정확히 정의하고 학습·검증·시험 데이터를 분리해야 한다.
- 과적합과 데이터 누수는 실제 성능을 과대평가하게 만드는 대표 문제이며 일반화 성능을 별도로 확인해야 한다.
- 정확도 하나가 아니라 정밀도·재현율·F1 점수와 오류 비용을 함께 보고 모델을 평가해야 한다.
## 🔎 추가 심화 학습 \| 머신러닝을 실제 운영까지 연결하기
머신러닝을 교실의 학습·시험 단계로만 이해하면 실제 서비스가 어떻게 만들어지는지 놓치기 쉽다. 현업에서는 모델 개발 이후에도 데이터 흐름, 배포, 모니터링, 재학습, 장애 대응이 계속 이어진다. 즉 모델은 완성품이라기보다 운영 시스템의 한 구성요소다.
### 데이터 파이프라인(Data Pipeline)
데이터 파이프라인은 여러 시스템에서 데이터를 수집하고 정리해 모델 학습이나 추론에 전달하는 일련의 흐름이다. 데이터가 매일 또는 실시간으로 들어오는 서비스에서는 이 과정이 자동화돼야 한다.
- 데이터 수집
- 형식 통일
- 오류·중복 제거
- 특징 생성
- 모델 입력
- 결과 저장
이 중 하나라도 문제가 생기면 모델 자체가 정상이어도 서비스 결과는 잘못될 수 있다.
### 모델 배포(Model Deployment)
학습이 끝난 모델을 실제 사용자가 이용할 수 있는 환경에 올리는 과정을 배포라고 한다. 실험 노트북에서 잘 작동하던 모델이 실제 서비스에서는 입력 형식, 처리 속도, 동시 사용자 수, 보안 조건 때문에 문제가 생길 수 있다.
### 추론 지연시간(Inference Latency)
추론 지연시간은 입력이 들어온 뒤 모델이 결과를 반환하기까지 걸리는 시간이다. 실시간 번역이나 결제 이상 탐지처럼 즉각적인 응답이 필요한 서비스에서는 정확도뿐 아니라 지연시간도 중요한 품질 지표다.
### 데이터 드리프트(Data Drift)
서비스가 운영되는 동안 사용자 행동이나 환경이 바뀌면서 입력 데이터의 분포가 학습 시점과 달라지는 현상이다. 계절, 정책, 시장 상황, 신규 사용자 유입이 원인이 될 수 있다. 데이터 드리프트가 커지면 처음에는 잘 작동하던 모델의 성능이 떨어질 수 있다.
### 개념 드리프트(Concept Drift)
입력과 정답의 관계 자체가 변하는 현상이다. 예를 들어 과거에는 특정 구매 패턴이 이탈의 신호였지만 시장 환경이 바뀌면서 더 이상 같은 의미를 갖지 않을 수 있다. 단순히 새로운 데이터를 많이 모으는 것만으로 해결되지 않고 문제 정의와 라벨을 다시 검토해야 할 수 있다.
### 모델 모니터링(Model Monitoring)
운영 중에는 다음을 계속 확인해야 한다.
- 입력 데이터의 변화
- 오류율과 성능 변화
- 특정 집단의 성능 차이
- 응답시간과 장애
- 이상한 입력의 증가
- 사용자가 결과를 어떻게 수정하는지
모니터링이 없으면 모델이 언제부터 잘못 작동하기 시작했는지 알기 어렵다.
## 🔎 추가 심화 학습 \| 평가 지표를 상황에 맞게 읽기
하나의 평가 지표만으로 모델을 판단하면 실제 위험을 놓칠 수 있다. 지표는 업무 목적과 오류 비용을 반영해 선택해야 한다.
### 불균형 데이터(Imbalanced Data)
정상 거래 99%, 이상 거래 1%인 데이터에서 모든 거래를 정상이라고 예측해도 정확도는 99%다. 그러나 이상거래를 하나도 찾지 못하므로 실제로는 쓸 수 없는 모델이다. 이런 상황에서는 재현율, 정밀도, F1 점수 등을 함께 봐야 한다.
### 임곗값(Threshold)
분류 모델은 종종 0\~1 사이의 점수나 확률을 출력한다. 어느 값 이상을 양성으로 볼지 정하는 기준이 임곗값이다. 임곗값을 낮추면 더 많은 대상을 양성으로 잡아 재현율은 높아질 수 있지만 거짓양성도 늘어날 수 있다.
### 정밀도와 재현율의 트레이드오프(Trade-Off)
정밀도는 양성이라고 예측한 것 중 실제 양성의 비율이고, 재현율은 실제 양성 중 모델이 찾아낸 비율이다. 스팸 필터, 질병 선별, 이상거래 탐지처럼 상황에 따라 어느 오류를 더 줄일지 판단해야 한다.
### 교차검증(Cross-Validation)
데이터를 여러 구간으로 나눠 학습과 검증을 반복하는 방법이다. 하나의 검증 집합에 우연히 맞는 모델을 선택하는 위험을 줄이고 평균적인 일반화 성능을 확인하는 데 도움이 된다.
### 과적합을 확인하는 실전 신호
학습 성능과 검증 성능의 차이가 점점 커지는지, 새로운 기간 데이터에서 성능이 급격히 떨어지는지, 특정 사용자군에서만 오류가 증가하는지 살핀다. 단순히 학습 정확도가 높아지는 것만으로 성공이라고 판단하지 않는다.
## 🔎 추가 심화 학습 \| 학습 데이터 설계에서 자주 발생하는 문제
### 라벨 품질(Label Quality)
지도학습에서는 라벨이 사실상 모델의 교과서 역할을 한다. 라벨이 잘못되거나 기준이 사람마다 다르면 모델도 일관된 판단 기준을 배우기 어렵다. 라벨링 지침, 예외 규칙, 복수 검수자를 두는 이유가 여기에 있다.
### 클래스 정의(Class Definition)
`위험 고객`, `우수 지원자`, `부정 리뷰`처럼 애매한 범주는 사람이 어떤 기준으로 정의했는지에 따라 결과가 달라진다. 모델 문제처럼 보이는 현상이 실제로는 업무 정의의 문제일 수 있다.
### 데이터 계보(Data Lineage)
데이터가 어디서 생성돼 어떤 변환을 거쳐 현재 값이 됐는지를 추적하는 정보다. 오류가 발생했을 때 원인을 찾고, 규정 준수와 감사에 대응하려면 데이터 출처와 변경 이력을 알아야 한다.
### 재현성(Reproducibility)
같은 데이터와 설정으로 다시 학습했을 때 유사한 결과를 얻을 수 있어야 실험 비교가 가능하다. 데이터 버전, 모델 버전, 설정값, 코드 버전을 기록하는 이유다.

## 📌 학습 요약
- AI의 발전은 규칙 기반 시스템(Rule-Based System)에서 머신러닝(Machine Learning), 딥러닝(Deep Learning)으로 확장되며 데이터와 연산환경의 변화와 함께 발전해 왔다.
- 머신러닝은 지도학습(Supervised Learning)·비지도학습(Unsupervised Learning)·강화학습(Reinforcement Learning)처럼 문제와 피드백 구조에 따라 학습 방식이 달라진다.
- 학습 데이터(Training Data)·검증 데이터(Validation Data)·시험 데이터(Test Data)를 분리하고 과적합(Overfitting)·데이터 누수(Data Leakage)를 관리해야 일반화 성능을 평가할 수 있다.
- 정확도(Accuracy)만으로 모델을 평가하지 않고 정밀도(Precision)·재현율(Recall)·F1 점수(F1 Score)와 실제 오류 비용을 함께 해석해야 한다.
