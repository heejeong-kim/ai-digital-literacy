  1. 생성형 AI (Generative AI): 인공지능의 한 분야로, 기존의 데이터를 학습하여 새로운 텍스트, 이미지, 음악, 비디오 등의 콘텐츠를 창조하는 기술
  2. 거대 언어 모델 (LLM: Large Language Model): 방대한 양의 텍스트 데이터를 학습하여 인간과 유사한 자연어 이해 및 생성 능력을 갖춘 인공지능 모델. ChatGPT, Gemini 등이 대표적임
  3. 자연어 처리 (NLP: Natural Language Processing): 컴퓨터가 인간의 언어를 이해하고 분석하며 생성할 수 있도록 하는 인공지능의 한 분야
  4. GPT (Generative Pre-trained Transformer): OpenAI에서 개발한 트랜스포머 아키텍처 기반의 거대 언어 모델 시리즈. 사전 학습과 미세 조정을 통해 다양한 자연어 처리 task를 수행함
  5. 사전 훈련 (Pre-training): 모델이 방대한 양의 일반적인 텍스트 데이터를 학습하여 언어의 기본적인 패턴과 문맥을 이해하는 과정
  6. 미세 조정 (Fine-tuning): 사전 훈련된 모델을 특정 작업이나 데이터셋에 맞춰 추가적으로 학습시켜 성능을 향상시키는 과정
  7. ChatGPT: OpenAI에서 개발한 GPT 모델 기반의 대화형 인공지능 챗봇 서비스. 질문 응답, 텍스트 생성, 번역, 코딩 등 다양한 기능을 제공함
  8. 멀티모달 (Multimodal): 하나의 AI 모델이 텍스트, 이미지, 오디오, 비디오 등 여러 종류의 데이터를 동시에 처리하고 이해할 수 있는 능력
  9. RLHF (Reinforcement Learning from Human Feedback): 인간의 피드백을 보상으로 사용하여 인공지능 모델을 학습시키는 강화 학습 방법. ChatGPT의 답변 품질 향상에 기여함
  10. 할루시네이션 (Hallucination): 거대 언어 모델이 사실에 기반하지 않은 정보를 그럴듯하게 생성하여 답변하는 현상
  11. OpenAI: 인공지능 기술을 연구하고 개발하는 미국의 연구 기업. ChatGPT, GPT 모델 시리즈 등을 개발함
  12. 트랜스포머 (Transformer): 자연어 처리 분야에서 혁신적인 성능을 보인 딥러닝 모델 아키텍처. 병렬 처리와 장거리 의존성 모델링에 강점을 가짐

1. LLM 개념과 생성형 AI 작동 원리 이해

1.1 LLM이란 무엇인가

1.1.1 개념 정의

  • LLM(Large Language Model, 거대언어모델) 은 수천억 개의 텍스트 데이터(전 세계 웹사이트, 논문, 오픈소스 코드 등)를 통째로 공부하여 인간의 언어와 논리 구조를 습관처럼 익힌 초대형 언어 모델
    • Large (거대): 공부한 양이 엄청나게 많다는 뜻. 도서관 수십만 개 분량의 책, 인터넷 글, 논문 등을 다 읽음 (뇌세포 역할을 하는 '파라미터'가 수천억 개 이상)
    • Language (언어): 사람의 말을 이해하고 생성하는 데 특화되어 있다는 뜻
    • Model (모델): 입력된 정보를 바탕으로 결과를 확률적으로 계산해내는 수학적 패턴 덩어리
  • 단순히 키워드를 검색하거나 번역하는 수준을 넘어, 레거시 기존 AI는 "이메일 스팸 분류기", "한영 번역기"처럼 정해진 한 가지 일만 할 수 있었으나 LLM은 문맥 전체를 읽기 때문에, 처음 보는 논문을 요약하거나 새로운 코드를 짜는 등 인간처럼 범용적인 업무가 가능
  • LLM은 앞에 나온 문맥을 바탕으로 다음 토큰을 확률적으로 예측하며 결과를 생성하는 자기회귀 언어 모델로, 인간과 같은 방식으로 의미를 이해한다고 단정하기는 어려움
  • 복잡한 추론처럼 보이는 결과도 생성할 수 있으나 생성 과정 자체가 사실성을 보장하는 것은 아니므로, 구조가 자연스러운 문장이라도 내용은 별도로 검증할 필요가 있음

1.2 LLM의 세부 구조 (Transformer 모델 분해)

💡

LLM은 "Self-Attention → FFN(Feed-Forward Network )"을 한 쌍으로 묶은 동일한 블록을 수십 층 반복 쌓은 네트워크로 입력된 문장은 이 블록을 통과할 때마다 두 단계의 가공을 거침

먼저 Self-Attention이 문장 안 모든 단어가 서로를 바라보며 "누구와 연결되고 누가 더 중요한지"를 계산하고, 이어서 FFN이 그 결과를 확장·비선형 변환·압축의 3단계로 정제

이 과정을 수십 층 반복하면서 초기 레이어의 단어 수준 패턴 파악이 중간 레이어의 문장 구조 이해를 거쳐 깊은 레이어의 문단 전체 의도와 맥락 파악으로 점진적으로 추상화됨

즉 LLM의 구조는 "여러 시선으로 관계를 읽고 → 정제하는 과정을 수십 번 반복하며 점점 깊은 이해에 도달하는 다단계 추상화 기계라고 할 수 있음

1.2.1 Transformer

Self-Attention 블록과 Feed-Forward Network(FFN)블록이 한쌍으로 구성되고 이 쌍을 수십번 반복하며 표현을 점점 정교하게 만드는 방식

2017년 구글이 발표한 인공신경망 구조로, 현재 존재하는 모든 초거대 AI(ChatGPT, Claude, Gemini 등)의 뿌리가 되는 핵심 알고리즘

  • 레거시 AI(RNN/LSTM)의 한계: 예전 AI는 문장을 앞에서부터 한 글자씩 순차적으로 읽었기 때문에 문장이 길어지면 앞부분 내용을 잊어버리는 '장기 의존성(Long-Term Dependency) 단절' 문제가 발생했고, GPU를 이용한 병렬 연산이 불가능해 학습 속도가 매우 느렸음
  • 트랜스포머(Transformer)의 혁신: 문장 안 여러 토큰의 관계를 병렬적으로 계산할 수 있어 순차 처리 중심 구조보다 대규모 학습에 유리하며, GPU 기반 병렬 연산의 효율을 크게 높여 초거대 모델 시대의 기반이 된 구조임 (드론의 시선이라고 이해하면 됨)

1.2.2 레이어(Layer)

LLM은 같은 모양의 블록을 수십 층 쌓아 올린 네트워크 구조로 각 층에서 표현이 조금씩 정교해지고 추상화되는 흐름으로 얕은 이해에서 깊은 이해로 확장되는 구조로 한 문장을 여러 깊이의 관점으로 반복 가공하는 다단계 생각 과정으로 이해하는 흐름

  • 초기 레이어: 단어 수준의 단순 패턴 파악
  • 중간 레이어: 문장 구조와 관계 이해
  • 깊은 레이어: 문단 전체의 의도, 느낌, 맥락을 파악하는 구조

1.2.3 Self-Attention 구조

Self-Attention은 문장 안의 모든 단어가 서로를 비교하며 “누가 더 중요하고 누구와 연결되는지”를 점수로 판단하는 메커니즘으로 이 메커니즘 덕분에 문장이 길어져도 앞뒤 단어 관계를 놓치지 않는 능력이 생기는 흐름

예: “어제 팀장님이 보낸 메일에 답장을 아직 못 했다”

  • “답장을” ↔ “메일” 연결
  • “보낸” ↔ “팀장님이” 연결
  • “어제”는 전체 상황의 시간 정보로 작동

1.2.4 Multi-Head Attention

Attention 연산을 여러 개의 'Head'로 나누어 서로 다른 표현 공간에서 단어 간 관계를 동시에 살펴보는 구조로, 회의실에 주어-동사 관계, 시간 정보, 감정 톤 등 서로 다른 관점을 가진 여러 전문가가 함께 참여하는 방식으로 이해할 수 있음

각 Head가 반드시 특정 역할만 담당하는 것은 아니며, 학습 과정에서 서로 다른 관계와 패턴에 주목하도록 형성되는 구조가 Multi-Head Attention임

[아래는 예시이며 실제로는 학습을 통해 모델이 스스로 역할을 결정함]

  • Head 1: 주어–동사 관계에 집중
  • Head 2: 시간 정보에 집중
  • Head 3: 감정·톤에 집중
  • Head 4: 대상·관계에 집중

1.2.5 Feed-Forward Network (FFN)

Attention으로 중요도와 연결성이 정해지면 FFN(Feed-Forward Network) 블록이 그 표현을 확장(Expand) → 필터링(Filtering) → 압축(Compress) 3단계를 통해, 선형 조합만으로는 표현할 수 없는 복잡한 패턴을 학습하는 가공 과정으로 두 과정이 반복되면서 단순 숫자 벡터가 의미적으로 풍부한 표현으로 변환되는 구조

비유

  • Attention: 어떤 재료가 서로 잘 어울리는지 판단, 관계를 찾아내는 것
  • FFN: 실제 지식(데이터)를 꺼내 단어의 의미를 풍부하게 가공

[Attention을 거친 사과 벡터]

1) 확장 (Expand)
'과일 사과'와 관련된 수많은 지식 뉴런을 동시에 깨움 : 빨간색, 아삭함, 비타민C, 껍질, 당도, 가을 수확 등

2) 필터링 (Filter)
현재 문장("디저트로 먹었다")에 불필요한 정보는 차단하고, 단어의 숨은 의미적 뉘앙스를 필터링(활성화 함수 연산)함 : '가을 수확', '농장' 정보는 버리고, '맛', '식감' 정보만 통과

3) 압축 (Compress)
필터링된 알짜배기 지식("새콤달콤함", "아삭한 디저트")을 원래의 차원으로 다시 압축하여 최종 단어 표현으로 고착화

[최종 가공된 사과 벡터] 단순히 글자 '사과'가 아니라, "레몬 타르트와 어울리는 새콤달콤하고 아삭한 과일 디저트"라는 깊은 의미 정보가 꽉 찬 벡터로 변환됨

1.3 LLM(생성형 AI) 작동 원리

단계명칭핵심 역할
1단계토큰화 (Tokenization)문장을 숫자로 쪼개기
2단계임베딩 (Embedding)의미를 공간 좌표로 변환
3단계다음 단어 예측 (Next-Token Prediction)확률적으로 가장 자연스러운 단어 선택
4단계AI 답변 출력 및 루프(Autoregressive)생성된 단어를 다시 입력에 추가하며 단어 하나씩 반복 출력

1.3.1 토큰화 (Tokenization) → 자연어를 모델이 처리할 단위로 나누기

LLM은 우리가 입력한 문장을 글자나 단어 그대로 처리하지 않고 토큰(Token)이라는 작은 단위로 나눈 뒤 각 토큰을 숫자 ID로 변환하여 계산

토큰은 항상 단어 하나와 일치하는 것이 아니라 단어 전체, 단어의 일부, 숫자, 기호, 공백 등이 하나 또는 여러 토큰으로 나뉠 수 있다. 이처럼 자연어를 모델이 계산할 수 있는 단위로 분해하는 과정이 토큰화(Tokenization)

예를 들어 사람이 "인공지능을 공부한다"라는 문장을 하나의 문장으로 읽더라도, LLM 내부에서는 토크나이저의 규칙에 따라 여러 개의 토큰으로 나뉘어 처리된다. 정확히 어떻게 나뉘는지는 사용하는 모델과 토크나이저에 따라 달라질 수 있음

1.3.2 임베딩 (Embedding) → 의미를 공간 좌표로 변환

토큰화된 단어를 고차원 벡터(좌표값)로 변환하는 과정. 단순히 문자를 숫자로 바꾸는 것을 넘어 단어가 가진 의미적 유사성을 수학적 거리로 표현하여 단어의 의미를 좌표값으로 변환하여 AI가 단어 간 관계를 수학적으로 계산할 수 있게 만드는 과정

예시)

왕(King) ↔ 여왕(Queen)       : 가까움  ✅
왕(King) ↔ 반도체(Semiconductor) : 멀리 떨어짐  ❌

수학적 연산: [국왕] - [남성] + [여성] = [여왕]

AI가 단어를 단순 암기하는 것이 아니라 단어 간 의미 관계를 수학적으로 이해하고 있다는 증거

참고: 위 예시는 Word2Vec 등 고전적인 정적 임베딩 방식의 대표적 비유이며, 실제 LLM의 임베딩은 문맥에 따라 동적으로 달라지는 컨텍스트 임베딩임. 다만 '단어를 의미 공간의 좌표로 이해한다'는 핵심 개념을 직관적으로 전달하는 용도로는 유효함

1.3.3 다음 단어 예측 (Next-Token Prediction) → LLM의 핵심 원리

LLM은 인간처럼 '생각'해서 답변을 만드는 것이 아니라 주어진 문맥에서 다음에 올 통계적 확률이 가장 높은 단어를 연속으로 선택하여 출력하는 확률 모델로 앞에 나온 문맥을 바탕으로 다음에 올 단어를 확률적으로 계산해 출력하는 과정

예시) 이러한 원리 때문에 LLM은 문법적으로 완벽하지만 내용이 거짓인 문장을 생성할 수 있음. '그럴듯함'과 '사실'은 전혀 다른 개념

1.3.4 AI 답변 출력 및 루프 (Autoregressive) → 생성된 단어를 다시 입력에 추가하며 반복 출력

앞서 선택된 단어를 새로운 입력 데이터로 포함시켜, 단어 하나씩 순차적으로 연속 생성하는 과정임으로 LLM이 문장을 한 번에 통째로 찍어내는 것이 아니라, 실시간으로 단어를 이어 붙여 나가는 자동 회귀(Autoregressive) 구조의 핵심 단계

앞 단계에서 출력된 단어를 다시 입력창에 밀어 넣어 다음 단어를 예측하는 연쇄적 피드백 루프 과정으로 예를 들어 첫 단어를 쓸 때는 책 한 장만 읽으면 되지만, 마지막 단어를 쓸 때는 책 한 권을 처음부터 끝까지 다 다시 읽어야 하는 비효율성이 있음

예시)

"나는 오늘"이라는 입력이 주어졌을 때의 출력 메커니즘은 다음과 같음:

  • 1회차 루프: "나는 오늘" → [맛있는] 예측 및 출력
  • 2회차 루프: "나는 오늘 맛있는" → [밥을] 예측 및 출력
  • 3회차 루프: "나는 오늘 맛있는 밥을" → [먹었다] 예측 및 출력
  • 4회차 루프: "나는 오늘 맛있는 밥을 먹었다" → 문장 종료 토큰 감지 후 멈춤

비효율성의 흐름

성능의 병목 구간 : 문장이 길어질수록 과거에 생성한 모든 토큰을 다시 읽어와 연산해야 하므로, 후반부로 갈수록 컴퓨팅 리소스(GPU 비용)가 기하급수적으로 증가

에러 전파(Error Propagation) 위험 : 루프 중간에 단어 하나를 잘못 선택하면(확률적 오차 발생), 그 잘못된 단어가 다음 단어 예측의 기준(문맥)이 되므로 이후 문장 전체가 엉뚱한 방향으로 흘러가는 '스노우볼 효과', 즉 이는 할루시네이션을 가속화하는 주된 요인이라 할 수 있음

1.4 구조적 한계 · 할루시네이션 (Hallucination)

AI가 실제로 존재하지 않는 사실·판례·통계·논문을 마치 사실인 것처럼 창작해 내는 현상

  • 사실 관계(Fact) 검증이 아닌 문맥적으로 "그럴듯한 문장" 생성에 최적화된 구조적 한계
  • 3단계의 확률적 예측 구조 자체에서 필연적으로 발생

예시) 뉴욕 변호사 가짜 판례 제출 사건 (2023)

미국 변호사가 ChatGPT가 생성한 변론서를 그대로 법원에 제출했다가 인용된 판례 6건이 모두 AI가 창작한 가짜임이 밝혀져 벌금 $5,000(약 650만 원) 선고

2. 토큰·컨텍스트·확률적 생성

2.1 토큰 수가 LLM 사용에 미치는 영향

토큰은 쉽게 말해 AI가 한 번의 대화에서 읽고 처리해야 하는 정보의 양을 세는 단위로 이해. 참고하자면 사람이 책을 읽을 때 페이지가 많아질수록 읽어야 할 양이 늘어나는 것처럼, AI도 입력된 토큰이 많아질수록 한 번에 처리해야 할 정보가 많아지는 구조

예시) AI에게 보고서 한 문단만 주고 요약을 요청하는 경우와 100페이지 분량의 자료 전체를 한꺼번에 넣고 요약을 요청하는 경우를 비교하면, 두 작업은 같은 '요약'이지만 AI가 읽어야 하는 토큰의 양은 크게 달라지는데 이 차이가 한 번에 처리할 수 있는 정보량, 응답에 사용할 수 있는 공간, API 사용량 등과 연결되는 것

💡

쉽게 이해하기

토큰을 여행 가방의 공간으로 보면, 가방의 크기는 한정되어 있고 자료를 많이 넣을수록 남는 공간이 줄어드는 것처럼, 한 번의 요청에 너무 많은 정보를 넣으면 모델이 한 번에 다룰 수 있는 범위 안에서 입력과 출력이 함께 공간을 사용

토큰이 많으면 무조건 나쁜가?

토큰이 적다고 항상 좋은 프롬프트인 것은 아니라 필요한 배경까지 없애면 오히려 AI가 상황을 제대로 판단하지 못해 답변 품질이 낮아질 수 있음

예를 들어

마케팅 전략 알려줘

처럼 지나치게 짧게 질문하면 토큰 수는 적지만 목적과 상황이 부족하며 반대로

대학생 대상 온라인 교육 서비스를 출시하려고 함. 초기 광고 예산은 월 300만 원이며 인스타그램과 유튜브를 주요 채널로 고려 중임. 첫 3개월 동안 실행할 마케팅 전략을 우선순위 중심으로 제안할 것

처럼 필요한 맥락을 제공하면 입력은 길어지지만 AI가 판단할 수 있는 정보가 많아져 결과의 구체성이 높아질 수 있음

따라서 핵심은 프롬프트를 무조건 짧게 만드는 것이 아니라 필요한 목적·맥락·조건은 충분히 제공하고, 같은 설명의 반복이나 관계없는 자료는 제거하는 것

영향무엇이 달라지는가사용자가 알아둘 점
처리 가능한 정보량입력과 출력에 사용되는 토큰이 컨텍스트 창 안에서 함께 사용됨매우 긴 문서나 대화는 한 번에 모두 처리하기보다 필요한 범위를 나누어 제공함
응답 길이입력에 많은 토큰을 사용하면 모델과 서비스 조건에 따라 출력에 사용할 수 있는 여유에도 영향을 줄 수 있음필요한 정보와 원하는 출력 분량을 명확하게 제시함
비용·처리량API 등 일부 환경에서는 입력·출력 토큰 수가 사용량과 비용 산정의 기준이 됨같은 내용을 불필요하게 반복하지 않고 필요한 자료만 제공함
언어·표현 방식같은 의미의 문장도 언어와 표현, 사용하는 모델의 토크나이저에 따라 토큰 수가 달라질 수 있음특정 언어가 항상 더 효율적이라고 단정하기보다 실제 사용하는 모델 기준으로 확인함
코드·표·기호코드와 표처럼 기호와 구조가 많은 입력도 여러 토큰으로 분해됨대용량 자료는 필요한 부분만 선택하거나 작업을 단계별로 나누어 처리함

2.2 컨텍스트 창 — AI는 한 번에 얼마나 많은 정보를 볼 수 있을까

컨텍스트 창(Context Window)은 모델이 한 번에 참조할 수 있는 토큰의 최대 범위이며 대화 내용·첨부 자료·지시사항·생성 중인 답변 등이 함께 들어가는 AI의 작업 기억 공간에 해당하는 것으로 쉽게 말하면 컨텍스트 창은 AI가 한 번의 작업에서 펼쳐놓고 볼 수 있는 책상 크기와 비슷함(단, 책상이 넓을수록 더 많은 문서와 이전 대화를 동시에 참고할 수 있지만, 책상 위에 자료가 많다고 해서 모든 내용을 똑같이 중요하게 읽는 것은 아님)

따라서 컨텍스트 창이 크더라도 핵심 조건과 중요한 자료를 명확하게 제시하는 것이 중요

최신 주요 모델의 컨텍스트 창

숫자가 크다고 항상 답변 품질이 높아지는 것은 아님

컨텍스트 창은 AI가 참고할 수 있는 최대 공간을 의미하는 것이며, 그 안의 모든 정보를 동일한 정확도로 기억하거나 활용한다는 의미는 아님

실제 ChatGPT·Claude·Gemini 서비스 화면에서 사용할 수 있는 범위는 선택한 모델·요금제·기능에 따라 달라질 수 있음

컨텍스트가 길어질 때 나타나는 대표 현상

현상설명대응 방법
컨텍스트 소실창을 넘어선 초반 대화가 더 이상 반영되지 않음중요한 조건을 주기적으로 다시 명시함
컨텍스트 오염잘못된 정보나 실패한 시도가 대화에 남아 계속 영향을 줌수정을 반복하기보다 새 대화창을 엶
지시 희석대화가 길어질수록 초반 지시의 영향력이 약해짐핵심 지시를 마지막 입력에 다시 붙임
세션 독립대화창마다 기억이 서로 분리되어 유지됨주제와 프로젝트 단위로 대화창을 나눔
  • 최근 모델은 컨텍스트 창이 크게 늘었으나 창이 크다고 해서 앞부분을 균일하게 잘 참조하는 것은 아님
  • 중요한 정보는 대화의 맨 앞이나 맨 뒤에 배치할 때 반영률이 높아짐

2.3 확률적 생성 — 왜 같은 질문에도 답이 달라질까

LLM은 정해진 문장을 저장해 두었다가 꺼내는 방식이 아니라 앞에 나온 문맥을 바탕으로 다음에 올 토큰들의 가능성을 계산하고 그중 하나를 선택하며 문장을 이어 가는 구조이기 때문에 같은 질문에도 답이 달라질 수 있음

예시) 오늘 점심으로라는 문장이 주어지면 다음 토큰 후보가 하나만 존재하는 것이 아니라 김치찌개, 샌드위치, 국밥, 파스타처럼 여러 후보에 서로 다른 확률이 부여될 수 있음

  • 김치찌개 35%
  • 샌드위치 25%
  • 국밥 20%
  • 파스타 10%
  • 기타 후보 10%

가장 가능성이 높은 후보가 선택될 가능성이 크지만 항상 같은 후보만 선택되는 것은 아니며 한 번 선택된 토큰은 다음 토큰을 예측하는 새로운 문맥이 되기 때문에 초반의 작은 선택 차이가 뒤의 문장 전체를 다른 방향으로 이어지게 할 수 있음

확률적 생성이 실제 사용에서 의미하는 것

  • 같은 프롬프트를 다시 입력해도 표현·예시·구성 순서가 조금씩 달라질 수 있음
  • 정답 범위가 넓은 기획·아이디어 작업에서는 여러 후보를 얻는 장점으로 작용함
  • 사실 확인·계산·규정 확인처럼 정확성이 중요한 작업에서는 한 번의 답변만 믿지 않고 검증할 필요가 있음
  • 중요한 결과는 여러 번 생성하여 공통점과 차이를 비교하는 방식이 유용함

즉 LLM의 답변은 하나의 고정된 정답을 꺼내는 과정이 아니라, 매 순간 여러 후보 중 하나를 선택하며 만들어지는 결과로 이해할 것

온도(Temperature)

온도는 다음 토큰을 선택할 때 확률이 높은 후보에 얼마나 집중할지, 낮은 확률의 후보까지 얼마나 폭넓게 고려할지 조절하는 값을 말하는 것으로 프롬프트에서는 온도 자체를 바꾸는 것이 아니라 ‘사실성과 일관성을 우선할 것’, ‘서로 다른 관점의 아이디어를 5개 제안할 것’처럼 원하는 결과의 방향을 조건으로 명시 하는 것

  • 낮은 온도: 높은 확률의 후보를 중심으로 선택하여 비교적 일관된 결과가 생성됨
  • 높은 온도: 다양한 후보가 선택될 가능성이 커져 표현과 아이디어의 변동 폭이 커짐
  • 일반적인 ChatGPT·Claude·Gemini 대화 화면에서는 사용자가 온도 값을 직접 설정하지 않는 경우가 많으므로 개념을 이해하는 수준으로 볼 것

3. 대화형 AI 인터페이스의 이해

대화형 AI는 질문을 입력하고 답을 받는 단순한 검색창이 아니라 작업에 맞는 기능을 선택하고, 필요한 자료를 제공하고, 결과를 확인하며 반복 개선하는 작업 환경으로 실제 ChatGPT·Claude·Gemini와 같은 대화형 AI를 사용할 때 어떤 기능을 어떤 순서로 활용할 것인지를 중심으로 확인

3.1 화면 구성 요소

* 실제 3대장을 열어서 함께 리뷰 합니다.

구성 요소기능활용 시점
입력창프롬프트 입력과 파일 첨부모든 작업의 시작점
모델 선택속도형과 추론형 모델 전환복잡한 분석은 추론형을 선택함
대화 목록주제별 세션 관리와 검색프로젝트 단위로 분리해 관리함
웹 검색최신 정보 조회와 출처 표시시의성 있는 질문에 사용함
파일 업로드문서·이미지 기반 답변 생성내부 자료 분석에 사용함
응답 재생성다른 후보 답변 생성과 비교품질이 낮거나 편차 확인이 필요할 때 사용함
메모리·설정사용자 정보와 답변 성향 저장반복 조건을 매번 쓰지 않기 위해 사용함

3.2 모델 선택 기준

같은 서비스 안에서도 응답 속도를 우선한 모델과 사고 과정을 길게 거치는 추론형 모델이 나뉘므로 작업 성격에 따라 선택해야 함

* 구체적인 모델명과 무료 사용 한도는 수시로 변경되므로 강의 당일 화면에서 함께 확인

작업 성격권장 모델 유형이유
요약, 번역, 문장 다듬기속도형정답 폭이 좁아 빠른 응답이 유리함
논리 전개, 수식 계산, 코드 설계추론형중간 단계 오류가 결과를 좌우함
최신 정보 조사웹 검색 기능 활성화학습 시점 이후 정보가 필요함
긴 문서 분석파일 업로드와 컨텍스트가 큰 모델원문을 직접 참조해야 정확함

3.3 표준 7단계 사용 흐름

한 번에 완성된 답을 기대하지 않고 2~3회 반복을 기본 전제로 진행

단계행동점검 질문
1 목적 정의얻고자 하는 결과물을 한 문장으로 적음결과물의 형태를 말할 수 있는가
2 프롬프트 작성5요소를 채워 입력함빠진 요소는 없는가
3 응답 확인목적 대비 부족한 지점을 표시함무엇이 왜 부족한가
4 조건 보강부족한 요소 하나만 지목해 재질문함한 번에 하나만 고치고 있는가
5 재질문개선된 응답을 다시 확인함이전보다 나아졌는가
6 검증사실 주장을 출처와 대조함인용해도 되는 정보인가
7 확정최종본을 정리하고 활용 사실을 기록함어떤 부분을 내가 수정했는가

3.4 대화창 관리 원칙

  • 하나의 대화창에는 하나의 목적만 담아 컨텍스트 오염을 예방
  • 수정과 재질문이 반복되어 이전의 잘못된 정보나 실패한 시도가 대화에 많이 남았다고 판단되면 새 대화창에서 핵심 조건을 다시 정리해 시작할 것
  • 반복 사용할 조건은 설정이나 템플릿으로 옮겨 매번 입력하지 않음

4. 프롬프트 5요소와 반복 개선 전략

4.1 프롬프트 5요소

프롬프트는 모델에게 주는 작업 지시서이며 복잡한 작업에서는 역할·목적·맥락·조건·형식을 구분해 제시할수록 모델이 요구사항을 파악하고 결과를 통제하기 쉬워짐

  • 단순한 질문에는 다섯 요소가 모두 필요한 것은 아니며 작업이 복잡할수록 필요한 요소를 추가하는 방식으로 활용할 것
요소답해야 할 질문작성 예시빠뜨렸을 때의 증상
역할(Role)누구로서 답하는가10년 차 IT 직무 취업 컨설턴트로서어조와 전문성 수준이 들쭉날쭉함
목적(Goal)무엇을 얻으려 하는가자기소개서 성장과정 문항 초안을 만든다주제만 겉도는 일반론이 나옴
맥락(Context)어떤 상황과 배경인가컴퓨터공학 전공 4학년, 백엔드 인턴 6개월 경험내 상황과 무관한 예시가 채워짐
조건(Constraint)무엇을 지키고 무엇을 피해야 하는가800자 이내, 경험 중심 서술, 과장 표현 금지분량과 톤이 매번 달라짐
형식(Format)어떤 모양으로 받는가소제목 3개와 본문으로 구성한 표후속 편집에 시간이 더 들어감

4.2 요소별 작성 요령

  • 역할은 직업명과 경력 연차를 함께 적을 때 답변의 구체성이 올라감
  • 목적은 명사가 아니라 동사로 적어야 모델이 수행할 행동을 특정할 수 있음
  • 맥락은 대상 독자, 나의 수준, 사용될 장면의 세 가지를 최소 단위로 포함함
  • 조건은 지켜야 할 것과 하지 말아야 할 것을 나누어 적을 때 준수율이 높아짐
  • 형식은 표, 목록, 단락 중 하나를 명시하고 가능하면 예시 한 줄을 함께 줌

4.3 좋은 질문과 나쁜 질문

개선 축나쁜 질문좋은 질문
범위마케팅 알려 줘20대 대상 앱 출시 첫 달 SNS 마케팅 실행안을 알려 줘
조건짧게 써 줘300자 이내로 전문 용어 없이 써 줘
형식정리해 줘항목·현황·개선안 3열 표로 정리해 줘
판단 기준좋은 걸로 골라 줘비용과 학습 난이도를 기준으로 3개를 비교해 골라 줘
근거사실인지 알려 줘출처와 발표 연도를 함께 제시하고 불확실하면 모른다고 답해 줘

4.4 반복 개선 3전략

  • 한 번에 여러 가지를 동시에 고치라고 지시하면 개선 원인을 특정할 수 없음
  • 개선이 멈추면 프롬프트를 손보기보다 새 대화창에서 처음부터 다시 작성하는 편이 빠름
전략방법지시문 예시
재질문부족한 요소 하나만 지목해 보강을 요청함세 번째 항목만 실제 사례를 넣어 다시 써 줘
자기평가 요청모델이 자기 답변을 기준에 따라 채점하고 수정하게 함위 답변을 채용 담당자 관점에서 5점 만점으로 평가하고 근거를 제시한 뒤 수정본을 작성해 줘
역질문 유도모델이 필요한 정보를 먼저 묻게 해 조건 누락을 줄임답하기 전에 필요한 정보를 세 가지만 나에게 먼저 질문해 줘

4.5 완성형 프롬프트 예시

구간작성 내용
역할너는 10년 차 IT 서비스 기업 채용 담당자야
목적내 경험을 바탕으로 자기소개서 성장과정 문항 초안을 작성해
맥락나는 컴퓨터공학 전공 4학년이며 백엔드 인턴 6개월과 팀 프로젝트 2건 경험이 있어
조건800자 이내로 쓰고 경험과 수치를 중심으로 서술하며 과장 표현과 상투적 문구는 쓰지 마
형식소제목 3개와 각 소제목별 본문 형태로 출력하고 마지막에 보완이 필요한 정보를 3가지 질문으로 제시해줘

5. 환각·편향·최신성 한계와 사실 검증

5.1 환각

환각은 모델이 학습한 패턴에 따라 그럴듯한 문장을 생성하는 과정에서 존재하지 않는 사실을 사실처럼 서술하는 현상

유형증상판별 신호
출처 조작존재하지 않는 논문·기사·저자를 인용함검색으로 원문이 확인되지 않음
수치 조작통계와 연도를 그럴듯하게 제시함발표 기관 자료와 값이 불일치함
인용문 조작실존 인물의 발언을 창작함1차 자료에 해당 발언이 없음
기능 조작존재하지 않는 메뉴·기능·조항을 설명함공식 문서에 항목이 없음
  • 환각은 다음 토큰을 예측하며 문장을 생성하는 과정, 학습 데이터의 한계, 불확실성을 처리하는 방식 등 여러 요인으로 발생할 수 있음
  • 모델이 잘 모르는 좁은 영역일수록, 그리고 구체적인 고유명사를 요구할수록 발생률이 높아짐
  • 프롬프트에 불확실성 표기 지시를 넣으면 발생 빈도를 낮출 수 있으나 완전히 없앨 수 없음

5.2 편향

  • 학습 데이터에 포함된 사회적 고정관념이 답변에 그대로 재생산될 수 있음
  • 다수 언어와 다수 문화권 자료가 많아 소수 관점과 국내 맥락이 축소될 수 있음
  • 사용자의 주장에 동조하려는 경향으로 비판적 관점과 반대 근거가 누락될 수 있음
  • 특정 직업이나 집단을 묘사하게 하는 질문으로 편향을 직접 관찰할 수 있음

5.3 최신성 한계

모델은 학습이 종료된 시점 이후의 사건을 알지 못하므로 시의성 있는 정보는 웹 검색 기능이나 사용자가 제공한 자료로 보완

정보 유형모델 단독 신뢰도보완 방법
변하지 않는 개념과 원리높음추가 조치가 거의 필요 없음
제품 사양과 요금낮음공식 페이지를 직접 확인함
최근 사건과 인사매우 낮음웹 검색을 켜고 출처를 확인함
교내 규정과 내부 자료없음원문을 직접 첨부함

5.4 사실 검증 4단계

단계점검 질문조치
분류이 문장은 사실인가 의견인가사실 주장만 검증 대상으로 선별함
출처근거 출처가 명시되어 있는가출처를 요구하고 링크의 실재를 확인함
대조1차 자료의 내용과 일치하는가공식 기관과 원문에 직접 접속해 대조함
판정그대로 인용해도 되는가확인·수정·삭제 중 하나로 판정해 기록함

5.5 책임 있는 사용 원칙

  • 최종 결과물의 책임은 사용자에게 있으므로 검증하지 않은 내용을 인용하지 않음
  • 개인정보와 미공개 자료는 입력하지 않으며 필요하면 익명화해 사용함
  • AI 활용 사실과 검증 과정을 산출물에 명시해 학술적·직업적 정직성을 유지함

- 불필요하게 장황한 설명은 제외할 것

# 형식
1. 핵심 개념 요약
2. 활용 사례 3가지를 표로 정리
3. 사용할 때 주의할 점 3가지
4. 결과를 검증하는 방법
5. 마지막에 핵심 내용을 한 문장으로 정리

프롬프트 작성 후 확인

  • 2개의 프롬프트 결과물을 비교할 것
  • 목적이 무엇인지 한 문장으로 확인할 것
  • 필요한 배경과 대상이 포함되었는지 확인할 것
  • 반드시 지켜야 할 조건이 명확한지 확인할 것
  • 원하는 출력 형식이 구체적인지 확인할 것
  • 같은 의미의 설명이 반복되지 않았는지 확인할 것

6.3 실제 실습

  1. 위 템플릿의 [ ] 부분을 자신의 상황에 맞게 수정할 것
  2. 완성한 프롬프트를 ChatGPT·Claude·Gemini의 새 대화창에 동일하게 입력할 것
  3. 첫 번째 응답에는 추가 지시를 넣지 않고 그대로 저장할 것
  4. 세 결과를 비교표에 기록할 것
  5. 자신의 목적에 가장 적합한 결과 1개를 선택할 것
  6. 선택한 결과에서 부족한 점 1~2가지를 찾아 추가 프롬프트로 개선할 것
  7. 최종 결과에 사실 주장이나 최신 정보가 있다면 원문·공식 자료·검색 결과와 대조할 것

개선 프롬프트 예시

방금 작성한 결과에서 다음 부분을 개선해줘

- 부족한 점: [수정이 필요한 부분]
- 유지할 점: [잘 작성된 부분]
- 추가 조건: [새롭게 반영할 조건]

기존 구조는 유지하되 수정된 부분이 분명하게 드러나도록 최종본을 다시 작성해줘

비교 후 정리

  • 세 결과에서 가장 눈에 띄는 차이 1가지 기록
  • 가장 활용하기 좋은 결과 1개 선택
  • 선택 이유를 2~3문장으로 작성
  • 수정이 필요했던 부분과 개선 프롬프트를 기록
  • 검증한 사실이 있다면 확인한 출처 또는 근거를 기록
