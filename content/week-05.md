# 1. 생성형 AI와 실생활 응용
## 1.1 생성형 AI 활용
생성형 AI는 1주차에서 살펴본 AI의 다섯 가지 기능(인식·분류·예측·추천·생성) 가운데 ‘생성’에 해당하고, 2주차에서 살펴본 머신러닝·딥러닝 발전 흐름 위에서 활용이 확대된 단계. 이번 주차에서는 그 개념을 다시 정의하기보다 실제로 요청을 입력하고 결과를 받아 수정하는 경험에 초점을 둠
2주차에서 확인한 것처럼 생성형 AI는 저장된 답을 꺼내 오는 것이 아니라 입력된 요청과 학습된 패턴을 바탕으로 가능성이 높은 결과를 계산함. 같은 요청에도 결과가 조금씩 달라지고, 말하지 않은 조건이 반영되지 않는 것은 오작동이 아니라 이 방식에서 자연스럽게 나타나는 특성
- 텍스트 AI: 설명·요약·아이디어·문장 초안·이야기 구성
- 이미지 AI: 삽화·콘셉트·배경·캐릭터 시안
- 공통점: 사용자의 요청을 바탕으로 결과를 생성
- 차이점: 결과 형식에 따라 확인해야 할 기준이 달라짐
\[참고\] 생성 원리와 환각, 멀티모달 구조는 10주차에서 더 자세히 다룸
---
## 1.2 실생활에서 활용하기 좋은 과제
### 1.2.1 학습 보조
학습에서 생성형 AI는 모르는 내용을 대신 공부해 주는 도구라기보다, 이해하기 어려운 내용을 다른 표현으로 바꾸거나 공부의 출발점을 만드는 보조 도구로 활용하는 것이 적절
같은 개념도 대상과 설명 방식에 따라 난이도가 달라질 수 있으므로, 이해되지 않는 부분을 다시 질문하거나 예시를 요청하면서 자신의 이해와 비교하는 과정이 중요
- 어려운 개념을 쉬운 말로 다시 설명
- 발표 주제의 질문 후보 만들기
- 긴 글을 읽기 전에 핵심 구조 파악
- 공부 계획이나 체크리스트 초안 만들기
> <span color="gray">예시) 초등학생에게 설명하듯이 광합성의 과정을 세 단계로 설명해줘처럼 대상과 형식을 지정하면 이해 수준에 맞는 설명 초안을 얻을 수 있음</span>
---
### 1.2.2 일상적인 글쓰기
글쓰기에서는 빈 화면에서 처음부터 문장을 만드는 부담을 줄이는 데 생성형 AI가 유용
필요한 목적과 상황을 알려 주면 문장 구조나 표현의 **초안**을 빠르게 만들 수 있고, 사용자는 그 초안을 자신의 상황에 맞게 고치면서 시간을 줄일 수 있음
- 이메일·안내문 초안
- 여행 준비 목록
- 행사 아이디어
- 일정 정리
- 개인 메모 구조화
AI가 만든 문장은 상황과 관계를 모두 알고 작성한 것이 아니므로 실제 발송이나 공개 전에는 표현의 적절성을 사람이 확인해야 함
---
### 1.2.3 창작과 아이디어 발산
창작에서는 AI에게 하나의 완성된 아이디어를 맡기기보다 여러 후보를 빠르게 만들어 보는 방식이 효과적
처음에는 선택지를 넓게 생성하고, 그중 목적에 맞는 아이디어를 사람이 선택한 뒤 다시 구체화하면 아이디어 발산 → 선택 → 발전의 흐름으로 활용할 수 있음
- 이야기 소재 탐색
- 제목 후보 만들기
- 캐릭터 설정 비교
- 장면 아이디어 확장
- 삽화 콘셉트 탐색
AI가 제안한 후보는 완성본으로 받아들이기보다 주제·대상·분위기 같은 기준으로 비교한 뒤, 사람이 필요한 아이디어를 선택하고 조합하는 방식으로 활용하는 것이 좋음
---
## 1.3 생성형 AI에 바로 맡기기 어려운 과제
편리하다고 모든 과제를 AI에 그대로 맡기는 것은 적절하지 않으며 생성형 AI는 문장을 자연스럽게 만들 수 있지만 그 문장이 실제 사실인지, 사용자의 상황에 가장 적절한 결정인지를 스스로 책임지고 보장하는 도구는 아님

# 2. 기초 프롬프트와 결과 수정
## 2.1 프롬프트는 AI에게 주는 작업 설명
프롬프트는 사용자가 AI에게 무엇을 해 달라고 요청하는 입력으로, 사람에게 일을 부탁할 때 전달하는 간단한 작업 지시서와 비슷하게 이해할 수 있음. 같은 AI를 사용하더라도 목적과 조건이 모호하면 넓고 일반적인 결과가 나오고, 분명하게 알려 주면 원하는 방향에 가까운 결과를 얻기 쉬움
좋은 프롬프트는 길고 자세한 문장이 아니라 결과에 실제로 영향을 주는 정보를 빠뜨리지 않고 전달하는 입력. 설명이 길어도 중요한 조건이 빠져 있으면 원하는 결과를 얻기 어려움
---
### 2.1.1 목적
목적은 **AI에게 어떤 일을 시키려는지**를 알려 주는 부분. 먼저 결과의 종류를 제시하면 AI가 설명을 해야 하는지, 요약을 해야 하는지, 아이디어를 제안해야 하는지 작업 방향을 정하기 쉬움
- 동화 줄거리를 만들어줘
- 행사 안내 이메일 초안을 작성해줘
- 이 내용을 5개 항목으로 요약해줘
---
### 2.1.2 대상
대상은 **결과를 실제로 읽거나 사용할 사람**을 의미. 같은 내용을 설명하더라도 초등학생에게 설명하는 문장과 대학생에게 설명하는 문장은 어휘와 정보의 깊이가 달라야 하므로, 대상을 알려 주면 AI가 표현 수준을 조정하기 쉬움
- 초등학생
- 대학 신입생
- 처음 서비스를 이용하는 고객
- 팀 회의에 참석하는 동료
---
### 2.1.3 조건
조건은 결과가 지켜야 할 구체적인 기준으로 **형식·필수 요소·제외 요소**의 세 가지로 나누어 생각하면 빠뜨리지 않고 전달할 수 있음. 목적과 대상만 알려 주면 내용의 방향은 정할 수 있지만 결과의 길이와 모양은 달라질 수 있으므로, 조건을 함께 제시해야 결과를 확인하고 수정하기도 쉬워짐
- **형식**: 6개 장면, 각 장면 2문장, 표 형식
- **필수 요소**: 작은 로봇 주인공, 동물 친구
- **제외 요소**: 폭력적인 표현, 어려운 전문용어

## 2.2 좋은 결과는 한 번의 요청보다 반복 수정에서 만들어짐
AI가 처음 만든 결과가 목적과 정확히 맞지 않는 것은 자연스러운 과정. 2주차에서 살펴본 것처럼 AI는 사용자의 머릿속 의도를 아는 것이 아니라 입력된 정보와 학습된 패턴으로 가능성이 높은 결과를 계산하기 때문에, 첫 요청에서 전달되지 않은 조건은 결과에 반영되지 않음
따라서 처음부터 완벽한 프롬프트를 만들려고 하기보다 **첫 결과를 확인하고 → 무엇이 부족한지 찾고 → 그 부족한 부분만 추가로 요청하는 방식**이 실용적. 긴 프롬프트를 처음부터 다시 쓰는 것보다 수정 지점을 구체적으로 지정하는 편이 빠름
**멀티턴(Multi-turn)은 첫 결과 확인 → 부족한 점 찾기 → 수정 조건 추가 → 다시 비교의 흐름으로 진행**
> <span color="gray">예시) 문장이 너무 길어. 각 장면을 2문장 이내로 줄여줘 / 주인공이 문제를 혼자 해결하지 말고 친구와 협력하는 장면을 추가해줘 / 7세 어린이가 모를 수 있는 단어를 쉬운 표현으로 바꿔줘</span>
AI와 대화가 길어진다고 자동으로 좋아지는 것이 아니라 무엇이 부족한지 사람이 판단해 수정 방향을 제시하는 것이 핵심
---
## 2.3 결과를 비교해 선택하기
AI가 제시한 첫 결과만 보면 다른 가능성을 떠올리기 어려울 수 있음. 이때 하나의 답을 계속 고치기보다 서로 다른 후보를 여러 개 만든 뒤 비교하면 **무엇이 더 적절한지 판단할 기준**이 생기고 선택의 폭도 넓어짐
비교는 AI가 가장 좋은 답을 자동으로 골라 주는 과정이 아니라, 사람이 목적에 맞는 결과를 선택하기 위한 과정
- 제목 5개 만들기
- 결말 3가지 비교
- 캐릭터 성격 3가지 제안
- 같은 장면을 밝은 분위기와 긴장감 있는 분위기로 각각 생성
비교할 때는 가장 좋은 것처럼 막연하게 고르기보다 대상·주제·이해도·일관성처럼 사람이 기준을 정함
---

# 3. AI를 활용하여 짧은 동화 만들기(기초 이론)
---
## 3.1 여러 생성 결과를 단계로 나누어 연결하는 작업
짧은 동화 콘텐츠 만들기는 한 번의 요청으로 완성하는 실습이 아니라 주제와 독자를 정하고 이야기를 장면으로 나눈 뒤 글과 이미지를 연결하고, 생성 결과를 직접 확인·수정하는 과정
- 한 번에 ‘동화 하나를 만들어줘’라고 요청하면 제목·등장인물·줄거리·장면·문장·이미지가 동시에 결정되어 줄거리가 문제인지, 표현이 문제인지, 이미지 설명이 문제인지 구분하기 어려움
- 작업을 여러 단계로 나누면 앞 단계에서 결정한 내용을 유지하면서 필요한 부분만 확인하고 수정할 수 있어 생성형 AI를 더 안정적으로 활용할 수 있음
**전체 제작 흐름**
1. 주제와 대상 독자 정하기
2. 등장인물 후보 만들고 선택하기
3. 줄거리 후보를 비교해 하나 선택하기
4. 6개 장면으로 나누기
5. 장면별 문장 작성
6. 장면별 이미지 설명 작성
7. 이미지 생성
8. 글과 이미지의 일관성 확인
9. 제목·순서·표현을 사람이 최종 수정
AI는 각 단계의 초안을 빠르게 만드는 데 도움을 주고, 이야기의 방향과 최종 선택은 사람이 결정. 문제가 생겼을 때 어느 단계로 돌아가야 하는지도 이 흐름으로 찾을 수 있음
---
## 3.2 주제와 대상 독자
### 3.2.1 주제
주제는 이야기를 통해 독자에게 전달하려는 중심 생각. 재미있는 사건이 많아도 이야기 전체를 관통하는 주제가 없으면 장면이 서로 따로 느껴질 수 있으므로, 먼저 ‘이 이야기를 읽고 무엇을 느끼거나 생각하게 할 것인가’를 정하는 것이 좋음
- 우정
- 협력
- 약속
- 용기
- 환경 보호
한 동화에 여러 교훈을 많이 넣기보다 하나의 핵심 메시지를 중심으로 장면을 구성하면 이야기의 흐름이 선명해짐
---
### 3.2.2 대상 독자
대상 독자는 실제 결과물의 난이도와 표현 방식을 결정하는 기준. 독자의 연령은 어휘·문장 길이·사건의 복잡성·이미지 표현에 영향을 주며, 같은 주제라도 누가 읽느냐에 따라 설명 방식이 달라짐
- 어린 독자에게는 한 장면에 너무 많은 사건을 넣기보다 원인과 결과가 분명하게 이어지도록 구성하는 편이 이해하기 쉬움
> <span color="gray">예시) 7\~9세 대상이라면 한 장면의 문장을 짧게 하고 사건의 원인과 결과가 쉽게 연결되도록 구성하는 것이 적절</span>
---
## 3.3 등장인물과 줄거리 만들기
### 3.3.1 등장인물
등장인물을 정할 때는 이름만 만드는 것이 아니라 어떤 성격을 가지고 있고 어떤 문제를 겪는지까지 함께 정하면 이후 줄거리를 만들기 쉬우며 특히 주인공에게 처음 상태와 변화할 지점을 만들어 두면 장면마다 행동의 이유가 자연스럽게 연결됨
- 주인공의 이름과 외형
- 성격
- 좋아하는 것과 어려워하는 것
- 이야기 안에서 해결해야 할 문제
---
### 3.3.2 줄거리
줄거리는 각 장면에서 일어날 사건을 시간 순서로 연결한 이야기의 뼈대로 세부 문장을 먼저 만들기보다 전체 흐름을 먼저 정하면 중간에 이야기가 다른 방향으로 벗어나는 것을 줄일 수 있음
기초 동화는 복잡한 반전보다 시작 → 문제 → 시도 → 협력 또는 변화 → 해결 → 마무리처럼 원인과 결과를 따라가기 쉬운 흐름으로 구성
> <span color="gray">예시) 혼자 모든 일을 하려는 작은 로봇이 무거운 상자를 옮기지 못함 → 동물 친구들이 서로 다른 방법으로 도움 → 함께 옮기는 데 성공 → 협력의 의미를 이해</span>
---
## 3.4 장면을 나누는 방법
장면 나누기는 긴 줄거리를 한 번에 이해할 수 있는 작은 단위로 나누는 과정으로 한 장면에 너무 많은 사건을 넣으면 어떤 장면을 이미지로 표현해야 하는지 불분명해지고 글과 이미지도 서로 맞기 어려워짐
따라서 각 장면은 하나의 핵심 사건을 중심으로 구성하고, ‘이 장면에서 독자가 반드시 알아야 할 변화가 무엇인가’를 기준으로 나누는 것이 좋음

## 3.5 이미지 프롬프트의 기초
텍스트 프롬프트가 ‘무슨 내용을 써야 하는지’를 설명한다면 이미지 프롬프트는 화면에 무엇이 보여야 하는지를 설명하는 입력이며, 동화 삽화를 만들 때는 장면의 핵심 정보를 시각적으로 설명해야 하며, 등장인물의 행동과 장소가 빠지면 문장과 다른 이미지가 생성될 수 있음
처음부터 전문적인 미술 용어를 많이 사용할 필요는 없고, 초보 단계에서는 누가 / 무엇을 하고 / 어디에 있으며 / 어떤 분위기인지를 분명하게 전달하는 것부터 시작
- 등장인물
- 행동
- 장소
- 분위기
- 기본 스타일
- 필요한 구도
> <span color="gray">예시) 작은 파란 로봇과 갈색 다람쥐가 숲길에서 큰 상자를 함께 밀고 있는 장면, 따뜻하고 밝은 어린이 그림책 삽화, 두 인물이 모두 보이는 구도</span>
구도·조명·화면비·캐릭터 일관성 등 이미지 생성 기준은 13주차에서 심화하므로 이번 주차에서는 글과 이미지가 같은 장면을 표현하는지 확인하는 데 집중
---
## 3.6 완성된 콘텐츠 최종 검토
텍스트와 이미지가 모두 만들어졌다고 바로 완성되는 것이 아니라 생성 과정이 여러 단계로 나뉘어 있기 때문에 각 결과가 개별적으로는 자연스러워도 전체를 이어 보면 등장인물·장면·표현이 서로 맞지 않을 수 있음
최종 검토에서는 ‘AI가 잘 만들었는가’보다 처음 정한 주제와 대상에 맞게 하나의 콘텐츠로 연결되었는가를 사람이 확인
**① 이야기 흐름**
- 등장인물의 행동이 앞뒤로 연결되는가
- 문제와 해결이 자연스럽게 이어지는가
**② 대상 적합성**
- 어휘와 문장 길이가 독자에게 적절한가
- 불필요하게 무섭거나 어려운 표현은 없는가
**③ 글과 이미지의 일치**
사람은 문장을 읽을 때 앞 장면의 정보를 자연스럽게 기억하지만, 이미지 생성 AI는 매번 입력된 설명을 중심으로 결과를 만들기 때문에 이전 장면의 설정이 자동으로 유지되지 않음
- 등장인물의 핵심 외형이 장면마다 크게 달라지지 않는가
- 문장 속 행동이 이미지에 나타나는가
- 장소와 시간대가 이야기 흐름과 맞는가
- 중요한 소품이 빠지지 않았는가
- 장면의 감정과 이미지 분위기가 지나치게 어긋나지 않는가
- 이미지 안의 글자나 표지가 이상하게 생성되지 않았는가
> <span color="gray">예시) 문장에서는 주인공이 파란 우산을 들고 있는데 이미지에서는 빨간 우산이 나오면 작은 오류처럼 보이지만 반복될수록 이야기의 일관성이 깨짐</span>
**④ 사람의 최종 수정**
- AI가 만든 표현 중 어색하거나 필요 없는 부분 제거
- 제목·장면 순서·문장 길이 직접 조정
- 최종 메시지가 의도한 주제와 연결되는지 확인
<callout icon="💡" color="blue_bg">
	생성형 AI 실습에서 중요한 것은 한 번에 완벽한 명령을 만드는 능력이 아니라, 목적과 조건을 정하고 → 초안을 만들고 → 비교하고 → 수정하고 → 검토하는 과정을 익히는 데 있음
</callout>

## 4.1 1단계. 동화의 기본 조건 정하기
아래 프롬프트를 입력하고 생성된 결과를 확인
### 프롬프트 1 — 동화 기본 기획
```plain text
7~9세 어린이를 위한 짧은 동화를 만들려고 해.
주제는 ‘친구와 협력하는 방법’이고, 주인공은 호기심이 많지만 혼자서 모든 일을 해결하려는 작은 로봇 ‘모모’야.
전체 이야기는 6개 장면으로 구성할 거야.
먼저 동화의 제목 후보 3개와 전체 줄거리를 5문장 이내로 제안해줘.
```
**결과에서 확인할 것**
- 제목과 줄거리가 주제에 맞는가
- 주인공의 특징이 반영되었는가
- 7\~9세 어린이가 이해하기 어려운 설정은 없는가
생성된 제목 3개 가운데 하나를 직접 선택
---
## 4.2 2단계. 이야기를 6개 장면으로 나누기
앞에서 선택한 제목과 줄거리를 그대로 이어서 다음 프롬프트 입력
### 프롬프트 2 — 장면 구성
```plain text
방금 만든 이야기의 흐름을 이용해서 동화를 6개 장면으로 나눠줘.
각 장면에는 다음 내용을 포함해줘.
1. 장면 번호
2. 장면에서 일어나는 핵심 사건
3. 동화책에 들어갈 본문 2문장

이야기는 ‘문제 발생 → 혼자 해결하려고 시도 → 실패 → 친구와 협력 → 문제 해결 → 배운 점’의 흐름이 자연스럽게 이어지도록 해줘.
7~9세 어린이가 이해하기 쉬운 단어를 사용해줘.
```
**결과에서 확인할 것**
- 6개 장면이 서로 자연스럽게 이어지는가
- 모모가 처음부터 바로 협력하지 않고 변화하는 과정이 보이는가
- 각 장면이 2문장이라는 조건을 지켰는가
---
## 4.3 3단계. 첫 결과를 그대로 사용하지 않고 수정하기
생성된 결과에서 보완할 점을 확인한 뒤 아래 프롬프트를 입력해 수정 결과를 비교
### 프롬프트 3 — 결과 수정
```plain text
전체 흐름은 유지하되 다음 조건으로 수정해줘.
- 모모가 혼자 문제를 해결하려다가 어려움을 겪는 장면을 조금 더 분명하게 보여줘.
- 친구가 해결 방법을 전부 알려주는 것이 아니라 모모와 친구가 서로 아이디어를 하나씩 내서 함께 해결하도록 바꿔줘.
- 어려운 단어는 더 쉬운 표현으로 바꿔줘.
- 각 장면은 여전히 2문장 이내로 유지해줘.
```
---
## 4.4 4단계. 장면에 맞는 이미지 설명 만들기
동화의 글이 정리되면 각 장면을 이미지로 만들기 위한 설명을 생성
### 프롬프트 4 — 이미지 장면 설명 만들기
```plain text
완성된 6개 장면 각각에 어울리는 동화책 삽화를 만들려고 해.
각 장면마다 이미지 생성 AI에 입력할 수 있는 설명을 작성해줘.

공통 조건은 다음과 같아.
- 주인공 모모: 작고 둥근 몸체를 가진 친근한 로봇, 큰 파란 눈, 노란색 작은 가방
- 전체 분위기: 밝고 따뜻한 어린이 동화책 일러스트
- 폭력적이거나 무서운 표현은 제외
- 각 장면에서 인물의 행동과 장소가 분명하게 보이도록 작성

표 형식으로 ‘장면 / 핵심 상황 / 이미지 설명’을 정리해줘.
```
이 단계에서는 전문적인 이미지 프롬프트 기술보다 **무엇을 보여줄지 구체적으로 설명하면 결과가 달라진다는 점**을 경험하는 데 초점을 둠
---
## 4.5 5단계. 실제 이미지 한 장 생성하고 수정하기
6개 장면을 모두 생성하기 전에 한 장면을 선택해 이미지를 먼저 생성하고 결과를 확인
### 프롬프트 5 — 첫 번째 삽화 생성
```plain text
어린이 동화책 삽화를 만들어줘.
작고 둥근 몸체, 큰 파란 눈, 노란색 작은 가방을 멘 친근한 로봇 ‘모모’가 혼자 무거운 상자를 옮기려고 애쓰는 장면이야.
모모는 힘들어 보이지만 무섭거나 위험한 분위기는 아니야.
밝고 따뜻한 동화책 일러스트 분위기로 표현해줘.
```
첫 이미지가 생성되면 결과를 관찰한 후 아래 프롬프트로 수정 요청
### 프롬프트 6 — 이미지 수정 요청
```plain text
현재 그림의 전체 분위기는 유지해줘.
모모가 너무 슬퍼 보이지 않도록 표정을 조금 더 밝게 바꾸고, 혼자 상자를 옮기기 어려워하는 상황이 더 잘 보이게 해줘.
배경에는 앞에서 설정한 친구 캐릭터가 멀리서 모모를 바라보고 있는 모습을 추가해줘.
```
**비교할 것**
- 처음 이미지와 수정 이미지에서 어떤 부분이 달라졌는가
- 수정 요청한 조건이 실제로 반영되었는가
- 원하지 않는 변화가 함께 생기지는 않았는가
---
## 4.6 6단계. 완성된 동화 전체 검토하기
텍스트와 이미지를 만든 뒤 마지막으로 AI에게 완성 여부를 판단하게 맡기지 않고 사람이 기준을 정해 검토
### 프롬프트 7 — 최종 검토
```plain text
지금까지 만든 6개 장면의 동화를 다음 기준으로 검토해줘.
1. ‘친구와 협력하는 방법’이라는 주제가 이야기 전체에서 드러나는가
2. 7~9세 어린이가 이해하기 어려운 표현이 있는가
3. 앞뒤 장면에서 서로 모순되는 내용이 있는가
4. 각 장면의 글과 이미지 설명이 서로 맞는가
5. 수정하면 좋은 부분이 있다면 이유와 함께 제안해줘.

단, 새로운 이야기를 다시 만들지 말고 현재 내용에서 확인해야 할 부분만 알려줘.
```
AI가 제안한 검토 결과도 그대로 받아들이지 않고 실제 동화와 비교해 최종 수정 여부를 결정

	- 최종 결과에서 사람이 직접 수정하거나 선택한 부분 1개 이상 설명
</callout>
