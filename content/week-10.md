# 1. 생성형 AI의 개념과 기본 원리
## 1.1 생성형 AI는 무엇을 만드는가
생성형 AI는 학습한 데이터의 패턴을 바탕으로 사용자의 입력과 현재 맥락에 맞는 새로운 결과를 구성하는 AI
1·2주차에서 살펴본 것처럼 분류·예측 중심 AI가 입력을 범주나 값으로 판단하는 데 초점을 둔다면, 생성형 AI는 입력을 바탕으로 **새로운 내용의 형태를 구성하는 것**에 초점을 둠. 10주차에서는 이 차이를 다시 정의하기보다 결과가 만들어지는 구조를 분석함
---
## 1.2 토큰과 토큰화(Token·Tokenization)
토큰은 언어 모델이 텍스트를 처리할 때 사용하는 기본 단위이며, 항상 단어 하나와 정확히 일치하지는 않음
토큰화는 문장을 모델이 처리할 수 있는 여러 토큰으로 나누는 과정
- 입력 길이와 처리 가능한 정보량에 영향
- 언어와 표현 방식에 따라 같은 의미도 토큰 수가 달라질 수 있음
- 긴 문서를 다룰 때는 글자 수보다 모델이 처리하는 토큰 범위를 고려해야 함
학생 입장에서는 토큰의 세부 계산법을 외우기보다 **모델이 문장을 그대로 읽는 것이 아니라 처리 가능한 단위로 나누어 계산한다는 점**을 이해하면 충분
---
## 1.3 대규모 언어 모델(Large Language Model, LLM)
대규모 언어 모델은 매우 많은 텍스트에서 언어의 패턴을 학습하고, 현재까지 주어진 문맥을 바탕으로 다음에 올 가능성이 높은 토큰을 반복해서 선택하며 문장을 구성하는 모델
---
### 1.3.1 입력이 바로 문장 전체의 정답이 되는 것은 아님
사용자의 질문이 들어오면 모델은 저장된 답변 하나를 그대로 꺼내기보다 현재 문맥에 이어질 수 있는 표현의 가능성을 계산해 결과를 이어감
> <span color="gray">예시) 오늘 날씨가 매우라는 문맥 뒤에는 좋다, 춥다, 덥다처럼 여러 표현이 가능하며, 모델은 현재 문맥과 학습된 패턴을 이용해 다음 표현의 가능성을 계산함</span>
---
### 1.3.2 트랜스포머와 어텐션(Transformer·Attention)
현재 널리 쓰이는 대규모 언어 모델은 대부분 2017년 발표된 트랜스포머(Transformer) 구조를 바탕으로 함. 트랜스포머의 핵심은 어텐션으로, 문장 안의 각 토큰이 다른 토큰 가운데 무엇을 더 중요하게 참고할지 계산하는 방식
- 앞뒤 단어의 관계를 거리와 상관없이 함께 계산
- 같은 단어도 문맥에 따라 다른 의미로 처리
- 긴 문장 안에서 어떤 부분이 지금 생성할 내용과 관련 있는지 가중치를 둠
> <span color="gray">예시) 그는 은행에 가서 통장을 만들었다와 강가의 은행나무 아래에서 쉬었다에서 은행이라는 같은 글자도 통장·강가처럼 함께 쓰인 단어를 참고해 서로 다른 의미로 처리됨</span>
2주차에서 배운 신경망이 입력을 여러 층에서 계산해 결과를 만든다면, 트랜스포머는 그 계산 과정에서 **문맥 안의 관계를 집중적으로 반영하는 구조**를 추가한 것으로 이해할 수 있음
---
### 1.3.3 사전학습(Pretraining)
사전학습은 대규모 데이터에서 언어·이미지 등 폭넓은 패턴을 미리 학습하는 단계
- 언어의 문법과 표현
- 단어와 문맥의 관계
- 문서 구조
- 다양한 주제에서 반복되는 패턴
사전학습을 했다는 사실이 현재 시점의 모든 정보를 알고 있다는 뜻은 아니며, 학습 데이터를 모은 시점 이후의 정보나 특정 조직의 내부 자료에는 한계가 있음
---
### 1.3.4 사후학습(Post-training)
사전학습만 마친 모델은 문장을 자연스럽게 이어 쓰는 능력은 있지만 질문에 답하거나 지시를 따르는 방식으로 행동하지는 않음. 사후학습은 사전학습된 모델을 실제 사용 목적에 맞게 다듬는 단계
- **지시 학습(Instruction Tuning)**: 질문과 바람직한 답변의 예시를 학습해 지시를 따르는 형식을 익힘
- **사람의 피드백을 이용한 강화학습(Reinforcement Learning from Human Feedback, RLHF)**: 여러 답변 가운데 사람이 더 낫다고 평가한 답변이 나오도록 조정
- **안전 기준 반영**: 위험하거나 부적절한 요청에 응답하는 방식을 조정
> <span color="gray">예시) 사전학습만 한 모델에 대한민국의 수도는?을 입력하면 비슷한 퀴즈 문장을 계속 이어 쓸 수 있지만, 사후학습을 거친 모델은 서울이라고 답하는 방식으로 행동함</span>
챗봇이 친절하고 확신 있게 답하는 말투도 사후학습의 결과이므로 **답변의 말투가 자신감 있다는 사실이 내용이 정확하다는 근거는 아님**
---
## 1.4 맥락 창(Context Window)
맥락 창은 모델이 한 번의 생성 과정에서 직접 참고할 수 있는 입력과 대화의 범위
맥락 창이 넓으면 더 긴 문서를 한 번에 다룰 수 있지만 다음과 같은 문제가 생길 수 있음
- 중요한 조건이 긴 문서 중간에 묻힘
- 서로 다른 지시가 충돌
- 관련 없는 정보가 많아짐
- 일부 세부 조건이 약하게 반영됨
긴 문서를 나누어 다루는 방법은 2.5에서 정리함
---
## 1.5 확률적 생성(Probabilistic Generation)
1.3에서 본 다음 토큰 예측 과정에서 여러 후보 중 하나를 선택하며 결과를 이어가는 방식으로, 같은 입력에도 표현이나 문장 순서가 조금씩 달라질 수 있음
- 다양한 아이디어를 만드는 데 유용
- 결과가 매번 완전히 같지 않을 수 있음
- 표현의 다양성과 사실의 정확성은 별개의 문제
자연스러운 문장이 생성되는 이유와 그 문장이 사실인지 여부는 서로 다른 평가 기준
> <span color="gray">예시) 대학생에게 생성형 AI를 설명해줘라는 요청에 대해 한 번은 검색·요약 사례를 중심으로, 다른 번에는 글쓰기·이미지 생성 사례를 중심으로 답할 수 있음. 두 결과가 다른 것은 하나가 틀렸다는 의미가 아니라 확률적 생성 과정에서 여러 가능한 표현이 선택될 수 있기 때문</span>
---

온도는 다음 토큰을 고를 때 가능성이 높은 후보에 얼마나 집중할지 정하는 설정값

---
## 1.6 이미지 생성의 원리: 확산 모델(Diffusion Model)
이미지 생성 AI는 언어 모델처럼 토큰을 하나씩 이어 쓰는 방식과 다르게, 많은 이미지 생성 서비스가 확산 모델을 바탕으로 작동함
**① 학습 단계**
- 원본 이미지에 노이즈를 조금씩 더해 알아볼 수 없는 상태로 만드는 과정을 반복
- 모델은 노이즈가 섞인 이미지에서 노이즈를 걷어 내는 방법을 학습
**② 생성 단계**
- 무작위 노이즈에서 시작
- 텍스트 프롬프트를 조건으로 삼아 노이즈를 여러 단계에 걸쳐 조금씩 제거
- 마지막 단계에서 프롬프트에 맞는 이미지가 나타남
> <span color="gray">예시) 흐린 안개 속에서 윤곽이 조금씩 선명해지듯, 처음에는 형태를 알 수 없는 점들이 단계를 거치며 고양이·배경·조명으로 정리됨</span>
이 방식 때문에 같은 프롬프트에서도 시작 노이즈가 달라지면 다른 이미지가 나오며, 이미지 안의 글자처럼 정확한 형태가 필요한 요소는 오류가 생기기 쉬움
---
## 1.7 추론형 모델(Reasoning Model)의 확산
추론형 모델은 답을 바로 생성하기보다 답하기 전에 내부적으로 여러 단계의 추론 과정을 거치도록 학습한 모델. 2024년 별도 모델로 처음 등장한 뒤 2025년부터 주요 서비스의 기본 기능으로 통합되었고, 현재 주요 생성형 AI 서비스에서는 질문에 따라 바로 답할지 더 오래 생각할지를 사용자가 고르거나 서비스가 자동으로 정하는 방식이 일반화됨

## 1.8 생성 결과가 사실과 다를 수 있는 이유
생성형 AI는 문맥에 어울리는 출력을 만드는 능력이 강하지만 실제 세계의 사실을 매번 독립적으로 확인하는 방식으로만 작동하지 않음
- 학습 데이터가 불완전하거나 오래될 수 있음
- 질문이 모호하거나 정보가 부족할 수 있음
- 실제 자료에 없는 관계를 그럴듯하게 연결할 수 있음
- 출처 형식을 요청하면 실제 확인 없이 비슷한 형식의 문자열을 만들 수 있음
이 특성은 환각과 연결됨

# 2. 생성형 AI의 한계와 보완 방식
## 2.1 환각(Hallucination)
환각은 생성형 AI가 실제 근거가 없거나 사실과 다른 내용을 자연스럽고 확신 있게 생성하는 현상
- 존재하지 않는 논문·책·기사 제목
- 틀린 날짜·통계·인물 정보
- 원문에 없는 내용 추가
- 실제 인물이 하지 않은 발언 인용
- 오래된 규정을 현재 기준처럼 설명
환각은 AI가 일부러 거짓말을 하는 사람처럼 의도를 가진다는 의미가 아니라 **확률적으로 자연스러운 출력을 구성하는 방식과 지식·맥락의 한계가 결합해 발생하는 결과**로 이해하는 것이 적절
> <span color="gray">예시) AI가 2025년 교육부 보고서에 따르면...이라고 말하더라도 실제 보고서가 존재하는지, 해당 문장이 실제로 있는지는 별도로 확인해야 함</span>
<callout color="blue_bg">
	### 실사례 : **ChatGPT가 만든 가짜 판례를 제출한 변호사들**
	미국 뉴욕의 변호사들은 항공사 상대 소송(Mata v. Avianca)에서 ChatGPT를 검색 엔진처럼 사용해 판례를 찾았고, ChatGPT가 만들어 낸 존재하지 않는 판례와 인용문을 확인 없이 법원에 제출함. 법원은 2023년 6월 변호사와 소속 법무법인에 5,000달러의 제재금을 부과함, 출처: [LawSites(2023)](https://www.lawnext.com/2023/06/court-imposes-sanctions-on-lawyers-who-filed-bogus-cases-after-relying-on-chatgpt-for-legal-research.html)
	요청한 형식(판례 이름·인용문)에 맞는 그럴듯한 문자열을 만드는 생성 방식이 실제 근거 확인 없이 사용될 때 어떤 결과가 생기는지 보여준 사례
	> 생성형 AI는 검색 엔진이 아니며, 출처처럼 보이는 결과일수록 원문으로 이동해 확인해야 함
</callout>
---
## 2.2 생성 결과의 검증
중요한 사실은 AI에게 다시 확실해?라고 묻는 것만으로 검증되지 않음. 같은 시스템 안에서 답을 재생성하는 것이므로 독립 검증이 아니며, AI의 말 안에서 답을 찾기보다 **외부의 확인 가능한 근거로 이동하는 것**이 중요
- 숫자는 원자료와 비교
- 인물과 기관명은 실제 존재 여부 확인
- 인용은 원문 확인
- 법률·정책은 기준 날짜 확인
- 출처는 실제 문서로 이동해 내용 확인
3주차에서 배운 정보 검증 방법이 생성형 AI 결과에도 그대로 적용됨
<callout color="blue_bg">
	### 실사례 : **에어캐나다 챗봇의 잘못된 환불 안내**
	에어캐나다 웹사이트의 챗봇은 조문 항공권 할인을 탑승 후에도 소급 신청할 수 있다고 안내했지만 실제 규정은 소급 적용이 불가능했음. 에어캐나다는 챗봇의 안내에 회사가 책임지지 않는다고 주장했으나, 캐나다 브리티시컬럼비아주 민사분쟁조정심판소는 2024년 2월 회사가 웹사이트의 모든 정보에 책임이 있다고 보고 812.02캐나다달러를 배상하도록 결정함, 출처: [MobileSyrup(2024)](https://mobilesyrup.com/2024/02/16/air-canada-has-to-pay-for-chatbot-mistake/)
	> 생성형 AI를 서비스에 넣으면 사용자뿐 아니라 운영 조직도 생성 결과를 검증할 책임을 가짐
</callout>
---
## 2.3 생성 결과의 편향
9주차에서 데이터 편향이 판단 결과를 치우치게 만들 수 있다고 배웠다면, 생성형 AI에서는 같은 편향이 **새로 만들어지는 콘텐츠의 모습**으로 나타남
- 직업·역할을 특정 성별이나 인종으로 반복 표현
- 특정 국가·문화를 고정관념에 가까운 모습으로 묘사
- 학습 데이터에 적게 나타난 언어·집단에서 품질이 낮아짐
- 프롬프트에 없는 특성을 기본값처럼 채워 넣음
> <span color="gray">예시) 의사·CEO를 그려달라는 요청에 매번 비슷한 성별과 외모의 인물이 나오고, 간호사·청소 노동자를 요청하면 다른 성별과 외모가 반복된다면 프롬프트에 없던 고정관념이 결과에 들어간 것</span>
<callout color="blue_bg">
	### 실사례 : **이미지 생성 AI의 직업별 고정관념**
	블룸버그는 2023년 이미지 생성 AI인 Stable Diffusion으로 고소득·저소득 직업 14개에 대한 이미지 5,000여 장을 생성해 분석함. 판사 이미지 가운데 여성은 약 3%로 미국 실제 판사 중 여성 비율(약 34%)보다 크게 낮았고, 고소득 직업은 밝은 피부의 남성, 저소득 직업은 여성과 어두운 피부로 표현되는 경향이 실제보다 강하게 나타남, 출처: [Marketplace(2023)](https://www.marketplace.org/episode/2023/06/14/is-ai-more-biased-than-humans)
	> 생성형 AI는 데이터의 편향을 반복하는 데 그치지 않고 더 강하게 증폭할 수 있으므로, 홍보물·교육 자료에 사용할 때는 표현의 다양성을 사람이 점검해야 함
</callout>
---
## 2.4 검색증강생성(Retrieval-Augmented Generation, RAG)
검색증강생성은 사용자의 질문과 관련된 외부 자료를 먼저 찾아 모델이 그 자료를 참고해 답변을 생성하도록 연결하는 방식
---
### 기본 생성과의 차이
- 기본 생성: 모델이 학습한 패턴과 현재 입력을 중심으로 결과 생성
- 검색증강생성: 현재 질문과 관련된 문서나 데이터베이스를 검색해 추가 맥락으로 제공
---
### 장점
- 최신 문서나 특정 조직의 자료를 답변 근거로 활용 가능
- 답변과 참고 자료를 연결하기 쉬움
---
### 주의점
검색한 자료 자체가 잘못되었거나 관련 문서를 놓치면 생성 결과도 영향을 받을 수 있으므로 검색증강생성 역시 자동으로 정확성을 보장하지는 않음
---

## 2.5 긴 문서를 다룰 때의 기본 전략
**① 문서를 논리적 단위로 나눔**
**② 각 부분의 핵심 주장·수치·조건을 따로 정리**
**③ 중요한 내용은 원문 위치와 함께 확인**
**④ 부분 요약을 전체 구조로 다시 통합**
**⑤ 최종 결과에서 빠진 조건과 서로 모순되는 내용을 재검토**
이 방식은 맥락 창의 한계를 완전히 없애는 기술이라기보다 사용자가 정보량을 구조적으로 관리하는 방법

# 3. 생성형 AI 유형과 기능
생성형 AI는 하나의 기술 이름처럼 보이지만 실제로는 어떤 형태의 입력을 받고 어떤 형태의 결과를 만들어 내는가에 따라 활용 방식과 검토 기준이 달라짐. 같은 생성 원리를 바탕으로 하더라도 텍스트의 오류와 이미지의 오류, 음성의 오류는 서로 다른 모습으로 나타나기 때문에 결과 형태에 맞는 판단 기준이 필요
---
## 3.1 텍스트 생성 AI
텍스트 생성 AI는 질문·지시·문서·대화 기록처럼 언어로 표현된 입력을 받아 새로운 문장이나 구조화된 텍스트를 생성하는 유형
---
### 3.1.1 주요 입력과 출력
**입력**
- 사용자의 질문과 지시
- 보고서·기사·회의록 같은 문서
- 표나 목록처럼 구조화된 텍스트
- 이전 대화의 맥락
**출력**
- 질문에 대한 설명
- 문서 초안
- 요약과 재작성
- 번역
- 아이디어 목록
- 표·체크리스트
- 코드와 코드 설명
텍스트 생성 AI의 핵심은 저장된 문장을 그대로 찾아 보여주는 것이 아니라 현재 입력과 맥락을 바탕으로 문장 구조와 표현을 새롭게 구성한다는 점
---
### 3.1.2 잘하는 일과 주의할 일
텍스트 생성 AI는 많은 문장을 빠르게 재구성하는 데 강점이 있음
- 긴 내용을 짧게 요약
- 같은 내용을 대상에 맞게 쉽게 다시 설명
- 여러 아이디어 후보 생성
- 문서의 기본 구조와 초안 작성
- 반복적인 문장 형식 변환
반면 사실성은 2.1에서 살펴본 환각 유형을 기준으로 별도로 확인해야 하며, 특히 요약에서는 원문의 조건이 빠지거나 없는 내용이 추가될 수 있음
> <span color="gray">예시) 보고서 20쪽을 5줄로 요약했을 때 핵심 결론은 남았지만 조사 대상과 예외 조건이 빠지면 문장은 자연스러워도 원문의 의미는 달라질 수 있음</span>
---
### 3.1.3 검토 기준
- 원문에 없는 주장을 추가하지 않았는가
- 숫자·날짜·고유명사가 정확한가
- 중요한 조건과 예외가 빠지지 않았는가
- 설명의 강도가 근거보다 과도하지 않은가
- 사실과 의견이 섞이지 않았는가
12주차에서는 이 유형을 실제 문서·코딩·PPT·자동화 업무에 적용하는 방법을 다룸
---
## 3.2 이미지 생성 AI
이미지 생성 AI는 텍스트 설명이나 참고 이미지를 입력으로 받아 새로운 이미지를 만들거나 기존 이미지의 일부를 수정하는 유형으로, 1.6의 확산 모델 원리를 바탕으로 작동하는 경우가 많음
---
### 3.2.1 주요 입력과 출력
**입력**
- 장면을 설명한 텍스트
- 참고 이미지
- 기존 이미지와 수정 지시
- 원하는 화면비·스타일·구도 조건
**출력**
- 일러스트
- 사진 스타일 이미지
- 캐릭터와 배경
- 광고·포스터 시안
- 발표자료용 시각 자료
- 기존 이미지의 부분 수정·확장
이미지 생성에서는 텍스트처럼 문장의 논리를 검토하는 대신 화면 안 요소의 형태·위치·관계가 자연스러운지 확인하는 일이 중요
---
### 3.2.2 이미지 생성에서 자주 발생하는 오류
- 손가락·신체 구조가 부자연스러움
- 글자와 간판의 텍스트가 틀림
- 사물의 개수나 위치가 지시와 다름
- 제품 구조가 실제와 다르게 표현됨
- 여러 장면에서 같은 캐릭터의 외형이 달라짐
- 현실의 사건처럼 보이지만 실제로 존재하지 않는 장면이 생성됨
> <span color="gray">예시) 교실에서 노트북을 사용하는 학생 세 명을 요청했는데 학생 수가 달라지거나 화면 속 글자가 의미 없는 문자로 생성될 수 있음</span>
---
### 3.2.3 이미지 결과를 볼 때 확인할 기준
- 프롬프트의 대상·행동·배경이 모두 반영되었는가
- 손·얼굴·사물의 구조가 자연스러운가
- 이미지 안의 글자를 실제 정보처럼 사용해도 되는가
- 인물 표현이 특정 성별·인종·연령의 고정관념으로 치우치지 않았는가
- 실제 사건을 기록한 사진처럼 오해될 가능성이 있는가
- 참고 이미지나 생성 결과의 사용 권리를 확인했는가
13주차에서는 구도·조명·스타일·일관성·편집을 중심으로 이미지 활용을 실습
---
## 3.3 음성·음악 생성 AI
음성·음악 생성 AI는 텍스트나 음성 샘플, 음악 조건을 바탕으로 새로운 음성·음악·효과음을 만드는 유형
---
### 3.3.1 음성 생성
텍스트를 자연스러운 음성으로 읽거나 특정한 말투·속도·감정에 맞는 음성을 생성할 수 있음
- 내레이션
- 안내 음성
- 오디오북
- 다국어 음성
- 교육 콘텐츠
음성 생성에서는 단순히 말이 자연스러운지뿐 아니라 발음·속도·억양·사람의 동의 여부가 중요
> <span color="gray">예시) 사람 이름이나 전문용어를 잘못 발음하면 문장 내용은 맞아도 실제 콘텐츠 품질은 낮아질 수 있음</span>
---
### 3.3.2 음성 복제와 사칭 위험
기존 사람의 음성 특징을 학습해 비슷한 목소리를 만드는 기능은 편리하지만 실제 사람과 구분하기 어려운 결과가 만들어질 수 있음
- 본인의 동의 없는 음성 사용
- 실제 인물이 하지 않은 말을 한 것처럼 표현
- 사칭·금융사기·허위 정보에 악용 가능
따라서 실제 사람의 음성을 사용할 때는 단순히 음성 파일을 가지고 있다는 사실보다 사용 동의·목적·범위를 확인해야 함
---
### 3.3.3 음악 생성
음악 생성 AI는 장르·분위기·악기·템포·길이 등의 조건을 바탕으로 새로운 음악을 구성
- 배경음악
- 광고 음악 시안
- 영상용 짧은 음악
- 분위기 탐색
생성 결과의 음악적 완성도뿐 아니라 서비스별 이용 조건과 상업적 사용 범위도 확인할 필요가 있음
14주차에서는 음성·음악을 영상 제작 과정과 함께 연결해 다룸
---
## 3.4 영상 생성 AI
영상 생성 AI는 텍스트·이미지·기존 영상을 이용해 시간의 흐름이 있는 새로운 장면을 생성하거나 기존 영상을 변형하는 유형
---
### 3.4.1 이미지 생성과 다른 점
정지 이미지는 한 장면의 모습만 확인하면 되지만 영상은 여러 프레임이 연속해서 이어짐. 따라서 한 프레임이 잘 만들어졌더라도 다음 프레임에서 인물·물체·배경이 바뀌면 영상 전체가 부자연스럽게 보일 수 있음
영상 생성에서는 다음 정보가 추가로 중요
- 누가 움직이는가
- 어떤 행동을 하는가
- 행동의 시작과 끝은 무엇인가
- 카메라가 움직이는가
- 장면의 길이는 어느 정도인가
---
### 3.4.2 대표 활용
- 숏폼 영상
- 광고 시안
- 홍보영상
- 교육 콘텐츠
- 스토리보드 시각화
- 정지 이미지에 움직임 추가
---
### 3.4.3 자주 발생하는 오류
- 인물의 얼굴이나 옷이 프레임마다 달라짐
- 손과 사물의 형태가 움직이면서 변함
- 배경 구조가 흔들림
- 움직임 방향이 갑자기 바뀜
- 물리적으로 자연스럽지 않은 동작이 생성됨
이러한 문제를 시간적 일관성(Temporal Consistency)의 관점에서 확인할 수 있음
> <span color="gray">예시) 사람이 컵을 들어 올리는 장면에서 컵의 손잡이가 중간 프레임에서 사라지거나 손가락 수가 달라진다면 한 장면의 이미지는 자연스러워도 영상 전체의 일관성은 낮음</span>
---
### 3.4.4 검토 기준
- 인물과 사물의 외형이 시간 흐름에서 유지되는가
- 행동의 시작과 끝이 자연스럽게 연결되는가
- 카메라 움직임이 장면의 목적과 맞는가
- 생성 장면이 실제 사건 기록처럼 오해될 가능성은 없는가
- 음성·음악·이미지의 사용 권리를 함께 확인했는가
14주차에서는 이러한 특성을 바탕으로 릴스·홍보영상 제작을 실습
---
## 3.5 코드 생성 AI
코드 생성 AI는 자연어 요구사항이나 기존 코드를 입력받아 프로그램 코드의 초안·수정안·설명·테스트 후보를 생성하는 유형
---
### 3.5.1 대표 기능
- 함수와 반복 코드 초안
- 오류 메시지 설명
- 기존 코드의 구조 설명
- 코드 수정안 제시
- 테스트 코드 후보 생성
- 다른 프로그래밍 언어로 변환
코드 생성도 언어 모델의 생성 결과이므로 코드처럼 보이는 문자열이 생성되었다는 사실과 실제로 올바르게 동작한다는 사실은 다름
---
### 3.5.2 코드가 그럴듯해 보여도 확인해야 하는 이유
- 존재하지 않는 함수나 라이브러리를 사용할 수 있음
- 일부 요구사항을 빠뜨릴 수 있음
- 정상 입력만 처리하고 예외 입력에서 오류가 날 수 있음
- 개인정보나 비밀번호를 노출하는 코드가 포함될 수 있음
- 보안상 위험한 처리 방식을 제안할 수 있음
> <span color="gray">예시) 파일을 정리하는 코드를 요청했는데 삭제 조건이 너무 넓게 설정되어 필요한 파일까지 지울 수 있다면 코드는 실행되더라도 안전한 코드라고 할 수 없음</span>
---
### 3.5.3 검토 기준
- 요구사항을 모두 충족하는가
- 실제 환경에서 실행되는가
- 잘못된 입력을 처리하는가
- 데이터 손실 가능성이 없는가
- 권한과 보안 문제가 없는가
- 테스트 결과가 예상과 같은가
12주차에서는 코드 생성과 실제 테스트 방법을 실습
---
## 3.6 멀티모달 AI(Multimodal AI)
멀티모달 AI는 텍스트 하나만 처리하는 것이 아니라 이미지·음성·영상 등 서로 다른 형태의 정보를 함께 입력받거나 여러 형태의 결과를 연결해 처리할 수 있는 AI
---
### 3.6.1 왜 멀티모달이 필요한가
실제 정보는 하나의 형태로만 존재하지 않는 경우가 많음
- 보고서에는 문장과 표·그래프가 함께 있음
- 영상에는 화면·자막·음성이 함께 있음
- 상품 페이지에는 사진과 설명이 함께 있음
멀티모달 AI는 이러한 여러 정보 형태를 함께 다루어 서로 다른 입력 사이의 관계를 해석하는 것이 특징
---
### 3.6.2 활용 사례
예시 1) 그래프 이미지를 업로드하고 가장 큰 변화가 나타난 구간을 설명해줘라고 요청
예시 2) 영수증 사진을 입력해 품목·가격을 표로 정리
예시 3) 발표자료의 슬라이드 이미지와 발표 대본을 함께 제공해 내용의 불일치를 찾음
예시 4) 영상 장면과 자막을 함께 분석해 화면과 설명이 맞는지 확인
---
### 3.6.3 멀티모달 결과의 한계

- 작은 글자나 복잡한 표를 잘못 읽을 수 있음
- 이미지의 위치 관계를 틀리게 해석할 수 있음
- 음성의 고유명사를 잘못 인식할 수 있음
- 서로 다른 입력의 내용을 잘못 연결할 수 있음

## 3.7 생성형 AI를 분석할 때 확인할 기준
생성형 AI를 비교할 때는 서비스 이름이나 결과의 화려함보다 입력·출력·생성 방식·오류 형태·검토 책임을 기준으로 보는 것이 중요
**① 무엇을 입력으로 받는가**
텍스트·이미지·음성·영상·코드 가운데 어떤 형태를 입력으로 사용할 수 있는지 확인. 같은 서비스라도 입력 형식에 따라 가능한 기능이 달라질 수 있음
**② 어떤 형태의 결과를 만드는가**
문장·이미지·음성·영상·코드처럼 결과 형태가 달라지면 품질을 판단하는 기준도 달라짐. 텍스트의 사실성, 이미지의 세부 구조, 영상의 시간적 일관성처럼 결과에 맞는 기준을 적용해야 함
**③ 모델의 학습 정보와 현재 제공된 맥락 중 무엇을 참고하는가**
모델이 기존 학습 패턴만 이용하는지, 사용자가 문서를 제공했는지, 검색을 통해 외부 자료를 가져왔는지를 구분해야 결과의 근거 범위를 판단하기 쉬움
**④ 결과가 확률적으로 달라질 수 있는가**
같은 입력에도 표현·구도·장면이 달라질 수 있으므로 5주차에서 연습한 것처럼 여러 결과를 비교해 목적에 맞는 결과를 선택
**⑤ 어떤 오류가 가장 중요한가**
결과 형태별로 주의할 오류가 다르므로 3.1\~3.6의 유형별 검토 기준과 3.6의 요약표를 적용
**⑥ 사람이 무엇을 최종 확인해야 하는가**
생성 결과가 목적에 맞는지, 사실과 근거가 정확한지, 개인정보·저작권·초상·음성 등 권리 문제가 없는지, 실제 사용 환경에서 문제가 없는지를 사람이 최종적으로 확인해야 함
---
## 3.8 하나의 콘텐츠 제작에서 여러 유형이 연결되는 방식
생성형 AI 유형은 서로 완전히 분리되어 사용되기보다 하나의 작업 안에서 역할을 나누어 연결되는 경우가 많음
> <span color="gray">예시) 대학생을 위한 AI 활용 안내 콘텐츠를 만든다면</span>
**① 텍스트 생성 AI**
안내문의 목차와 설명 문장 초안을 작성
**② 이미지 생성 AI**
핵심 메시지를 보여줄 삽화와 표지 시안을 제작
**③ 음성 생성 AI**
안내 영상의 내레이션 초안을 음성으로 변환
**④ 영상 생성 AI**
정지 이미지와 장면 설명을 이용해 짧은 움직이는 장면을 제작
**⑤ 코드 생성 AI**
콘텐츠를 보여줄 간단한 웹페이지나 인터랙션의 코드 초안을 작성
**⑥ 멀티모달 AI**
문장과 이미지, 슬라이드와 대본이 서로 일치하는지 함께 검토
이 과정에서 중요한 것은 많은 유형을 사용하는 것이 아니라 각 단계의 목적에 맞는 유형을 선택하는 것. 텍스트를 생성하는 문제에 영상 모델을 사용할 필요가 없고, 이미지가 필요하다고 해서 모든 장면을 생성형 이미지로 만들 필요도 없음. **문제와 결과 형태를 먼저 정하고 그에 맞는 생성형 AI를 선택하는 것이 기본 원칙**
---

## 4.1 실험 설계
**사용할 자료**
- 9주차 강의교안처럼 교수자가 활용을 허용한 강의자료 1개
- 개인정보나 다른 사람의 과제·저작물이 포함된 파일은 사용하지 않음(7주차)
**두 가지 조건**
- **조건 A(자료 없이 묻기)**: 질문만 입력

## 4.4 정리: 자료를 주고 질문할 때의 확인 습관
1. 질문할 때 근거가 될 자료를 함께 제공함
2. 자료에 근거해서만 답하고 근거 위치를 표시하도록 요청함
3. 수치·고유명사·기준은 표시된 위치로 가서 원문을 직접 확인함
4. 자료에 없는 질문에는 없다고 답하는지 확인함
5. 긴 자료는 장 단위로 나누어 질문함(2.5)

	**학습 요약**
	- 대규모 언어 모델은 텍스트를 토큰으로 나누고, 어텐션으로 문맥의 관계를 계산하며, 다음 토큰을 확률적으로 선택해 문장을 생성함
	- 사전학습으로 언어의 패턴을 익히고 사후학습으로 지시를 따르는 방식을 다듬지만, 확신 있는 말투가 정확성을 보장하지는 않음
	- 이미지 생성은 노이즈를 단계적으로 제거하는 확산 모델을 바탕으로 하는 경우가 많고, 추론형 모델도 확률적 생성이라는 기본 원리는 같음
	- 환각과 생성 결과의 편향은 생성 방식과 학습 데이터의 한계에서 나타나므로 외부 근거 검증과 표현의 다양성 점검이 필요함
	- RAG는 외부 문서를 근거로 제공하고 미세조정은 모델의 행동 방식을 조정하며, 목적에 따라 적합한 방식이 다름
	- 생성형 AI는 결과 형태에 따라 텍스트·이미지·음성·영상·코드·멀티모달로 구분하고 유형별 검토 기준을 적용해야 함
	- 11주차에서는 이번 주차에서 분석한 생성형 AI의 원리와 유형을 바탕으로 콘텐츠의 목적·대상·메시지를 기획함
