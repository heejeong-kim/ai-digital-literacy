# 1. AI 발전의 흐름
## 1.1 기계의 지능을 어떻게 판단할 것인가
### 1.1.1 튜링 테스트(Turing Test)
1950년 앨런 튜링이 제안한 사고실험으로, 기계가 대화를 통해 사람과 구분하기 어려운 반응을 보일 수 있는지를 질문한 초기 AI 논의의 대표 사례. 당시에는 기계가 실제로 ‘생각한다’는 말을 어떻게 정의할 것인지부터 논쟁이 필요했기 때문에, 내부의 사고 과정을 직접 증명하려 하기보다 사람이 관찰할 수 있는 대화 행동을 기준으로 문제를 바꾸어 접근했다는 점이 중요
기본적인 상황은 사람이 문자 기반 대화를 통해 상대와 질문·답변을 주고받되, 상대가 사람인지 기계인지 직접 볼 수 없는 조건을 가정하는 것. 이때 기계가 충분히 자연스럽고 맥락에 맞는 반응을 보여 평가자가 사람과 쉽게 구분하기 어렵다면, 적어도 외부 행동의 관점에서는 지능적인 반응을 보였다고 판단할 수 있다는 문제의식을 갖는 것
- **평가 대상**: 기계의 내부 구조나 의식의 존재보다 외부에서 관찰되는 대화 반응
- **평가 방식**: 질문에 대한 답변의 자연스러움·맥락 적합성·일관성 등을 사람이 종합적으로 판단
- **의미**: ‘기계가 생각하는가’라는 추상적인 철학적 질문을 관찰 가능한 행동의 문제로 전환
- **연구적 영향**: 인간과 기계의 대화, 언어 이해, 문제 해결 능력을 어떻게 평가할 것인지에 대한 초기 기준을 제시
> <span color="gray">예시) 어떤 대화 시스템이 질문의 의도를 파악해 자연스럽게 답하고 앞선 대화 내용을 이어 간다면 사람처럼 보이는 반응을 만들 수 있으나 자연스러운 문장을 만든다는 사실만으로 실제 세계를 사람처럼 이해하거나 모든 종류의 지능을 갖추었다고 결론 내릴 수는 없음</span>
**튜링 테스트의 한계**
- 사람과 비슷한 대화를 만드는 능력은 시각 인식·로봇 제어·수학적 추론·창의성 등 AI의 모든 능력을 대표하지 않음
- 평가자가 사람과 구분하기 어렵다고 느끼는 정도는 질문의 종류와 대화 상황에 따라 달라질 수 있음
- 사람처럼 보이는 반응과 실제로 정확한 정보를 제공하는 능력은 서로 다른 문제
- 따라서 오늘날에는 하나의 테스트만으로 AI 전체 성능을 판단하기보다 과제별 정확도·안전성·신뢰성 등 여러 기준을 함께 사용
튜링 테스트의 핵심 가치는 오늘날 AI를 판정하는 최종 시험이라는 데 있기보다, 지능을 어떻게 관찰하고 평가할 것인가라는 질문을 구체적인 행동의 문제로 바꾸었다는 점. 이후 AI의 발전을 살펴볼 때도 단순히 사람과 얼마나 비슷한지보다 어떤 문제를 어떤 방식으로 해결할 수 있게 되었는지를 함께 보는 것이 중요
---
## 1.2 사람이 규칙을 작성하던 AI
### 1.2.1 규칙 기반 방식
초기 AI의 많은 시스템은 사람이 문제 해결에 필요한 규칙을 직접 정하고 컴퓨터가 그 규칙을 실행하는 구조
- 조건과 결과를 명확하게 표현할 수 있는 문제에 적합
- 판단 근거를 비교적 설명하기 쉬움
- 예외가 많아질수록 규칙의 수가 늘고 관리가 복잡
> <span color="gray">예시) ‘특정 조건을 모두 만족하면 추가 검사를 권고한다’처럼 전문가가 판단 규칙을 미리 작성하면 시스템은 입력된 정보가 규칙에 맞는지 확인해 결과를 제시</span>
---
### 1.2.2 전문가 시스템(Expert System)
특정 분야 전문가의 지식과 판단 규칙을 컴퓨터가 사용할 수 있는 형태로 정리해 의사결정을 지원하는 시스템
- **지식베이스**: 분야의 사실·규칙·조건을 저장
- **추론 과정**: 입력된 상황과 규칙을 비교해 결론을 도출
- **장점**: 반복되는 전문 판단을 일정한 기준으로 지원
- **한계**: 전문가가 말로 설명하기 어려운 경험과 새로운 예외를 모두 규칙으로 표현하기 어려움
---
## 1.3 데이터에서 패턴을 학습하는 AI
### 1.3.1 머신러닝으로의 전환
머신러닝은 사람이 모든 판단 규칙을 하나씩 작성하는 대신, 여러 사례가 담긴 데이터를 이용해 입력과 결과 사이의 패턴을 모델이 학습하도록 하는 방식
규칙 기반 AI에서는 사람이 먼저 조건과 예외를 정리한 뒤 시스템에 입력하지만, 현실의 문제는 모든 경우를 규칙으로 미리 적기 어려운 경우가 많음. 이미지·음성·문장처럼 경우의 수가 많고 형태가 복잡한 데이터에서는 사람이 규칙을 계속 추가하는 방식보다 실제 사례를 이용해 반복되는 관계를 찾도록 하는 접근이 더 유용할 수 있음
> <span color="gray">예시) 스팸 메일을 가르는 규칙을 사람이 수백 개 작성하는 대신 정상 메일과 스팸 메일 사례를 학습시키고, 새로운 메일이 어느 쪽과 더 비슷한지 판단하도록 모델을 만듦. 이때 모델은 스팸이라는 의미를 사람처럼 이해하기보다 제목·본문·발신 정보 등 여러 특징과 정답 사이에서 반복되는 관계를 계산해 새로운 입력에 적용</span>
- 개발의 중심이 규칙 작성에서 문제 정의·데이터 구성·학습·평가로 확대
- 사람이 모든 판단 기준을 직접 적는 비중은 줄지만 어떤 데이터를 준비하고 무엇을 정답으로 볼지는 여전히 사람이 결정
- 학습 데이터가 실제 사용 환경을 충분히 반영하지 못하면 새로운 상황에서 성능이 낮아질 수 있음
- 데이터에 오류나 편향이 있으면 학습 결과에도 영향을 줄 수 있음
- 사람이 사라지는 자동 학습이 아니라 사람이 문제와 기준을 정하고 모델이 데이터에서 패턴을 찾는 구조
머신러닝의 중요한 변화는 컴퓨터에게 답을 만드는 규칙을 모두 직접 알려 주는 것에서, 사례를 통해 규칙에 해당하는 계산 기준을 조정하도록 하는 방향으로 중심이 이동했다는 점
---
### 1.3.2 딥러닝의 확산
딥러닝은 여러 층의 인공신경망을 이용해 복잡한 특징을 학습하는 머신러닝의 한 분야
전통적인 머신러닝에서는 사람이 문제 해결에 중요한 특징을 어느 정도 선택하거나 가공하는 경우가 많지만, 딥러닝은 여러 층을 거치며 원래 데이터에서 필요한 특징 표현을 단계적으로 학습하는 비중이 큼. 이 차이 때문에 사람이 어떤 특징을 사용해야 할지 미리 정하기 어려운 이미지·음성·텍스트 처리에서 활용이 빠르게 확대
> <span color="gray">예시) 고양이와 개 이미지를 구분할 때 사람이 귀 모양·윤곽·색상 같은 특징을 하나씩 설계하는 대신, 많은 이미지 사례를 통해 낮은 수준의 선·모양부터 더 복잡한 형태의 조합까지 구분에 도움이 되는 특징을 여러 층에서 학습할 수 있음</span>
- 이미지·음성·텍스트처럼 사람이 중요한 특징을 일일이 정하기 어려운 데이터에 강점
- 대규모 데이터와 고성능 연산 장치의 발전이 학습 가능한 모델의 규모와 활용 범위를 확대
- 복잡한 패턴을 잘 찾을 수 있지만 내부 계산 과정이 커지고 복잡해지면서 결과를 사람이 직관적으로 설명하기 어려운 경우도 있음
- 학습에 많은 데이터와 연산 자원이 필요할 수 있어 문제 규모와 목적에 따라 비용을 함께 고려해야 함
- 모든 문제에서 항상 더 좋은 방법이라는 의미는 아니며 문제의 특성·데이터량·설명 필요성에 따라 다른 방법이 적절할 수 있음
딥러닝의 확산은 AI가 다룰 수 있는 데이터의 범위를 넓혔다는 점에서 중요하며, 이후 대규모 언어 모델과 생성형 AI가 발전할 수 있는 기술적 기반과도 연결
---
### 1.3.3 생성형 AI로의 확장
생성형 AI(Generative AI)는 딥러닝 발전을 바탕으로 분류·예측을 넘어 글·이미지·음성·영상·코드 같은 새로운 결과를 구성하는 활용이 대중화된 단계
기존 AI가 입력을 특정 범주로 나누거나 미래 값을 예측하는 역할에 많이 사용되었다면 생성형 AI는 사용자의 요청과 현재 맥락을 바탕으로 새로운 형식의 결과를 만들어 낸다는 점에서 활용 경험이 크게 달라짐
> <span color="gray">예시) 고객 문의를 불만·배송·환불처럼 분류하는 AI는 기존 범주 가운데 하나를 선택하지만, 생성형 AI는 같은 문의를 바탕으로 고객에게 보낼 답변 초안을 새로 작성할 수 있음. 두 기능은 목적이 다르지만 모두 데이터에서 학습한 패턴을 이용한다는 공통점</span>
- 자연어로 요청할 수 있어 전문적인 프로그래밍 지식이 없는 일반 사용자까지 AI 활용 범위가 확대
- 글쓰기·요약·이미지 제작·코드 작성처럼 사람이 직접 결과물을 만드는 업무에도 AI 활용이 빠르게 확장
- 결과가 자연스럽고 완성도 높게 보여도 실제 사실·출처·권리·적절성까지 자동으로 보장되는 것은 아니므로 사람의 검토가 필요
- 이전 AI와 단절된 기술이라기보다 머신러닝과 딥러닝의 발전 위에서 생성 기능이 크게 확장된 흐름
- 생성형 AI의 등장으로 AI를 사용하는 사람의 역할도 결과를 받는 것에서 목적을 정하고 요청을 구성하고 결과를 검토·수정하는 방향으로 확대
- 구체적인 생성 원리와 유형은 10주차에서 다룸
생성형 AI를 AI 역사의 완전히 새로운 출발점으로 보기보다, 규칙 기반 방식에서 머신러닝·딥러닝으로 이어진 발전 흐름 위에서 생성 가능한 결과의 범위와 사용자 접근성이 크게 넓어진 단계로 이해하는 것이 적절

# 2. 머신러닝과 딥러닝의 기본 구조
## 2.1 머신러닝은 무엇을 학습하는가
머신러닝에서 학습은 사람이 지식을 이해하고 기억하는 과정과 같지 않음. 여러 사례가 담긴 데이터에서 입력과 결과 사이의 반복되는 관계를 계산하고, 새로운 입력이 들어왔을 때 더 적절한 결과를 만들도록 모델 내부의 계산 기준을 조정하는 과정
여기서 중요한 것은 **AI가 데이터 자체를 그대로 외우는 것이 아니라, 데이터 안에서 문제 해결에 도움이 되는 패턴을 찾는다는 점**. 어떤 패턴을 찾도록 학습시키는지는 정답을 함께 제공하는지, 정답 없이 구조를 찾는지, 행동 결과에 보상을 주는지에 따라 달라짐
**머신러닝의 학습방식 3가지**

### 2.1.1 입력과 정답의 관계를 배우는 “지도학습”
지도학습(Supervised Learning)은 입력 데이터와 함께 원하는 정답을 제공하고, 둘 사이의 관계를 학습하도록 하는 방식으로 학생이 문제와 정답을 함께 보면서 풀이 기준을 익히는 것에 비유할 수 있지만, 모델은 의미를 이해하기보다 입력 특징과 정답 사이의 계산 관계를 조정
**대표적인 지도학습 문제는 분류와 회귀**
- **분류**: 결과를 정해진 범주 가운데 하나로 판단
	- 이메일 → 스팸 / 정상
	- 제품 이미지 → 정상 / 불량
	- 고객 정보 → 이탈 가능 / 유지 가능
- **회귀**: 연속적인 수치를 예측
	- 주택 정보 → 예상 가격
	- 과거 판매 기록 → 예상 판매량
	- 기상 조건 → 예상 전력 사용량
> <span color="gray">예시) 스팸 메일 분류 모델을 만든다면 여러 메일에 스팸 또는 정상이라는 정답 표시를 붙여 학습시킴. 모델은 특정 단어 하나만 외우는 것이 아니라 제목·본문·발신 정보 등 여러 특징과 정답 사이의 관계를 조정하고, 새로운 메일이 들어왔을 때 어느 범주에 가까운지 판단함</span>
**지도학습 품질의 중요성**
- 정답 표시가 잘못되면 모델도 잘못된 관계를 학습할 수 있음
- 특정 유형의 사례가 부족하면 실제 환경에서 그 유형을 잘 처리하지 못할 수 있음
- 사람이 붙인 정답에도 주관적 판단이나 기존 편향이 들어갈 수 있음
따라서 정답이 있으니 객관적인 학습이라고 단순하게 이해하기보다 **누가 어떤 기준으로 정답을 만들었는가**까지 확인해야 함
---
### 2.1.2 데이터 안의 구조를 찾는 “비지도학습”
비지도학습(Unsupervised Learning)은 미리 정해진 정답 없이 데이터 자체에서 유사성·차이·구조를 찾는 방식으로 ‘이 고객은 A그룹이다’처럼 정답을 먼저 주는 것이 아니라 모델이 여러 특징을 비교해 서로 비슷한 대상을 묶거나 반복되는 구조를 발견하도록 함
**대표적인 활용**
- **군집화**: 비슷한 구매 행동을 가진 고객을 여러 집단으로 묶음
- **문서 구조 탐색**: 주제나 표현이 비슷한 문서를 묶음
- **패턴 탐색**: 평소와 다른 거래나 이용 행동 후보를 찾음
- **데이터 탐색**: 사람이 미리 예상하지 못한 집단이나 관계의 후보를 발견
> <span color="gray">예시) 온라인 쇼핑몰 고객을 구매 금액·방문 빈도·관심 상품으로 분석했더니 세 집단으로 나뉘었다고 가정. 모델은 충성 고객, 가격 민감 고객, 신규 고객이라는 의미를 알고 묶은 것이 아니라 수치 패턴이 비슷한 사람을 가까운 집단으로 정리한 것으로 각 집단에 어떤 의미를 붙일지는 사람이 실제 데이터와 업무 맥락을 보고 해석</span>
**결과 해석에 특히 주의가 필요**
- 비슷하게 묶였다고 해서 같은 원인이나 성향을 가진다고 단정할 수 없음
- 어떤 특징을 사용했는지에 따라 집단 구성이 달라질 수 있음
- 집단 수를 어떻게 정하느냐에 따라 결과가 달라질 수 있음
- 발견된 패턴이 실제로 의미 있는지 추가 검토가 필요
즉 비지도학습은 정답을 찾아주는 방법이라기보다 데이터를 탐색하고 질문의 후보를 발견하는 방법으로 이해하는 것이 적절
---
### 2.1.3 행동과 보상을 이용하는 “강화학습”
강화학습(Reinforcement Learning)은 어떤 상태에서 행동을 선택하고, 그 행동의 결과로 받은 보상을 이용해 장기적으로 더 좋은 결과를 만드는 행동 전략을 학습하는 방식으로 지도학습이 문제마다 정답을 직접 제공한다면 강화학습은 ‘이 행동은 정답이다’라고 매번 알려 주기보다 행동 결과가 얼마나 좋은지 보상으로 평가한다는 차이가 있음
**강화학습의 기본 요소**
- **상태**: 현재 어떤 상황에 있는가
- **행동**: 지금 어떤 선택을 할 것인가
- **보상**: 그 행동 결과가 얼마나 좋은가
- **정책**: 어떤 상태에서 어떤 행동을 선택할지에 대한 전략
> <span color="gray">예시) 미로를 빠져나오는 시스템을 학습시킨다면 매 순간 이동 방향을 정답으로 알려 주는 대신 출구에 가까워지거나 성공했을 때 높은 보상을 주고, 잘못된 경로에서는 낮은 보상을 줄 수 있음. 반복적인 시도 속에서 장기적으로 더 높은 보상을 얻는 이동 전략을 찾도록 학습함</span>
**대표적인 활용**
- 게임에서 장기적으로 높은 점수를 얻는 행동 학습
- 로봇의 이동·제어 전략 탐색
- 반복적인 자원 배분이나 의사결정 문제
강화학습에서 보상을 잘못 정하면 시스템이 사람이 기대한 목적이 아니라 보상 점수만 높이는 예상하지 못한 행동을 찾을 수 있으므로 무엇을 좋은 결과로 볼 것인지와 안전하게 허용할 행동의 범위를 함께 설계
세 학습 방식을 구분할 때는 어떤 알고리즘 이름인가보다 학습할 때 어떤 피드백이 제공되는가를 먼저 확인하면 이해하기 쉬움

## 2.2 딥러닝은 어떻게 학습하는가
딥러닝(Deep Learning)은 여러 층의 인공신경망(Artificial Neural Network)을 이용해 데이터에서 필요한 특징과 판단 기준을 함께 학습하는 것으로 머신러닝의 지도학습·비지도학습·강화학습이 어떤 방식의 학습 신호를 이용하는가를 구분한다면, 딥러닝은 주로 어떤 구조의 모델을 이용해 복잡한 패턴을 학습하는가에 초점을 둔 개념
### 2.2.1 인공신경망과 여러 층의 구조
인공신경망은 입력된 여러 값을 연결해 계산하고 그 결과를 다음 단계로 전달하는 구조로 하나의 계산 단계만 사용하는 것이 아니라 여러 층을 연속적으로 쌓으면 앞쪽 층에서는 비교적 단순한 특징을, 뒤쪽 층에서는 이를 조합한 더 복잡한 특징을 표현할 수 있음
- **입력층(Input Layer)**: 이미지의 픽셀, 문장의 단어 표현, 센서 값 등 원래 데이터를 입력받음
- **은닉층(Hidden Layer)**: 입력을 여러 단계로 변환하면서 문제 해결에 필요한 특징 표현을 학습
- **출력층(Output Layer)**: 분류할 범주, 예측값, 다음 단어의 확률 등 최종 결과를 계산
> <span color="gray">예시) 고양이 이미지를 분류할 때 초기 층에서는 선·경계·색 변화처럼 비교적 단순한 패턴을 감지하고, 여러 층을 거치면서 귀·눈·얼굴 형태처럼 더 복잡한 특징의 조합을 표현해 최종적으로 고양이일 가능성을 계산할 수 있음</span>
---
### 2.2.2 딥러닝에서 실제로 학습되는 것
딥러닝 모델의 연결에는 입력을 얼마나 중요하게 반영할지를 나타내는 여러 내부 값, 즉 가중치(Weight)가 존재. 
- 처음에는 이 값들이 원하는 결과를 만들도록 충분히 조정되어 있지 않지만, 데이터를 반복해서 처리하면서 예측 결과와 목표 사이의 차이가 작아지는 방향으로 가중치를 수정
- 대표적인 학습 흐름은 다음과 같음
	1. **입력(Forward Pass)**: 데이터를 신경망에 넣어 현재 가중치로 결과를 계산
	2. **오차 계산(Loss)**: 모델의 예측과 실제 목표 사이의 차이를 손실 함수(Loss Function)로 계산
	3. **오차의 영향 추적(Backpropagation)**: 어떤 가중치가 오차에 얼마나 영향을 주었는지 출력층에서 앞쪽 층 방향으로 계산
	4. **가중치 수정(Optimization)**: 경사하강법(Gradient Descent) 등의 최적화 방법을 이용해 손실이 줄어드는 방향으로 가중치를 조금씩 변경
	5. **반복 학습**: 많은 데이터를 반복해서 처리하며 모델의 내부 계산 기준을 점진적으로 조정
<callout color="blue_bg">
	딥러닝에서 ‘학습한다’는 것은 신경망이 사람처럼 내용을 암기하거나 이해한다는 뜻이 아니라, 입력에 대해 더 적절한 결과가 나오도록 수많은 가중치가 반복적으로 조정된다는 의미
</callout>
---
### 2.2.3 딥러닝이 복잡한 데이터에 강한 이유
딥러닝은 여러 층의 신경망을 이용해 원래 데이터에서 필요한 특징 표현 자체를 학습하는 비중이 크기 때문에 이미지·음성·텍스트처럼 사람이 모든 특징을 직접 정의하기 어려운 복잡한 데이터에서 특히 활용도가 높음
> <span color="gray">예시) 전통적인 이미지 분류에서는 사람이 모양·색·경계와 같은 특징을 설계해 모델에 제공할 수 있지만, 딥러닝에서는 많은 이미지와 목표를 이용해 어떤 시각적 특징이 분류에 중요한지 신경망 내부에서 단계적으로 학습하도록 할 수 있음</span>
딥러닝은 일반적으로 많은 데이터와 계산 자원이 필요하고, 모델이 복잡해질수록 내부 판단 과정을 사람이 직관적으로 설명하기 어려워질 수 있으므로 문제의 규모와 데이터의 형태에 따라 비교적 단순한 머신러닝 모델이 더 효율적이고 적절한 경우도 존재
---
## 2.3 머신러닝과 딥러닝의 관계
딥러닝은 머신러닝과 별개의 경쟁 기술이 아니라 머신러닝 안에 포함되는 대표적인 방법
- 전통적인 머신러닝에서는 사람이 어떤 특징을 사용할지 비교적 많이 정하는 경우가 있음
- 딥러닝에서는 여러 층을 거치며 데이터에서 유용한 특징 표현을 함께 학습하는 비중이 커짐
- 문제와 데이터의 복잡성이 높다고 무조건 딥러닝을 선택하는 것이 아니라 필요한 성능·데이터량·연산 비용·설명 가능성을 함께 고려
> <span color="gray">예시) 사진 속 고양이를 구분할 때 전통적인 방식은 색·윤곽·형태 같은 특징을 사람이 설계해 활용할 수 있고, 딥러닝은 많은 이미지에서 구분에 필요한 특징을 단계적으로 학습할 수 있음</span>
---
# 3. 데이터·알고리즘·모델과 AI 훈련 과정
## 3.1 데이터는 학습의 재료
AI 학습에서 데이터는 모델이 패턴을 찾는 사례의 모음
- 어떤 대상을 포함했는지에 따라 학습할 수 있는 범위가 달라짐
- 잘못된 값이나 치우친 사례가 많으면 결과에도 영향을 줄 수 있음
- <span color="gray">[참고] 데이터의 품질과 대표성을 분석하는 방법은 6주차에서 더 자세히 다룸</span>
---
## 3.2 알고리즘은 학습하는 방법
알고리즘은 데이터를 어떤 순서와 계산으로 처리하고, 모델이 현재 만든 결과의 오류를 어떻게 줄여 갈지 정하는 학습 절차를 말하며 데이터가 학습할 사례라면 알고리즘은 그 사례를 이용해 모델의 계산 기준을 어떤 방식으로 바꿀 것인지 정하는 방법에 해당. 같은 데이터를 가지고 있어도 어떤 학습 방법과 계산 기준을 사용하는지에 따라 모델이 만들어지는 과정과 결과가 달라질 수 있음
**프로세스의 반복**
1. 입력 데이터를 모델에 제공
2. 모델이 현재 기준으로 결과를 예측
3. 예측 결과와 실제 정답의 차이를 계산
4. 오류가 줄어드는 방향으로 모델 내부의 계산값을 조정
5. 여러 사례에 대해 이 과정을 반복
- 알고리즘은 사례에서 오류를 줄이는 방법 제공
- 반복 학습을 통해 모델 내부의 계산 기준이 변화
- 최종적으로 새로운 입력에도 적용할 수 있는 모델 형성
즉 알고리즘은 완성된 답을 직접 저장하는 규칙집이라기보다 데이터를 이용해 모델의 계산 기준을 개선해 가는 절차
---
## 3.3 모델은 학습 결과가 반영된 상태
모델은 학습을 통해 조정된 계산 구조와 내부 값이 반영되어, 이전에 보지 못한 새로운 입력에도 분류·예측·추천·생성 등의 결과를 만들 수 있게 된 상태로 학습 전에는 모델의 계산 기준이 충분히 조정되지 않았지만 데이터를 이용한 반복 학습을 거치면서 어떤 입력 특징을 어떻게 반영할지 내부 값이 변화. 이처럼 학습 결과가 실제 계산 구조에 반영된 것이 모델이며, 사용 단계에서는 새로운 입력을 받아 학습된 기준에 따라 결과를 생성
> <span color="gray">예시) 스팸 메일 모델의 경우 학습이 끝난 뒤 새로운 이메일이 들어오면 과거 메일 전체를 그대로 다시 검색해 같은 문장을 찾는 것이 아니라, 학습 과정에서 형성된 계산 기준을 이용해 현재 메일이 스팸에 가까운지 정상에 가까운지 판단</span>
**모델의 3가지 요소**
- **데이터**: 어떤 사례를 통해 배울 것인가
- **알고리즘**: 사례를 이용해 어떻게 학습할 것인가
- **모델**: 학습 결과가 반영되어 실제 입력을 처리하는 상태
1주차에서 살펴본 것처럼 여러 문제와 정답은 데이터, 틀린 이유를 확인하며 풀이 방식을 개선하는 과정은 알고리즘을 이용한 학습, 그 결과 새로운 문제를 스스로 풀 수 있게 된 상태는 모델에 해당. 여기서 새로운 문제를 푼다는 것은 이전 문제를 그대로 기억해 답을 복사하는 것이 아니라 학습한 풀이 기준을 새로운 문제에 적용한다는 의미
같은 목적의 모델이라도 사용한 데이터·학습 방법·설정이 다르면 서로 다른 결과를 만들 수 있음. 따라서 모델이라는 말은 AI 전체를 막연하게 가리키는 표현이라기보다 **특정 데이터와 학습 과정을 거쳐 실제 작업을 수행할 수 있도록 만들어진 계산 구조**로 이해하는 것이 적절
모델이 완성되었다고 학습 과정이 끝났다고 볼 수는 없음. 새로운 입력에서 학습한 기준이 제대로 적용되는지는 별도로 확인해야 하며, 이러한 학습 데이터와 새로운 데이터의 차이·검증·일반화는 다음 3.4에서 연결해 살펴봄
---
## 3.4 학습·검증과 새로운 데이터
### 3.4.1 학습 데이터
모델이 패턴을 배우고 내부 값을 조정할 때 사용하는 데이터
---
### 3.4.2 검증 데이터
학습 과정에서 모델의 설정과 성능을 점검할 때 사용하는 별도의 데이터
학습한 문제를 그대로 다시 풀어 높은 점수를 얻는 것만으로 실제 실력을 판단하기 어려운 것처럼, AI도 학습에 사용하지 않은 데이터에서 결과를 확인해야 새로운 상황에 적용할 수 있는지 판단할 수 있음
**시험·평가 데이터**는 학습과 모델 설정 조정이 끝난 뒤 최종 성능을 독립적으로 확인할 때 사용하는 데이터. 학습 데이터나 검증 데이터와 분리해 두면 모델을 만드는 과정에서 직접 활용하지 않은 사례를 기준으로 실제 성능을 더 객관적으로 확인할 수 있음
---
### 3.4.3 과적합과 일반화
과적합(Overfitting)은 학습 데이터의 세부 특징에 지나치게 맞춰져 새로운 데이터에서는 성능이 떨어지는 상태이며, 일반화(Generalization)는 학습하지 않은 새로운 데이터에도 배운 패턴을 적절하게 적용하는 능력
- 학습 성능만 높다고 좋은 모델이라고 판단하지 않음
- 실제 사용 환경과 비슷한 데이터에서 결과를 확인해야 함
- 환경이 바뀌면 기존 모델의 성능도 달라질 수 있음
> <span color="gray">예시) 특정 조명에서 촬영한 제품 사진만 학습한 불량 판정 AI가 다른 공장의 조명에서는 오류가 늘어난다면, 학습 데이터와 실제 사용 환경의 차이를 함께 살펴봐야 함</span>
---

# 4. 학습 과정을 사례로 연결해서 이해하기
## 4.1 스팸 메일 분류 모델을 만든다면
AI의 학습 과정을 가장 쉽게 이해하는 방법은 하나의 실제 문제를 처음부터 끝까지 따라가 보는 것임. 스팸 메일 분류를 예로 들면 목표는 새로운 메일이 들어왔을 때 스팸인지 정상 메일인지 구분하는 것
**① 문제 정의**
먼저 무엇을 맞히려는지 정함. 이 경우 결과는 스팸 / 정상 두 범주이며, 단순히 많은 메일을 모으는 것보다 어떤 메일을 스팸으로 볼지 기준을 정하는 일이 먼저임
**② 데이터 준비**
과거 메일을 모으고 각각 스팸인지 정상인지 표시함. 광고성 표현, 발신 주소, 링크 수, 제목 패턴 등 여러 특징이 데이터 안에 포함될 수 있음
**③ 학습**
모델이 각 메일을 보고 스팸인지 정상인지 예측하고 실제 정답과 비교함. 틀린 정도를 줄이는 방향으로 내부 계산값을 반복해서 조정하며 입력 특징과 정답 사이의 관계를 학습
**④ 모델 확인**
학습이 끝난 모델에 학습할 때 사용하지 않은 메일을 입력해 실제로 얼마나 잘 분류하는지 확인함. 학습 데이터와 새로운 데이터의 성능 차이가 크다면 3.4.3에서 살펴본 과적합 여부를 함께 확인해야 함
**⑤ 실제 사용과 재검토**
서비스 환경이 바뀌고 새로운 스팸 유형이 등장하면 이전 모델의 성능도 달라질 수 있음. 따라서 AI 모델은 한 번 만들면 끝나는 제품이라기보다 새로운 데이터와 환경 변화에 따라 성능을 다시 확인해야 하는 시스템으로 이해하는 것이 중요
---

## 4.3 같은 AI라도 학습 방식이 달라지는 이유
같은 데이터 기반 AI라도 모든 문제가 같은 학습 방식을 사용하지 않고 문제의 형태와 피드백 방식이 다르기 때문
**분류 문제**

## 4.4 AI가 잘 학습하려면 데이터가 많기만 하면 되는가
데이터의 양은 중요하지만 양만 많다고 좋은 모델이 만들어지는 것은 아님
- 데이터가 실제 사용 환경을 충분히 대표하는가
- 잘못된 값이나 라벨이 지나치게 많지 않은가
- 특정 집단이나 특정 상황만 과도하게 포함되지 않았는가
- 중요한 예외 상황이 포함되어 있는가
- 학습할 문제와 실제 사용할 문제의 조건이 같은가
> <span color="gray">예시) 낮에 촬영한 도로 사진만으로 학습한 모델은 밤이나 비 오는 날의 도로에서 성능이 낮아질 수 있음. 데이터 수가 수십만 장이어도 사용 환경의 다양성을 충분히 포함하지 못한다면 실제 성능이 제한될 수 있음</span>
---
## 4.5 2주차에서 꼭 구분해야 할 오해
**오해 1. AI가 학습하면 스스로 목표를 정한다**
- 학습은 사람이 정한 문제와 평가 기준 안에서 모델의 계산 기준이 조정되는 과정이며 목표 자체를 자유롭게 만드는 것과는 다름
**오해 2. 딥러닝은 머신러닝보다 별개의 완전히 다른 기술이다**
- 딥러닝은 머신러닝 안에 포함되는 대표적인 접근으로 이해하는 것이 적절
**오해 3. 모델이 학습 데이터를 잘 맞히면 좋은 모델이다**
- 중요한 것은 학습하지 않은 데이터와 실제 환경에서도 성능을 유지하는지 확인하는 것
**오해 4. 생성형 AI는 기존 AI와 완전히 단절된 기술이다**
- 생성형 AI는 머신러닝과 딥러닝 발전 흐름 위에서 새로운 콘텐츠 생성 기능이 크게 확장된 형태

	AI를 이해할 때는 데이터를 넣으면 답이 나온다는 단순한 그림보다, 문제 정의 → 데이터 준비 → 학습 → 검증 → 실제 사용 → 재평가의 순환 과정으로 보는 것이 중요함
</callout>

	**학습 요약**
	- AI 발전은 사람이 규칙을 직접 작성하던 방식에서 데이터로 패턴을 학습하는 방식으로 중심이 이동한 과정
	- 머신러닝은 데이터에서 패턴을 학습하고, 딥러닝은 다층 신경망을 이용하는 머신러닝의 한 분야
	- 지도학습·비지도학습·강화학습은 정답 정보와 피드백 방식에 따라 학습 목적이 다름
	- 데이터는 학습의 재료, 알고리즘은 학습 절차, 모델은 학습 결과가 반영된 계산 구조
	- 학습 데이터에서 잘 맞는 것보다 새로운 데이터에서도 성능을 유지하는 일반화가 중요
</callout>
