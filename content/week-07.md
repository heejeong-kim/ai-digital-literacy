# 1. 개인정보 보호와 사이버 보안
## 1.1 개인정보는 왜 보호해야 하는가
개인정보는 한 사람을 직접 알아볼 수 있거나 다른 정보와 결합했을 때 특정 개인을 식별할 수 있게 하는 정보
- 이름이나 전화번호처럼 바로 개인을 알아볼 수 있는 정보뿐 아니라 위치·검색·구매 기록처럼 여러 자료를 결합했을 때 개인을 추정하게 하는 정보도 포함
- 개인정보가 노출되면 스팸이나 사칭에 이용되는 데서 끝나지 않고 계정 탈취·금전 피해·평판 침해로 이어질 수 있으므로 수집 단계부터 보호가 필요함
- 이름·연락처
- 학번·사번·계정 식별자
- 위치정보
- 얼굴·지문 같은 생체정보
- 구매·검색·이용 기록
- 건강·재정·학습 기록
개인정보의 위험은 정보 한 조각만으로 결정되지 않음. 여러 정보가 결합되면 원래보다 개인을 더 쉽게 추정할 수 있으므로 무엇을 왜 수집하고 누구와 공유하는지가 중요
---
## 1.2 필요한 만큼만 사용하는 데이터 최소화
데이터 최소화(Data Minimization)는 목적을 달성하는 데 필요한 범위만 개인정보를 수집·사용하는 원칙
- 정보를 많이 모아 두는 것이 항상 유리한 것은 아니며, 필요하지 않은 정보까지 보유하면 유출되었을 때 피해 범위도 커짐
- 수집 전에는 이 정보가 왜 필요한지, 더 적은 정보로 같은 목적을 달성할 수 있는지, 언제 삭제할지를 함께 결정해야 함
> <span color="gray">예시) 행사 참여 확인에 이메일 주소만 필요하다면 주민등록번호나 상세 주소까지 받는 것은 목적에 비해 과도할 수 있음</span>
AI나 외부 서비스에 문서를 입력할 때도 같은 기준을 적용
- 목적과 관계없는 이름·연락처 제거
- 민감한 내부 정보가 포함되어 있는지 확인
- 서비스의 저장·이용 조건 확인
- 필요한 일부 정보만 입력할 수 있는지 검토
개인정보를 많이 모으면 분석에 도움이 될 수 있지만 동시에 유출·오남용·권한 관리의 위험도 커짐
---
## 1.3 계정 보안의 기본
계정 보안은 비밀번호 하나를 어렵게 만드는 것만이 아니라 로그인·인증·권한·복구 수단을 함께 관리하는 과정
- 계정이 탈취되면 저장된 개인정보뿐 아니라 연결된 다른 서비스와 공유 문서까지 영향을 받을 수 있음
- 비밀번호·다중요소인증·접근 권한은 서로 다른 위험을 줄이므로 하나만 사용하기보다 함께 적용하는 것이 중요
---
### 1.3.1 비밀번호
비밀번호는 계정에 접근할 수 있는 첫 번째 인증 정보로, 다른 사람이 쉽게 추측하거나 재사용하기 어렵도록 관리해야 함
- 긴 비밀번호나 여러 단어를 조합한 암호문은 짧고 복잡한 한 단어보다 기억하기 쉽고 추측하기 어렵게 만들 수 있음
- 서비스마다 서로 다른 비밀번호 사용
- 짧고 쉽게 추측되는 표현 피하기
- 비밀번호를 다른 사람과 공유하지 않기
- 비밀번호 관리 도구 활용 고려
같은 비밀번호를 여러 곳에서 재사용하면 한 서비스에서 유출된 정보가 다른 계정 공격으로 이어질 수 있음
---
### 1.3.2 다중요소인증(Multi-Factor Authentication)
다중요소인증은 서로 다른 종류의 인증 요소를 두 가지 이상 사용해 본인 여부를 확인하는 방식
- **알고 있는 것**: 비밀번호·PIN
- **가지고 있는 것**: 스마트폰·보안키·인증 앱
- **본인의 특성**: 지문·얼굴 등 생체정보
- 비밀번호와 문자 인증번호처럼 서로 다른 요소를 함께 사용하면 비밀번호가 노출되어도 추가 보호 단계가 남음
- 비밀번호를 두 번 입력하는 것은 단계가 두 번이어도 같은 종류의 요소만 사용하므로 엄밀한 의미의 다중요소인증은 아님
- 서비스에서 ‘2단계 인증’ 또는 ‘2단계 확인’이라고 표시할 수 있지만, 서로 다른 인증 요소를 사용하는 경우에 다중요소인증에 해당함
> <span color="gray">예시) 비밀번호를 입력한 뒤 본인 스마트폰의 인증 앱에서 로그인을 승인하는 방식은 알고 있는 것과 가지고 있는 것을 함께 사용한 다중요소인증</span>
---
### 1.3.3 접근 권한
접근 권한은 로그인한 사용자가 어떤 정보와 기능을 보고·수정하고·공유할 수 있는지 정하는 범위임
- 로그인에 성공했다는 사실과 모든 정보에 접근할 권한이 있다는 사실은 다름
- 필요한 사람에게 필요한 기간과 범위만 권한을 주면 계정 하나에 문제가 생겼을 때 노출되는 정보와 기능을 줄일 수 있음
- 필요한 사람에게 필요한 범위만 권한 부여
- 공유 링크가 누구에게 열려 있는지 확인
- 프로젝트 종료 후 불필요한 접근 권한 제거
- 공용 기기에서는 자동 로그인과 저장된 계정 정보 확인
---
## 1.4 피싱
피싱은 가짜 이메일·문자·웹사이트 등을 이용해 사용자가 로그인 정보·금전·민감정보를 스스로 제공하도록 속이는 공격임
- 공격자는 기술로 시스템을 직접 뚫기보다 실제 기관이나 지인을 흉내 내 사용자가 링크를 누르고 정보를 입력하게 유도
- 문장이 자연스럽고 로고가 정확해 보여도 안전하다는 뜻은 아니므로 발신 주소·연결 주소·요구 행동을 함께 확인해야 함
---
### 1.4.1 자주 나타나는 신호
- 계정이 곧 정지된다고 압박하는 과도한 긴급성
- 링크를 눌러 즉시 로그인하라는 요구
- 송금 계좌나 결제 정보를 갑자기 변경하라는 요청
- 실제 기관과 비슷하지만 다른 주소
- 첨부파일이나 프로그램 실행 요구
---
### 1.4.2 대응 방법
- 메시지 속 링크를 바로 누르지 않음
- 공식 앱이나 주소를 직접 입력해 상태 확인
- 발신자 이름보다 실제 주소 확인
- 송금·계정 변경 요청은 다른 연락 수단으로 재확인
- 의심 메시지를 다른 사람에게 그대로 전달하지 않음
> <span color="gray">예시) ‘학교 계정이 오늘 정지됩니다’라는 문자를 받았다면 문자 링크에서 로그인하기보다 학교 공식 사이트나 앱에 직접 접속해 공지를 확인하는 것이 안전함</span>
---
## 1.5 사람의 심리를 이용한 공격: 사회공학
사회공학(Social Engineering)은 시스템의 기술적 취약점을 직접 공격하기보다 긴급함·권위·호기심·친밀감 같은 사람의 심리를 이용해 정보나 권한을 얻는 공격 방식
- 앞에서 살펴본 피싱은 사회공학이 이메일·문자·가짜 웹사이트의 형태로 나타난 대표적인 사례
- 사회공학은 피싱 외에도 전화 사칭·대면 요청·메신저 사칭 등의 형태로 발생할 수 있음
- 사람을 평소보다 빠르게 행동하게 만드는 감정을 이용하므로 요청 내용이 그럴듯한지보다 정상 절차를 따르고 있는지 먼저 확인해야 함
- **긴급성**: 지금 하지 않으면 문제가 생긴다고 압박
- **권위**: 상사·기관·교수 등을 사칭
- **호기심**: 확인하고 싶은 사진·파일로 유도
- **보상**: 당첨·환급·무료 혜택을 강조
- **친밀감**: 지인 계정을 이용해 자연스럽게 접근
핵심은 메시지가 그럴듯한지보다 **평소 절차를 우회하거나 예상하지 못한 행동을 요구하는가**를 확인하는 것
---
## 1.6 악성코드와 랜섬웨어
악성코드(Malware)는 시스템이나 정보를 손상·탈취·통제하기 위해 만들어진 프로그램의 총칭이며, 랜섬웨어(Ransomware)는 파일이나 시스템을 사용할 수 없게 만든 뒤 금전을 요구하는 대표적인 형태
- 악성코드는 첨부파일·위장 프로그램·취약한 웹사이트 등을 통해 들어올 수 있으며 감염 사실이 바로 드러나지 않을 수도 있음
- 예방은 실행 전 출처 확인과 업데이트에서 시작하고, 사고 후 복구를 위해 중요한 파일을 별도로 백업해야 함
기본 예방 행동
- 운영체제와 프로그램 업데이트
- 출처가 불분명한 첨부파일 실행 주의
- 불필요한 프로그램 설치 제한
- 중요한 파일 별도 백업
- 계정과 기기의 접근 권한 최소화
백업은 사고가 난 뒤 처음 생각하는 것이 아니라 사고 전에 준비하는 복구 수단이며, 실제로 복원할 수 있는지 확인하는 과정도 필요함
---
# 2. 저작권과 디지털 인권
## 2.1 저작권
저작권은 창작자가 자신의 창작물을 이용할 수 있는 권리와 다른 사람이 사용할 때 지켜야 할 조건을 정하는 제도임
- 직접 만든 글·사진·음악·영상·프로그램은 디지털 형태로 공개되어도 창작물로서 보호될 수 있음
- 자료를 볼 수 있다는 것과 복사·수정·배포할 수 있다는 것은 다르므로 사용 전에 허용 범위를 확인해야 함
- 글
- 사진
- 그림
- 음악
- 영상
- 프로그램 코드 등
인터넷에 공개되어 있다는 사실은 저작권이 없다는 의미가 아님. 공개적으로 볼 수 있는 것과 자유롭게 복사·수정·재배포할 수 있는 것은 구분해야 함
---
## 2.2 라이선스
라이선스는 저작물을 어떤 조건으로 사용할 수 있는지 정한 이용 허락
- 저작권자가 모든 이용을 개별적으로 허락하는 대신 사용 가능한 범위와 지켜야 할 조건을 미리 표시한 것
- 같은 무료 자료라도 출처 표시·수정·상업적 이용·재배포 조건이 다를 수 있으므로 자료마다 실제 라이선스를 확인해야 함
자료를 사용할 때 확인할 항목
- 상업적 이용이 가능한가
- 수정이 가능한가
- 출처를 표시해야 하는가
- 같은 조건으로 다시 배포해야 하는가
- 사용 범위나 기간에 제한이 있는가
> <span color="gray">예시) 무료 이미지 사이트의 사진도 서비스마다 이용 조건이 다를 수 있으므로 무료라는 표시만 보고 사용하는 대신 실제 라이선스를 확인해야 함</span>
---
## 2.3 디지털 인권
디지털 인권(Digital Rights)은 온라인과 디지털 기술 환경에서도 개인의 존엄·사생활·표현·접근·차별받지 않을 권리 등이 존중되어야 한다는 관점
- 기술이 편리하더라도 개인을 과도하게 감시하거나 특정 집단을 서비스에서 배제한다면 권리 문제가 발생할 수 있음
- 게시·공유·추천·자동화 과정에서 누구의 정보와 선택이 영향을 받는지 살펴보는 것이 디지털 인권을 판단하는 출발점
일상적인 디지털 활동에서도 다음을 고려할 수 있음
- 상대방의 동의 없이 개인 대화를 공개하지 않기
- 사진과 영상을 공유하기 전에 당사자의 의사를 고려하기
- 특정 집단을 모욕하거나 차별하는 표현 피하기
- 개인을 과도하게 추적하거나 감시하는 방식의 위험 인식
- 디지털 서비스 이용에서 소외되는 사람이 없는지 고려

# 3. 온라인 명예훼손과 책임 있는 행동
## 3.1 온라인 평판은 빠르게 확산될 수 있음
온라인 평판은 게시물·댓글·사진·영상 등을 통해 다른 사람이 특정 개인이나 조직을 평가하는 데 영향을 주는 정보
- 온라인 게시물은 복사·캡처·재공유가 쉬워 원래 의도보다 넓게 퍼질 수 있음
- 원문을 삭제해도 복사본과 검색 기록이 남을 수 있으므로 공개하기 전에 대상·표현·범위를 확인해야 함
특정 사람에 대한 부정적인 내용을 올릴 때는 사실 여부뿐 아니라 공개 범위·표현 방식·개인의 권리에 미치는 영향을 함께 생각해야 함
---
## 3.2 명예훼손과 온라인 행동
온라인 명예훼손은 게시물·댓글·영상·메시지 등으로 특정 사람의 사회적 평가를 훼손할 수 있는 내용을 퍼뜨리는 문제와 연결됨
- 공유한 사람이 사실이라고 믿었다고 해서 책임이 사라지는 것은 아니므로 공개 전 근거와 필요성을 확인해야 함
- 수업에서는 구체적인 법률 결론보다 피해를 줄이기 위한 확인·표현·수정 행동에 초점을 둠
따라서 다음과 같은 행동 기준을 적용함
- 확인되지 않은 내용을 사실처럼 단정하지 않기
- 개인의 실명·사진·연락처를 불필요하게 공개하지 않기
- 비판할 때 사람 자체보다 행동·주장·근거를 중심으로 표현
- 감정적인 상황에서 즉시 공개 게시하지 않기
- 잘못된 정보를 올렸다면 수정·삭제·정정하기
---

## 3.4 문제가 발생했을 때의 기본 대응
보안 사고가 의심될 때는 원인을 완전히 알아낼 때까지 기다리기보다 피해가 더 커지지 않도록 추가 행동을 멈추고 공식 지원 채널에 알리는 것이 우선임
- 혼자 해결하려고 메시지와 파일을 반복해서 열면 피해가 확대되거나 필요한 기록이 사라질 수 있음
- 대응은 중지 → 차단 → 신고 → 기록 → 재발 방지의 순서로 진행함
**① 추가 행동을 멈춤**
- 의심 링크나 파일을 더 열지 않음
**② 피해 범위를 줄임**
- 필요한 경우 비밀번호 변경·계정 로그아웃·기기 네트워크 분리
**③ 담당자에게 알림**
- 학교·회사·서비스의 공식 보안 또는 지원 채널 이용
**④ 기록을 남김**
- 메시지·시간·화면·발신 정보 등 필요한 증거 보존
**⑤ 다시 같은 일이 발생하지 않도록 원인을 점검**
- 계정 보안·공유 권한·백업·사용 습관 개선
<callout icon="💡" color="blue_bg">
	사이버 보안과 프라이버시는 특별한 전문가만의 문제가 아니라 링크를 누르고, 파일을 공유하고, AI에 자료를 입력하고, 온라인에 글을 올리는 일상적인 선택에서 시작됨
</callout>

## 4.3 사고 전 예방 조치
사고가 발생하기 전이었다면 다음 기준으로 프로젝트 환경을 구성함
1. **데이터 최소화**: 행사 운영에 학번이 필요하지 않다면 수집하지 않고, 안내 발송이 끝난 연락처는 정해진 기준에 따라 삭제
2. **분리 저장**: 이름·연락처가 포함된 신청 명단과 참석 인원 집계 자료를 서로 다른 파일로 분리해 관리
3. **접근 권한 최소화**: 팀원 계정만 열람하도록 설정하고 필요한 사람에게만 편집 권한 부여
4. **계정 보호**: 서비스마다 다른 비밀번호를 사용하고 다중요소인증과 로그인 알림 활성화
5. **외부 서비스 확인**: AI 서비스에 입력하기 전에 개인정보를 제거하고 저장·이용·삭제 조건과 학교 지침 확인
6. **콘텐츠 권리 확인**: 이미지와 자료의 원출처·라이선스·인용 범위를 기록
7. **백업**: 참가 신청 명단과 행사 운영 문서를 분리된 위치에 백업하고 복원 가능 여부 확인
> <span color="gray">예시) 참석 인원 집계에는 시간대와 참석 여부만 사용하고, 이름·이메일이 포함된 신청 명단은 제한된 담당자만 접근하도록 설정함</span>

## 4.4 피싱 의심 사고 대응
팀원이 의심 링크에서 계정 정보를 이미 입력했다면 메시지의 진위를 오래 조사하기보다 피해 확산을 막는 행동을 먼저 수행
1. **추가 행동 중지**: 링크를 다시 열거나 추가 인증번호·파일을 전달하지 않음
2. **공식 경로 접속**: 이메일 링크가 아닌 학교 공식 사이트나 앱으로 직접 이동
3. **계정 보호**: 비밀번호를 변경하고 로그인된 다른 기기와 세션을 종료
4. **추가 인증 확인**: 다중요소인증과 복구 이메일·전화번호가 변경되지 않았는지 확인
5. **접근 권한 점검**: 공유 폴더와 연결된 서비스에 알 수 없는 사용자·앱·권한이 추가되지 않았는지 확인
6. **공식 채널 신고**: 학교 보안 담당 부서나 서비스 지원 채널에 상황을 알림
7. **기록 보존**: 이메일·발신 주소·접속 시간·변경 내역을 삭제하지 않고 보관
8. **기기 확인**: 파일을 실행했다면 네트워크 연결을 제한하고 공식 절차에 따라 악성코드 검사를 요청
계정 복구 후에는 참가 신청 명단과 운영 문서가 열람·다운로드·변경되었는지 확인하고 개인정보 노출 가능성이 있다면 조직의 정해진 절차에 따라 담당자에게 보고
---
## 4.5 저작권과 디지털 인권 점검
보안 사고를 해결해도 행사 홍보자료와 참가자 권리에 대한 검토는 별도로 필요함
**인터넷 이미지**
- 검색 결과가 아니라 실제 원본 페이지에서 작성자와 라이선스 확인
- 수정·재배포·행사 홍보 사용이 허용되는지 확인
- 요구되는 방식으로 출처 표시
- 조건을 확인할 수 없다면 직접 제작하거나 이용 조건이 명확한 자료로 교체
**참가자 후기**
- 이름·학번·연락처와 특정인을 추정할 수 있는 정보 제거
- 공개에 필요한 동의와 사용 범위 확인
- 원문을 자극적으로 편집해 의미를 바꾸지 않음
- 개인의 평판을 해칠 가능성이 있다면 공개 필요성과 표현 방식을 다시 검토
**외부 AI 서비스 이용**
- 행사 안내문 작성에 필요하지 않은 참가자 정보를 입력하지 않음
- 입력 자료와 생성 결과의 이용 조건을 확인
- 참가자 후기나 개인 정보를 AI 입력 자료로 사용하기 전에 권한과 필요성을 확인

- 메시지의 링크 대신 공식 주소로 직접 접속
- 참가 신청 명단을 외부 서비스에 그대로 입력하지 않음
- 공유 폴더는 팀원만 접근하도록 설정

- 사고가 의심되면 숨기지 않고 즉시 공식 채널에 알림
- 개인정보·출처·라이선스를 공개 전 최종 확인
