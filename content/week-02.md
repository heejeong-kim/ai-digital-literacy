# 1️⃣ 1교시 \| AI 발전의 흐름과 머신러닝의 기본 구조

## 1. 인공지능 발전의 흐름

AI의 발전은 하나의 기술이 직선적으로 좋아진 과정이 아니라 **문제를 표현하는 방식·데이터의 규모·컴퓨팅 성능·알고리즘·사용자 인터페이스가 함께 변화한 과정**

### 1.1 튜링 테스트(Turing Test)와 초기 AI 질문

1950년 앨런 튜링이 제안한 사고실험에서 출발한 대표적 질문은 **기계가 인간과 구분하기 어려운 수준으로 대화할 수 있는가**에 대한 문제

- **핵심 질문**: 기계 내부가 사람과 같은지보다 외부에서 관찰되는 행동이 얼마나 지능적으로 보이는지에 초점
- **의미**: 인공지능을 철학적 개념에 머물지 않고 관찰 가능한 과제로 논의하게 만든 계기
- **한계**: 인간처럼 대화하는 능력만으로 지능 전체를 평가하기 어려움
- **현재 연결**: 대화형 생성형 AI의 등장으로 자연어 상호작용이 다시 중요한 평가 경험으로 부각
- **이해 포인트**: 현재 AI 성능평가 지표라기보다 초기 AI 연구가 던진 대표적인 문제의식

---

### 1.2 초기 AI와 규칙 중심 접근

초기 AI는 사람이 문제 해결 규칙을 직접 작성하고 컴퓨터가 그 규칙을 실행하는 방식이 중심

- **핵심 구조**: 사람이 지식과 규칙을 정의 → 시스템이 조건에 따라 결과 산출
- **대표 형태**: `조건 A와 조건 B가 모두 맞으면 결과 C`와 같은 명시적 규칙
- **장점**: 판단 근거가 비교적 명확하고 규칙이 고정된 문제에서 결과 설명이 쉬움
- **한계**: 예외가 많아질수록 규칙 수가 급격히 증가하고 서로 충돌하는 규칙 관리가 어려움
- **예시**: 특정 기준을 만족하면 경고를 표시하는 진단·업무 규칙 시스템
- **이해 포인트**: 시스템이 규칙을 스스로 발견하는 것이 아니라 사람이 작성한 규칙을 정확하게 실행하는 구조

---

### 1.3 전문가 시스템(Expert System)

특정 분야 전문가의 지식을 지식베이스에 저장하고 추론 규칙을 이용해 판단을 지원하는 초기 AI 방식

- **구성**: 전문가 지식 → 지식베이스 → 추론 규칙 → 판단 또는 추천
- **활용**: 질병 진단 보조, 장비 점검, 세무·금융 규칙 확인, 업무 의사결정 지원
- **강점**: 특정 분야의 명시적 전문지식을 체계화해 반복 활용 가능
- **한계**: 전문가가 말로 설명하기 어려운 암묵적 지식과 복잡한 예외를 모두 규칙으로 표현하기 어려움
- **운영 문제**: 환경 변화 시 지식베이스와 규칙을 사람이 계속 갱신해야 하는 부담
- **이해 포인트**: 지식을 자동으로 학습하기보다 사람이 정리한 전문지식을 계산 가능한 형태로 구조화한 시스템

---

### 1.4 머신러닝(Machine Learning)으로의 전환

사람이 모든 판단 규칙을 직접 작성하는 대신 **데이터에서 반복되는 패턴을 학습해 모델을 만드는 접근**으로 중심이 이동

- **기본 흐름**: 문제 정의 → 데이터 수집 → 특징 구성 → 학습 → 모델 → 새로운 입력 → 예측
- **예시**: 정상·스팸 이메일 사례를 학습해 새로운 이메일을 자동 분류
- **변화 1**: 규칙을 사람이 직접 모두 작성하는 방식에서 데이터가 규칙 형성에 중요한 역할을 하는 방식으로 이동
- **변화 2**: 시스템 개발의 핵심이 규칙 작성뿐 아니라 데이터 수집·라벨링·평가 설계로 확대
- **사람의 역할**: 해결할 문제, 사용할 데이터, 정답 기준, 중요한 오류, 평가 방법 설계
- **주의점**: 데이터에 존재하는 오류나 편향도 함께 학습할 가능성
- **이해 포인트**: 사람이 사라지는 자동 학습이 아니라 사람이 학습 조건과 기준을 설계하고 모델이 데이터에서 패턴을 찾는 구조

---

### 1.5 딥러닝(Deep Learning)의 확산

여러 층의 인공신경망을 이용해 복잡한 표현을 학습하는 머신러닝의 한 분야

- **확산 배경**: 디지털 데이터 증가, GPU 등 연산 성능 향상, 학습 알고리즘 개선, 클라우드·분산학습 확대
- **강점**: 이미지·음성·텍스트처럼 사람이 중요한 특징을 일일이 정의하기 어려운 데이터에서 유용한 표현을 자동 학습
- **대표 활용**: 이미지 분류, 음성 인식, 기계 번역, 자연어 처리
- **머신러닝과 관계**: 딥러닝은 머신러닝과 별개의 기술이 아니라 머신러닝 안에 포함되는 대표적 접근
- **한계**: 많은 데이터와 연산 자원이 필요할 수 있고 내부 판단 과정을 해석하기 어려운 경우 존재
- **선택 기준**: 데이터가 적고 규칙이 명확하거나 설명 가능성이 중요한 문제에서는 단순한 모델이 더 적절할 수 있음
- **이해 포인트**: 모든 문제의 정답이 아니라 대규모·복잡한 데이터의 표현 학습에 강점을 가진 방법

---

### 1.6 생성형 AI(Generative AI)의 대중화

딥러닝의 발전을 바탕으로 텍스트·이미지·음성·영상·코드 등 새로운 콘텐츠를 생성하는 AI가 일반 사용자에게 빠르게 확산된 단계

- **기술적 배경**: 대규모 데이터, 대형 딥러닝 모델, 고성능 연산 자원, 대규모 사전학습의 결합
- **활용 변화**: 분류·예측 중심에서 글쓰기·요약·대화·이미지 제작·코드 작성·멀티미디어 제작까지 확대
- **사용 방식 변화**: 전문 개발자 중심 활용에서 자연어로 요청하고 결과를 검토하는 일반 사용자 중심 활용으로 범위 확대
- **대표 사례**: 대규모 언어 모델 기반 챗봇, 이미지 생성 AI, 코드 생성 도구, 음성·영상 생성 도구
- **연결 관계**: 생성형 AI도 머신러닝과 딥러닝 발전 흐름 위에 존재하는 AI 활용 형태
- **주의점**: 자연스러운 생성 결과가 사실 정확성이나 안전성을 자동으로 보장하는 것은 아님
- **주차 구분**: 2주차에서는 역사적 전환점과 학습 구조 중심, 토큰·맥락 창·확률적 생성·환각은 10주차에서 심화
- **이해 포인트**: **규칙 기반 → 데이터 기반 머신러닝 → 딥러닝 → 생성형 AI**로 이어지며 AI가 다루는 문제와 인간이 AI를 사용하는 방식 모두 변화

## 2. 대표 학습 방식

머신러닝의 학습 방식은 더 고급인 방법을 선택하는 문제가 아니라 **정답 데이터의 존재 여부·학습 목표·피드백 방식**에 따라 구분

### 2.1 지도학습(Supervised Learning)

입력과 정답이 함께 주어지고 둘의 관계를 학습하는 방식

- **입력과 정답**: 고객 정보와 이탈 여부, 주택 정보와 실제 가격처럼 학습 데이터에 목표 값 포함
- **주요 목적**: 분류와 회귀
- **분류 예시**: 스팸/정상, 불량/정상, 이탈/유지
- **회귀 예시**: 가격, 매출액, 수요량, 도착시간 예측
- **장점**: 목표와 정답이 명확해 모델 성능을 측정하기 쉬운 편
- **한계**: 많은 정답 라벨을 만드는 데 비용과 시간이 필요할 수 있음
- **주의점**: 사람의 과거 판단을 라벨로 사용할 경우 기존 오류나 편향이 정답처럼 학습될 가능성
- **이해 포인트**: 데이터 양뿐 아니라 **정답 기준이 실제 해결하려는 문제를 제대로 나타내는지** 여부가 중요

---

### 2.2 비지도학습(Unsupervised Learning)

정답 라벨 없이 데이터 안의 구조·유사성·차이를 탐색하는 방식

- **주요 목적**: 군집화, 이상 탐지, 차원 축소, 데이터 구조 탐색
- **예시**: 구매 패턴이 비슷한 고객을 여러 집단으로 묶어 고객 유형 탐색
- **활용**: 사전에 정답을 정의하기 어려운 탐색적 분석, 데이터 구조 이해, 후속 분석 후보 발견
- **장점**: 정답 라벨이 없는 대규모 데이터에서도 패턴 탐색 가능
- **한계**: 발견된 집단이나 패턴이 실제 업무에서 의미 있는 구분인지 자동으로 보장되지 않음
- **사람의 역할**: 만들어진 군집의 특성을 해석하고 실제 목적에 사용할 가치가 있는지 판단
- **이해 포인트**: 결과는 정답이라기보다 **데이터를 이해하기 위한 구조적 단서**에 가까움

---

### 2.3 강화학습(Reinforcement Learning)

환경과 상호작용하면서 행동 결과로 보상을 받고 장기적으로 더 큰 보상을 얻는 전략을 학습하는 방식

- **기본 구성**: 상태 → 행동 → 결과 → 보상 → 전략 수정
- **예시**: 게임에서 여러 행동을 반복하며 장기 점수가 높은 전략 학습
- **활용**: 게임, 로봇 제어, 자원 배분, 순차적 의사결정 문제
- **특징**: 각 입력마다 정답을 직접 제공하기보다 행동 결과에 대한 보상으로 학습
- **핵심 설계**: 어떤 행동을 좋은 행동으로 볼지 결정하는 보상 기준
- **위험**: 잘못 설계한 보상을 극대화하는 과정에서 사람이 의도하지 않은 행동을 학습할 가능성
- **이해 포인트**: 단순 반복이 아니라 **행동과 결과의 연결을 통해 전략을 개선하는 학습 방식**

---

### 2.4 자기지도학습(Self-Supervised Learning)

데이터 자체에서 학습 목표를 만들어 별도의 사람 라벨을 최소화하면서 표현을 학습하는 방식

- **예시 개념**: 문장의 일부를 가리고 맞히기, 앞 문맥을 보고 다음 표현 예측
- **장점**: 사람이 모든 데이터에 정답을 붙이지 않아도 대규모 데이터 활용 가능
- **생성형 AI 연결**: 대규모 언어 모델의 사전학습에서도 데이터 자체의 구조를 이용한 학습 방식 활용
- **주의점**: 자기지도학습을 사용한다고 데이터 품질·편향 문제가 사라지는 것은 아님
- **주차 구분**: 여기서는 지도·비지도·강화학습과의 차이를 이해하고 구체적인 언어 모델 학습 구조는 10주차에서 심화
- **이해 포인트**: 현대 AI의 대규모 학습에서는 사람이 직접 붙인 라벨만이 유일한 학습 신호가 아님

## 3. 머신러닝의 기본 구조

대표 학습 방식을 이해한 뒤에는 **문제 정의 → 데이터 준비 → 입력과 목표 설정 → 알고리즘 선택 → 모델 학습 → 결과 평가**의 구조로 연결해서 이해하는 것이 핵심

### 3.1 문제 정의와 문제 유형

머신러닝의 시작점은 모델을 먼저 선택하는 것이 아니라 해결하려는 문제와 원하는 출력 형태를 정하는 것

- **문제 정의 질문**: 무엇을 예측·분류·탐색하려는가
- **사용 시점 질문**: 결과를 언제, 누가, 어떤 의사결정에 사용할 것인가
- **분류(Classification)**: 스팸/정상, 이탈/유지처럼 정해진 범주 예측
- **회귀(Regression)**: 가격, 매출액, 수요량처럼 연속적인 숫자 예측
- **군집(Clustering)**: 정답 없이 비슷한 대상을 묶어 구조 탐색
- **중요성**: 문제 유형이 잘못 정의되면 모델 성능이 높아도 실제 업무 목적과 연결되지 않을 가능성
- **이해 포인트**: AI 개발의 출발점은 알고리즘이 아니라 **문제와 출력 형태의 정의**

---

### 3.2 특징(Feature)

모델이 판단에 사용하는 입력 정보

- **예시**: 고객 이탈 예측에서 가입 기간, 최근 접속일, 이용 횟수, 문의 횟수
- **좋은 특징**: 실제 예측 시점에 사용할 수 있고 문제와 관련성이 높은 정보
- **나쁜 특징**: 결과가 발생한 뒤에만 알 수 있는 미래 정보, 오류가 많은 값, 목적과 무관한 정보
- **특징 공학**: 원시 기록에서 평균 구매금액, 최근 방문 이후 경과일처럼 학습에 유용한 변수 생성
- **딥러닝 연결**: 특징을 자동으로 학습하는 비중이 커져도 어떤 데이터를 입력할지 결정하는 일은 여전히 중요
- **이해 포인트**: 모델의 성능은 알고리즘뿐 아니라 어떤 정보를 입력으로 주는지에 크게 영향

---

### 3.3 라벨(Label)

지도학습에서 모델이 맞혀야 하는 정답 또는 목표 값

- **분류 라벨**: 스팸/정상, 이탈/유지, 불량/정상
- **회귀 라벨**: 실제 가격, 실제 판매량, 실제 소요시간
- **라벨 품질**: 잘못된 정답이 많으면 모델이 잘못된 패턴을 학습할 가능성
- **편향 위험**: 과거 사람의 판단을 그대로 라벨로 사용할 경우 기존 편향이 정답처럼 고정될 가능성
- **이해 포인트**: 라벨은 단순한 정답표가 아니라 모델이 무엇을 좋은 예측으로 볼지 결정하는 기준

---

### 3.4 알고리즘(Algorithm)

데이터를 어떤 방식으로 처리하고 모델 내부 값을 조정할지 정하는 계산 절차

- **역할**: 입력·정답·손실 정보를 이용해 패턴 학습
- **선택 기준**: 문제 유형, 데이터 규모, 설명 가능성, 계산 비용, 필요한 성능
- **비교**: 같은 데이터를 사용해도 알고리즘에 따라 학습 속도와 결과 특성 차이
- **주의점**: 복잡한 알고리즘이 항상 더 좋은 결과를 보장하는 것은 아님
- **이해 포인트**: 알고리즘은 정답을 저장한 규칙표가 아니라 **모델을 학습시키는 방법**

---

### 3.5 모델(Model)

데이터와 알고리즘을 통해 학습된 패턴을 보유하고 새로운 입력에 결과를 만드는 계산 구조

- **학습 전**: 데이터 패턴을 충분히 반영하지 못한 초기 상태
- **학습 중**: 손실을 줄이는 방향으로 내부 값 조정
- **학습 후**: 새로운 입력을 받아 예측·분류·점수 결과 제공
- **예시**: 스팸 분류 모델, 수요 예측 모델, 고객 이탈 예측 모델
- **이해 포인트**: 모델은 데이터 자체도 알고리즘 자체도 아닌 **학습의 결과물**

---

### 3.6 손실함수(Loss Function)와 학습

모델의 예측과 실제 정답 사이의 차이를 수치로 표현해 학습 방향을 제공하는 기준

- **역할**: 현재 모델이 얼마나 틀렸는지 계산
- **학습 연결**: 손실이 줄어드는 방향으로 모델 내부 값 반복 조정
- **주의점**: 손실이 낮다고 실제 업무 목표가 자동으로 달성되는 것은 아님
- **예시**: 가격 예측 오차를 줄이거나 분류 오류를 줄이는 방향으로 학습
- **이해 포인트**: 모델 학습은 무작정 정답을 외우는 것이 아니라 **정의된 손실을 줄이는 반복적 최적화 과정**

---

### 3.7 학습과 추론(Inference)의 차이

학습은 모델을 만드는 과정이고 추론은 학습된 모델을 실제 입력에 사용하는 과정

- **학습**: 과거 데이터와 정답을 이용해 모델 내부 값 조정
- **추론**: 처음 보는 입력을 학습된 모델에 넣어 결과 생성
- **예시**: 과거 고객 데이터로 이탈 모델 학습 → 오늘 고객 정보를 넣어 이탈 가능성 예측
- **운영 요소**: 속도, 비용, 입력 데이터 품질, 모델 버전 관리
- **주의점**: 실제 운영 데이터가 학습 데이터와 크게 달라지면 추론 성능 저하 가능
- **이해 포인트**: 사용자가 보는 AI 결과 대부분은 이미 학습된 모델의 추론 결과

## 4. 데이터·알고리즘·모델의 관계

1주차에서 소개한 세 요소를 2주차에서는 실제 학습 구조 안에서 연결해 이해하는 것이 핵심

### 4.1 데이터의 역할

모델이 학습할 사례와 패턴을 제공하는 재료

- **좋은 데이터**: 실제 사용 환경을 적절히 대표하고 오류·누락이 적은 데이터
- **나쁜 데이터**: 특정 집단만 과도하게 포함되거나 오래된 상황만 반영한 데이터
- **영향**: 같은 알고리즘도 데이터가 달라지면 전혀 다른 결과의 모델 생성 가능
- **이해 포인트**: 데이터는 모델이 학습하는 현실의 표본

---

### 4.2 알고리즘의 역할

데이터를 어떤 방식으로 처리하고 패턴을 학습할지 정하는 계산 절차

- **역할**: 데이터와 손실 정보를 이용해 모델 내부 값 조정
- **비교**: 같은 데이터를 사용하더라도 알고리즘 선택에 따라 성능·설명가능성·계산 비용 차이
- **이해 포인트**: 알고리즘은 정답을 저장한 규칙표가 아니라 학습을 수행하는 절차

---

### 4.3 모델의 역할

데이터와 알고리즘을 통해 학습된 패턴을 보유하고 새로운 입력에 결과를 만드는 결과물

- **학습 전**: 아직 데이터 패턴을 충분히 반영하지 못한 초기 상태
- **학습 후**: 입력에서 출력으로 연결되는 내부 값이 조정된 상태
- **운영**: 새로운 데이터에 예측·분류·점수 결과 제공
- **이해 포인트**: 모델은 데이터 자체도 알고리즘 자체도 아닌 **학습을 통해 만들어진 계산 구조**

---

### 4.4 스팸메일 분류로 연결하기

- **문제**: 새 이메일이 스팸인지 정상인지 분류
- **데이터**: 과거 이메일과 스팸/정상 라벨
- **특징**: 단어·표현·발신 정보 등 입력 정보
- **알고리즘**: 데이터에서 분류 패턴을 학습하는 절차
- **모델**: 학습 결과 생성된 스팸 분류기
- **새 입력**: 처음 보는 이메일
- **추론 결과**: 스팸 가능성 점수 또는 스팸/정상 분류
- **검증**: 실제 정답과 비교해 성능 평가
- **핵심 연결**: **데이터는 학습 재료, 알고리즘은 학습 방법, 모델은 학습 결과, 추론은 모델 사용 과정**

# 2️⃣ 2교시 \| 모델 훈련·검증과 성능 평가

## 1. 모델 훈련·검증의 전체 흐름

2교시는 1교시에서 구성한 머신러닝 구조가 실제로 **학습 → 점검 → 조정 → 최종 평가 → 운영 확인**으로 이어지는 과정을 다루는 흐름

### 1.1 전체 과정

모델 개발은 데이터를 한 번 학습시키고 정확도 하나를 확인하는 과정이 아니라 여러 단계를 분리해 성능과 일반화 가능성을 점검하는 과정

- **1단계 문제 정의**: 무엇을 예측하고 어떤 오류를 중요하게 볼지 결정
- **2단계 데이터 준비**: 실제 사용 환경을 대표하는 데이터 수집·정제
- **3단계 데이터 분할**: 학습·검증·시험 데이터 역할 분리
- **4단계 모델 학습**: 학습 데이터로 손실을 줄이는 방향으로 모델 조정
- **5단계 검증·조정**: 검증 데이터로 모델 구조와 설정 비교
- **6단계 최종 시험**: 선택이 끝난 모델을 시험 데이터로 최종 평가
- **7단계 운영 확인**: 배포 이후 실제 사용자 데이터에서 성능 변화 관찰
- **이해 포인트**: 학습 데이터의 높은 성능이 목표가 아니라 새로운 상황에서도 안정적으로 작동하는 모델 확보가 목표

## 2. 데이터 분할과 역할

데이터 분할은 모델이 **공부한 문제와 시험 문제를 구분**해 새로운 데이터에서의 성능을 확인하기 위한 기본 장치

### 2.1 학습 데이터(Training Data)

모델이 패턴을 실제로 배우는 데 사용하는 데이터

- **역할**: 모델 내부 값 조정
- **특징**: 전체 데이터 중 가장 큰 비중을 차지하는 경우가 많음
- **주의점**: 학습 데이터 성능만 높다고 좋은 모델로 판단할 수 없음
- **이해 포인트**: 학습 데이터는 교재와 연습문제에 가까운 역할

---

### 2.2 검증 데이터(Validation Data)

모델 구조와 설정을 비교하고 학습을 언제 멈출지 판단하는 데이터

- **역할**: 여러 모델 후보 비교, 하이퍼파라미터 조정, 과적합 확인
- **주의점**: 검증 데이터를 반복해서 사용하면 검증 데이터에 맞춰 과도하게 조정될 가능성
- **이해 포인트**: 개발 과정 중간의 모의시험에 가까운 역할

---

### 2.3 시험 데이터(Test Data)

모델 선택과 설정 조정이 끝난 뒤 최종 성능을 확인하는 데이터

- **원칙**: 학습과 설정 조정 과정에서 반복적으로 보지 않는 것이 중요
- **위험**: 시험 결과를 보고 다시 모델을 반복 수정하면 시험 데이터가 검증 데이터처럼 사용될 가능성
- **운영 연결**: 시험 데이터도 실제 배포 환경과 완전히 같은 분포를 보장하지 않으므로 운영 이후 모니터링 필요
- **이해 포인트**: 시험 데이터는 최종 실전평가에 가까운 역할

---

### 2.4 데이터 분할 시 지켜야 할 원칙

단순히 임의로 세 파일로 나누는 것보다 데이터 특성과 실제 사용 상황을 고려한 분할이 중요

- **중복 방지**: 같은 사람·같은 문서·같은 사건의 거의 동일한 데이터가 학습과 시험에 동시에 들어가지 않도록 관리
- **시간 순서**: 미래 예측 문제라면 과거 데이터로 학습하고 이후 시점 데이터로 평가하는 방식 고려
- **집단 분리**: 같은 환자나 동일 사용자의 여러 기록이 학습과 시험에 동시에 포함되면 성능 과장 가능
- **대표성**: 시험 데이터가 실제 사용 환경의 주요 집단과 상황을 포함하는지 확인
- **이해 포인트**: 데이터 분할 방법 자체가 평가 결과의 신뢰도에 직접 영향

## 3. 모델 학습과 설정 조정

### 3.1 파라미터(Parameter)

학습 과정에서 데이터에 맞춰 자동으로 조정되는 모델 내부 값

- **역할**: 입력과 출력의 관계 표현
- **학습 연결**: 손실을 줄이는 방향으로 반복 조정
- **예시 개념**: 선형 모델의 가중치나 신경망 내부 연결 값
- **이해 포인트**: 사람이 일일이 정하는 값이 아니라 학습 과정에서 데이터에 맞춰 바뀌는 값

---

### 3.2 하이퍼파라미터(Hyperparameter)

학습 과정의 방식과 모델 복잡도를 사람이 미리 정하거나 검증을 통해 선택하는 설정

- **예시**: 학습률, 반복 횟수, 트리 깊이, 신경망 층 수 등
- **선택 방법**: 검증 데이터 성능을 비교해 적절한 설정 탐색
- **주의점**: 시험 데이터를 보면서 하이퍼파라미터를 조정하면 최종 평가 신뢰도 저하
- **이해 포인트**: 파라미터는 학습되는 값, 하이퍼파라미터는 학습 방식을 정하는 설정

---

### 3.3 학습 반복과 조기 종료

모델은 여러 번 데이터를 보면서 내부 값을 조정하지만 오래 학습한다고 항상 좋은 결과가 되는 것은 아님

- **초기**: 학습 데이터와 검증 데이터 모두 성능 개선 가능
- **중간**: 학습 성능은 계속 좋아지지만 검증 성능 개선이 둔화될 수 있음
- **과도한 반복**: 학습 성능은 상승하지만 검증 성능이 하락하는 과적합 신호 가능
- **대응**: 학습 조기 종료, 모델 단순화, 데이터 확대, 규제 적용 등
- **이해 포인트**: 오래 학습하는 것이 목표가 아니라 **새로운 데이터에서 성능이 가장 안정적인 지점을 찾는 것**

## 4. 과적합·과소적합·일반화

### 4.1 과적합(Overfitting)

모델이 학습 데이터의 세부 패턴과 우연한 잡음까지 과도하게 학습해 새로운 데이터에서 성능이 낮아지는 상태

- **신호**: 학습 성능은 매우 높지만 검증·시험 성능은 상대적으로 낮음
- **원인**: 지나치게 복잡한 모델, 적은 데이터, 반복 조정, 데이터 누수, 잡음이 많은 데이터
- **예시**: 기출문제 문장과 답을 그대로 외운 학생이 표현이 바뀐 문제를 풀지 못하는 상황
- **대응**: 더 많은 데이터, 모델 단순화, 규제, 조기 종료, 검증 방법 개선
- **이해 포인트**: 학습 데이터에서 잘하는 것과 실제 새로운 데이터에서 잘하는 것은 다른 문제

---

### 4.2 과소적합(Underfitting)

모델이 문제의 기본 패턴조차 충분히 학습하지 못한 상태

- **신호**: 학습 데이터와 검증 데이터 모두 성능이 낮음
- **원인**: 지나치게 단순한 모델, 부족한 특징, 학습 부족
- **대응**: 모델 표현력 확대, 특징 개선, 충분한 학습
- **이해 포인트**: 단순한 모델이 항상 안전한 것도 아니며 문제를 표현할 충분한 능력이 필요

---

### 4.3 일반화(Generalization)

학습에 사용하지 않은 새로운 데이터에서도 안정적으로 성능을 유지하는 능력

- **핵심**: 실제 AI 서비스에서 가장 중요한 평가 대상
- **확인**: 검증·시험 데이터와 실제 운영 데이터 성능 비교
- **영향 요소**: 데이터 대표성, 모델 복잡도, 과적합, 시간에 따른 데이터 변화
- **이해 포인트**: 좋은 모델은 학습 데이터를 가장 잘 외운 모델이 아니라 새로운 상황에서도 충분히 작동하는 모델

## 5. 분류 모델의 성능 지표

### 5.1 정확도(Accuracy)

전체 예측 중 맞힌 비율

- **장점**: 직관적이고 전체적인 성능을 빠르게 이해하기 쉬움
- **한계**: 클래스 비율이 크게 불균형한 문제에서 높은 정확도가 실제 성능을 과장할 가능성
- **예시**: 이탈 고객이 5%뿐이라면 모두 유지로 예측해도 정확도 95% 가능
- **이해 포인트**: 정확도 하나만 보고 모델 품질을 판단하기 어려운 상황 존재

---

### 5.2 정밀도(Precision)

모델이 양성이라고 예측한 것 중 실제 양성의 비율

- **중요 상황**: 잘못된 양성 판정의 비용이 큰 경우
- **예시**: 정상 거래를 사기로 잘못 차단하는 비용이 큰 금융 탐지
- **해석**: 양성이라고 판단했을 때 얼마나 믿을 수 있는지에 가까운 지표
- **이해 포인트**: 거짓양성을 줄이는 것이 중요할수록 정밀도 확인 필요

---

### 5.3 재현율(Recall)

실제 양성 대상 중 모델이 찾아낸 비율

- **중요 상황**: 실제 양성을 놓치는 비용이 큰 경우
- **예시**: 위험 환자, 실제 사기 거래, 실제 불량품을 놓치지 않는 것이 중요한 상황
- **해석**: 찾아야 할 대상을 얼마나 많이 찾아냈는지에 가까운 지표
- **이해 포인트**: 거짓음성을 줄이는 것이 중요할수록 재현율 확인 필요

---

### 5.4 F1 점수(F1 Score)

정밀도와 재현율을 함께 고려하는 조화평균 기반 지표

- **활용**: 두 지표의 균형이 중요한 상황
- **장점**: 한쪽 지표만 극단적으로 높은 모델보다 균형 잡힌 모델 비교에 도움
- **한계**: 실제 업무 비용과 모든 상황을 자동으로 반영하는 것은 아님
- **이해 포인트**: 지표는 목적에 따라 선택해야 하며 높은 숫자 하나가 곧 좋은 의사결정을 의미하지는 않음

---

### 5.5 혼동행렬(Confusion Matrix)

실제 값과 예측 값을 네 가지 조합으로 나눠 어떤 오류가 발생했는지 보는 표

- **참양성**: 실제 양성을 양성으로 예측
- **참음성**: 실제 음성을 음성으로 예측
- **거짓양성**: 실제 음성을 양성으로 잘못 예측
- **거짓음성**: 실제 양성을 음성으로 잘못 예측
- **활용**: 정확도 숫자 하나보다 어떤 유형의 오류가 많은지 파악
- **이해 포인트**: 성능 평가는 맞힌 수뿐 아니라 **어떤 방식으로 틀렸는지**까지 확인하는 과정

## 6. 임계값(Threshold)과 지표의 균형

많은 분류 모델은 처음부터 양성/음성을 직접 출력하기보다 **양성일 가능성 점수**를 만들고 임계값을 기준으로 최종 분류

### 6.1 임계값의 의미

- **예시**: 이탈 가능성 0.7 이상이면 이탈 위험 고객으로 분류
- **낮은 임계값**: 더 많은 대상을 양성으로 판단해 재현율이 높아질 수 있으나 거짓양성 증가 가능
- **높은 임계값**: 양성 판정을 엄격하게 해 정밀도가 높아질 수 있으나 실제 양성을 놓칠 가능성
- **이해 포인트**: 임계값은 기술적 숫자 하나가 아니라 실제 비용과 업무 자원을 반영하는 운영 기준

---

### 6.2 업무 비용과 임계값

- **의료**: 위험 환자를 놓치는 비용이 크다면 재현율을 중시하는 방향 고려
- **마케팅**: 상담 가능한 고객 수가 제한돼 있다면 정밀도와 상담 자원을 함께 고려
- **사기 탐지**: 실제 사기를 놓치는 비용과 정상 거래를 차단하는 비용 비교
- **이해 포인트**: 가장 높은 정확도의 임계값이 항상 실제 업무에 가장 적절한 임계값은 아님

## 7. 모델 평가에서 함께 확인할 요소

### 7.1 베이스라인(Baseline)

새 모델이 실제로 개선되었는지 비교하기 위한 가장 단순한 기준

- **예시**: 이탈률이 10%라면 모두 유지라고 예측해도 정확도 90%
- **판단**: 새 모델 정확도가 91%라면 숫자는 높아 보여도 실제 개선 폭은 작을 수 있음
- **비교 대상**: 단순 규칙, 기존 업무 방식, 평균값 예측, 이전 모델
- **이해 포인트**: 모델 점수는 절대값뿐 아니라 기존 방식보다 얼마나 나아졌는지 비교 필요

---

### 7.2 집단별 성능

전체 평균 성능이 높아도 특정 집단에서 오류가 집중될 가능성

- **확인 예시**: 연령대, 지역, 기기 유형, 언어, 고객 유형별 성능
- **위험**: 소수 집단 성능 저하가 전체 평균에 가려질 가능성
- **연결**: 9주차의 공정성과 편향 문제로 확장
- **이해 포인트**: 평균 성능과 집단별 성능을 함께 보는 습관 필요

---

### 7.3 시간에 따른 성능 변화

모델을 만든 시점과 실제 사용하는 시점의 데이터가 달라질 수 있음

- **원인**: 사용자 행동 변화, 시장 변화, 정책 변화, 제품 개편, 새로운 유형의 입력 등장
- **결과**: 학습 당시에는 잘 작동한 모델의 성능이 시간이 지나며 저하 가능
- **대응**: 운영 모니터링, 재평가, 필요 시 재학습
- **이해 포인트**: 모델 평가는 배포 직전 한 번으로 끝나는 과정이 아님

## 8. 학습·평가·운영 과정의 주요 위험

### 8.1 데이터 누수(Data Leakage)

실제 예측 시점에는 알 수 없는 미래 정보가 학습 데이터에 들어가 성능이 비정상적으로 높게 보이는 문제

- **예시**: 이탈 고객만 받을 수 있는 해지 완료 코드를 이탈 예측 특징으로 사용
- **결과**: 시험 환경에서는 높은 성능, 실제 운영에서는 급격한 성능 저하 가능
- **예방**: 모든 특징이 실제 예측 시점에 사용 가능한 정보인지 확인
- **이해 포인트**: 성능이 지나치게 높을 때는 데이터 누수 가능성도 점검

---

### 8.2 데이터 대표성 부족

학습 데이터가 실제 사용 환경의 다양한 상황과 집단을 충분히 포함하지 못한 문제

- **예시**: 특정 연령대나 특정 지역 데이터에 과도하게 집중
- **영향**: 일부 집단에서 높은 오류율 발생 가능
- **대응**: 데이터 구성과 집단별 성능 함께 확인
- **이해 포인트**: 데이터 양이 많아도 대표성이 부족하면 좋은 학습 데이터라고 보기 어려움

---

### 8.3 운영 환경 변화

시험 데이터도 실제 미래 상황 전체를 완벽하게 대표하지는 못함

- **한계**: 예상하지 못한 사용자 행동, 새로운 유형의 입력, 새로운 정책·시장 변화
- **필요성**: 배포 전 시험뿐 아니라 배포 후 실제 성능 모니터링 필요
- **운영 질문**: 어떤 오류를 기록하고 누가 검토하며 언제 모델을 다시 평가할 것인지 정의
- **이해 포인트**: 오프라인 시험 점수와 실제 서비스 품질을 구분해서 관리

## 9. 전체 사례로 연결하기 \| 고객 이탈 예측

2주차의 개념을 하나의 사례로 연결하면 머신러닝 개발의 전체 흐름을 이해하기 쉬움

### 9.1 문제 정의

고객이 다음 달에 서비스를 해지할 가능성을 예측해 상담 우선순위를 정하는 문제

- **목표**: 모든 고객에게 무조건 혜택을 제공하는 것이 아니라 이탈 위험 고객을 먼저 찾는 것
- **출력**: 이탈 가능성 점수 또는 이탈/유지 분류
- **중요 오류**: 실제 이탈 고객을 놓치는 거짓음성과 정상 고객을 위험 고객으로 잘못 분류하는 거짓양성의 비용 비교

---

### 9.2 데이터와 특징

과거 고객 행동 기록과 실제 이탈 여부를 이용해 지도학습 데이터 구성

- **특징 후보**: 가입 기간, 최근 접속일, 이용 횟수, 문의 횟수, 요금제 변경, 결제 실패 횟수
- **라벨**: 실제 이탈/유지
- **주의점**: 이탈 이후에만 생성되는 정보를 특징으로 포함하지 않기
- **대표성**: 특정 요금제나 특정 기간 고객만 과도하게 포함되지 않았는지 확인

---

### 9.3 학습과 검증

데이터를 학습·검증·시험으로 분할하고 여러 모델과 설정 비교

- **학습**: 학습 데이터에서 손실을 줄이는 방향으로 모델 조정
- **검증**: 검증 데이터로 과적합 여부와 설정 비교
- **시험**: 마지막에 시험 데이터로 최종 성능 확인
- **확인 지표**: 정확도뿐 아니라 정밀도·재현율·F1 점수와 혼동행렬 확인

---

### 9.4 임계값과 운영

이탈 가능성 점수를 실제 상담 대상으로 바꾸는 기준 설정

- **예시**: 0.7 이상 고객만 상담할지, 0.5 이상 고객까지 포함할지 결정
- **낮은 임계값**: 더 많은 위험 고객을 찾지만 상담 대상 수 증가
- **높은 임계값**: 상담 대상은 줄지만 실제 이탈 고객을 놓칠 가능성
- **운영 판단**: 상담 인력과 이탈 비용을 함께 고려
- **모니터링**: 시간이 지나 고객 행동이 달라지면 성능과 임계값 재검토
- **최종 연결**: 좋은 AI 모델은 높은 점수만 가진 모델이 아니라 **문제 정의·데이터·평가·운영 판단이 함께 설계된 모델**

- AI 발전 흐름은 **튜링 테스트의 문제의식 → 규칙 기반·전문가 시스템 → 머신러닝 → 딥러닝 → 생성형 AI**로 연결
- 머신러닝은 데이터에서 패턴을 학습해 모델을 만드는 접근이며 지도학습·비지도학습·강화학습·자기지도학습 등 다양한 학습 방식 존재
- 머신러닝 기본 구조는 **문제 정의 → 특징·라벨 → 알고리즘 → 모델 → 손실함수 → 학습 → 추론**의 연결
- 모델 평가는 학습 데이터 성능이 아니라 새로운 데이터에서의 **일반화 성능** 확인이 핵심
- 학습·검증·시험 데이터의 역할을 분리하고 데이터 누수와 대표성 문제를 함께 점검하는 것이 중요
- 정확도·정밀도·재현율·F1 점수는 문제의 오류 비용과 목적에 따라 함께 해석
- 임계값은 모델 점수를 실제 의사결정으로 바꾸는 운영 기준이며 업무 비용과 자원을 함께 고려
- AI 모델의 품질은 모델 자체뿐 아니라 데이터·평가·운영 과정 전체의 설계 품질과 연결
