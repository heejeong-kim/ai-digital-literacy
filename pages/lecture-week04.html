  2. 검증한 문제를 상황과 해결 방식을 바꿔 여러 형태의 프로젝트 아이디어로 전환할 수 있다
  3. 후속 질문과 웹 검색·심층 조사 기능을 활용해 AI가 처음 제시한 결과를 확장하고 검증할 수 있다

  5. 분석 결과와 팀의 수행 가능성을 바탕으로 5~6주차에서 발전시킬 프로젝트 후보 2개를 선정할 수 있다

4주차는 아이디어 하나를 바로 확정하는 시간이 아니라 여러 가능성을 탐색하고 근거를 확인해 볼 가치가 있는 후보를 남기는 시간으로 아이디어가 아니라 문제에서 시작함

관심 주제·타겟·최근 변화 중 한 경로로 문제를 모은 뒤 팀의 경험으로 검증하고, 그 문제를 상황과 해결 방식을 바꿔 여러 아이디어로 펼친 후 이어서 시장·트렌드·타겟·기술 관점에서 가능성을 살펴보고, 우리 팀이 한 학기 동안 실제로 발전시킬 수 있는지 확인

  • 이번 주차에는 최종 주제를 하나로 좁히지 않고 프로젝트 후보 2개를 선정하며, 5~6주차에서 두 후보를 더 구체화한 뒤 7주차 검증을 통해 최종 1개를 선택
  • 🚨 팀 구성과 팀 작업공간 개설을 먼저 완료후 진행, 작업공간은 Notion 활용 (개인, 팀 분리해서 정리)

1. 문제 발견

프로젝트는 아이디어가 아니라 문제에서 시작하며 좋아 보이는 아이디어를 먼저 정하면 그 아이디어를 지키기 위해 문제를 나중에 끼워 맞추게 되므로, 이 장에서는 해결책을 만들지 않고 문제만 모음

🚫 이 장에서는 아이디어를 만들지 않고 AI에게 처음부터 해결책을 물으면 문제가 실제로 존재하는지 확인하기 전에 해결책이 먼저 굳어짐. 아이디어 전환은 2장에서 진행

1.1 아이디어의 출발점

아래 세 경로 중 하나만 선택해도 되고, 팀원별로 서로 다른 경로를 맡아 병렬로 진행해도 무관하며 어느 경로를 택하든 1장의 결과물은 아이디어가 아니라 문제 목록이 도출되어야함

출발점던지는 질문의 형태이런 팀에 적합함
관심 주제이 영역에서 사람들이 반복적으로 불편해하는 일은 무엇인가다루고 싶은 분야가 정해진 팀
타겟 사용자이 사람들이 시간·정보·비용 때문에 곤란해지는 순간은 언제인가돕고 싶은 대상이 정해진 팀
최근 변화최근 달라진 행동이나 기술 때문에 새로 생긴 불편은 무엇인가분야도 대상도 아직 정해지지 않은 팀

팀원 C최근 변화AI 코딩 도구의 수업·과제 사용 확산1년 사이 주변 학생 대부분이 과제에 AI 코딩 도구를 쓰는 방식으로 바뀐 것을 관찰함AI로 코드를 받아 쓰게 되면서 새로 생긴 이해도 확인, 과제 인정 기준, 협업 혼란 탐색
팀원 D관심 주제자취생의 식생활·생활비 관리2년째 자취 중이며 장보기와 식사 준비에서 낭비가 반복되는 것을 경험함자취생이 장보기, 식재료 보관, 식사 결정, 생활비 관리에서 반복적으로 겪는 불편 탐색

팀의 1.1 실습 결과 — 탐색 출발점 4개 확정

  2. 편입생·전과생의 학기 초 적응 과정 (타겟 사용자 · B)

  4. 자취생의 식생활과 생활비 관리 과정 (관심 주제 · D)

실습 체크 확인

  • ☑ 팀에서 어떤 경로로 문제를 찾을지 정함 → 3개 경로를 병렬로 사용
  • ☑ 팀원별 담당 경로와 담당자를 기록함
  • ☑ 탐색 출발점 1개 이상 확보 → 4개 확정
  • ☑ 이 단계에서 아이디어·해결책을 만들지 않음 → 표의 모든 칸이 "문제를 찾을 범위"로만 작성됨

자가 점검: 표의 탐색 방향에 "앱을 만든다", "자동화한다" 같은 해결책 표현이 없는지 확인함. 해결책이 섞이면 1장 규칙 위반이므로 문장을 "~ 과정에서 겪는 불편 탐색"으로 통일함.

1.2 관심 주제에서 문제 찾기

내가 관심을 갖고 있거나 자주 경험하는 영역일수록 AI가 내놓은 문제가 진짜인지 판단하기 쉬움

관심 영역 예시탐색 질문 예시자주 나타나는 불편의 형태
대학생활대학생이 반복적으로 불편해하는 일은 무엇인가?정보가 흩어져 있음, 마감을 놓침, 역할이 겹침
학습처음 배우는 학생이 자주 어려워하는 지점은 무엇인가?용어를 모름, 틀린 이유를 모름, 무엇부터 할지 모름
콘텐츠콘텐츠를 만들 때 시간이 많이 드는 단계는 무엇인가?소재가 떠오르지 않음, 초안에 오래 걸림, 형식을 매번 새로 잡음
취업·진로진로를 탐색하는 학생이 부족하다고 느끼는 정보는 무엇인가?직무 차이를 모름, 경험을 설명하지 못함, 기준을 모름
지역·생활지역이나 일상에서 정보 탐색이 불편한 장면은 무엇인가?정보가 최신이 아님, 조건에 맞는 것을 찾기 어려움

1.3 타겟에서 문제 찾기

관심 주제가 뚜렷하지 않다면 누구를 도울 것인지를 먼저 정하고 그 사람이 겪는 상황을 찾음. 타겟이 구체적일수록 문제 문장이 선명해짐

타겟 예시AI에게 탐색할 내용
대학교 신입생입학 후 적응 과정에서 반복적으로 겪는 어려움
자취를 처음 시작한 학생생활 정보·예산·식사·안전 관련 불편
팀 프로젝트를 자주 하는 학생역할 분담·회의·자료 정리·일정 관리 문제
취업 준비를 시작한 학생직무 탐색·경험 정리·공고 분석 문제
소규모 동아리 운영자공지·회원 관리·홍보·회의록 등 반복 업무

1.4 최근 변화에서 문제 찾기

최근 새롭게 나타난 행동·기술·소비·학습 방식의 변화를 먼저 살펴본 뒤, 그 변화 때문에 새로 생긴 불편을 찾음. 기존에도 있던 문제가 아니라 최근에 생긴 문제라는 점이 이 경로의 강점임

최근 변화 문제 예시

  • 최근 대학생이 AI를 사용하는 방식의 변화
  • 숏폼·크리에이터·개인화 콘텐츠의 변화
  • 취업·학습·생산성 도구 사용 변화
  • AI 검색·에이전트·자동화 기능의 확산
  • 특정 산업이나 생활 영역에서 새롭게 등장한 서비스

1.5 근거와 팀 경험으로 문제 검증

1.2~1.4에서 모은 문제 후보는 웹 근거를 바탕으로 탐색한 결과이지만, 출처가 실제 문제를 충분히 뒷받침하는지와 우리 팀이 이해하고 다룰 수 있는 문제인지는 추가 확인이 필요함

근거와 팀 경험을 함께 대조해 실제로 존재한다고 판단할 수 있는 문제만 남김

진행 방법

  1. 모은 문제 후보를 한 목록으로 합치고 거의 같은 문장은 하나로 통합
  2. 각 문제의 출처를 직접 열어 근거 내용이 문제 문장을 실제로 뒷받침하는지 확인
  3. 근거 수준을 충분 / 보통 / 부족 중 하나로 판정
  4. 팀원이 각 문제에 직접 겪음 / 주변에서 봄 / 경험 없음 중 하나를 표시
  5. 근거가 부족하고 팀 경험도 확인되지 않는 문제는 제외
  6. 근거는 충분하지만 팀 경험이 없는 문제는 후속 확인 필요로 표시
  7. 근거와 팀 경험을 함께 고려해 최종 문제 5~7개 확정
  8. 남은 문제를 발생 빈도와 불편 정도 순으로 5~7개로 압축함
  9. 남긴 문제를 팀의 언어로 다시 씀
문제 문장직접 겪음주변에서 봄발생 빈도현재 대처 방식남김 / 제외
  • 현재 대처 방식 칸이 비어 있으면 그 문제는 아직 확인되지 않은 것임
  • 이미 잘 해결되고 있어 아무도 불편해하지 않는 문제도 제외
  • 제외한 문제도 사유와 함께 남겨 두면 나중에 다시 꺼낼 수 있음

1장의 결과물은 팀이 검증한 문제 5~7개임. 이 목록이 2장의 입력물이 되며, 여기에 없는 문제로는 아이디어를 만들지 않음

4. 아이디어 가능성 탐색

선정한 3~5개 후보가 단순히 재미있는 생각인지, 실제로 더 탐색할 가치가 있는지를 시장·트렌드·타겟·기술 네 관점에서 확인하는 것으로 이 단계는 정밀한 사업성 분석이 아니라 프로젝트 후보를 비교하기 위한 기초 조사이며, 3.2 요약표 마지막 행에 적어 둔 “4장에서 확인할 질문”에 답하는 단계

조사는 3주차에서 실습한 웹 검색과 심층 조사(Deep Research) 기능을 켜고 진행하며, 조사 결과는 2주차 사실 검증 4단계(분류·출처·대조·판정)에 따라 확인

4.1 시장 가능성 확인

시장 분석에서는 “얼마나 큰 시장인가”보다 먼저 비슷한 문제를 해결하려는 서비스나 수요가 실제로 존재하는가를 확인

확인 질문

  • 이미 비슷한 서비스나 도구가 있는가?
  • 사람들은 이 문제를 해결하기 위해 현재 무엇을 사용하고 있는가?
  • 기존 방식에서 불편하다고 평가되는 지점은 무엇인가?
  • 무료·유료 서비스가 있다면 어떤 기능을 제공하는가?

AI가 제시한 시장 정보와 서비스명은 그대로 믿지 않으며 2주차 사실 검증 4단계에 따라 분류(사실 주장인가 의견인가) → 출처(근거가 제시되었는가) → 대조(공식 페이지·원문과 일치하는가) → 판정(인용·수정·삭제) 순서로 확인하고 판정 결과를 가능성 분석표에 함께 기록

🖇️ [실습] · 4.1 시장 가능성 확인

예시 프롬프트

다음 프로젝트 아이디어와 비슷한 기존 서비스나 해결 방법을 조사해줘

아이디어: [아이디어]
타겟: [타겟]

비슷한 서비스, 현재 대안, 기존 방식의 불편, 차별화 지점을 출처와 함께 정리해줘.
확실하지 않은 내용은 추가 확인 필요로 표시해줘.

4.2 트렌드 가능성 확인

트렌드 분석에서는 이 아이디어와 관련된 행동이나 기술이 최근 커지고 있는지, 줄고 있는지, 형태가 바뀌고 있는지를 확인

확인 질문

  • 최근 이 주제와 관련해 사람들이 관심을 가지는 변화는 무엇인가?
  • AI 때문에 새롭게 가능해진 방식이 있는가?
  • 최근 사용자 행동이 어떻게 달라지고 있는가?
  • 지금 시작했을 때 의미가 있는 이유를 설명할 수 있는가?

트렌드 조사는 최신성이 핵심이므로 웹 검색 또는 심층 조사 기능을 반드시 켜고 진행하며 기능을 끈 상태의 답변은 모델 학습 시점까지의 정보이므로 최근 변화를 반영하지 못함

🖇️ [실습] · 4.2 트렌드 가능성 확인

예시 프롬프트

다음 아이디어와 관련된 최근 변화를 조사해줘.

아이디어: [아이디어]
타겟: [타겟]

최근 2년 이내 사용자 행동 변화와 AI로 새롭게 가능해진 방식을 출처명·발행일과 함께 정리해줘.
근거를 찾지 못한 내용은 확인 필요로 표시해줘.

예시

“최근 *의 확산으로 * 사용자의 행동이 바뀌고 있으며, 이 프로젝트는 그 변화에서 ___를 해결하려는 아이디어임.”

4.3 타겟 분석

타겟 분석에서는 “누구나 사용할 수 있다”가 아니라 가장 먼저 사용할 사람 한 집단을 구체적으로 정함

확인 항목질문
사용자누가 가장 자주 이 문제를 겪는가?
상황언제·어디에서 문제가 발생하는가?
현재 방식지금은 어떻게 해결하거나 참고 있는가?
불편 정도시간·노력·혼란·비용 중 무엇이 발생하는가?
사용 이유새로운 도구를 사용해볼 이유가 있는가?

🖇️ [실습] · 4.3 타겟 구체화

예시

“대학생”보다 “처음 팀 프로젝트를 수행하며 회의 내용과 역할 분담을 정리하는 데 어려움을 겪는 1학년 학생”처럼 구체화함

4.4 기술 가능성 확인

기술 분석에서는 어려운 기술을 직접 구현할 수 있는지를 묻기보다 현재 사용할 수 있는 생성형 AI와 도구를 조합해 핵심 기능을 시험할 수 있는가를 확인

확인 질문

  • 입력으로 어떤 자료가 필요한가?
  • AI가 처리해야 할 핵심 작업은 무엇인가?
  • 결과는 텍스트·이미지·영상·웹 화면 중 어떤 형태인가?
  • ChatGPT·Claude·Gemini 같은 기존 도구만으로 먼저 시험할 수 있는가?
  • 별도 데이터나 API가 반드시 필요한가?
  • 우리 팀이 모르는 기술이 너무 많이 필요한가?
판정의미
바로 시험 가능현재 AI 도구와 자료만으로 핵심 기능을 테스트할 수 있음
조금 학습하면 가능새 도구나 간단한 연결 방법을 익히면 시험할 수 있음
범위 축소 필요아이디어는 좋지만 현재 규모로는 구현 요소가 너무 많음
이번 학기에는 어려움전문 데이터·고급 개발·비용이 많이 필요한 핵심 기능에 의존함
  • 이번 학기에는 어려움으로 판정된 후보는 6.1 탈락 기준에 따라 제외하거나, 핵심 기능을 줄여 다시 판정함
  • 범위 축소 필요로 판정된 후보는 줄인 범위를 그대로 후보 카드의 “예상 결과물”에 반영함
  • 판정 근거를 한 줄로 남겨야 6장에서 왜 그 후보를 뺐는지 설명할 수 있음

🖇️ [실습] · 4.4 기술 가능성 확인

예시

입력: 팀 회의록 텍스트 → AI 처리: 핵심 안건과 할 일 추출 → 결과물: 담당자별 할 일 목록. 기존 AI 도구로 시험할 수 있으므로 ‘바로 시험 가능’으로 판정함.

✅ 4장 실습 완료 기준: 후보 3~5개에 대해 시장·트렌드·타겟·기술 근거가 모두 채워짐

5. 팀 프로젝트 수행 가능성 점검

시장 가능성이 있어도 수업 프로젝트로 완성하기 어려우면 범위를 줄여야 함. 다음 질문을 통해 우리 팀이 실제로 해볼 수 있는가를 확인

점검 항목확인 질문
기간남은 수업 기간 안에 핵심 결과를 만들 수 있는가?
팀 역량현재 할 수 있는 것과 새로 배워야 할 것을 구분할 수 있는가?
데이터·자료테스트에 필요한 자료를 직접 확보할 수 있는가?
도구무료 또는 학교에서 사용할 수 있는 AI 도구로 시험 가능한가?
핵심 기능기능을 하나만 남겨도 프로젝트의 가치가 보이는가?
시연 가능성학기 말에 입력→처리→결과를 보여줄 수 있는가?

5.1 프로젝트를 작게 만드는 기준

  • “모든 대학생”보다 특정 상황의 사용자 한 집단을 선택
  • 기능 5개보다 핵심 기능 1개를 먼저 시험함
  • 완전 자동화보다 사람이 중간에 확인하는 방식도 허용함
  • 실제 서비스 출시보다 작동 원리를 보여주는 프로토타입을 목표로 함
  • 데이터가 부족하면 공개 자료나 팀이 직접 만든 테스트 자료로 범위를 줄임

좋은 팀 프로젝트는 가장 큰 아이디어가 아니라 핵심 가치를 실제로 시험하고 설명할 수 있는 아이디어

🖇️ [실습] · 5장 팀 프로젝트 수행 가능성 점검

✅ 5장 실습 완료 기준: 각 후보가 “가능 / 범위 축소 필요 / 이번 학기에는 어려움” 중 하나로 판정

6. 프로젝트 후보 2개 선정

시장·트렌드·타겟·기술 분석과 수행 가능성 점검 결과를 비교해 5~6주차에서 함께 발전시킬 후보 2개를 선정함

6.1 탈락 기준 적용

남길 후보를 고르기 전에 떨어뜨릴 기준을 먼저 적용함. 좋아 보이는 이유를 찾는 방식은 팀 취향으로 흘러 4장 조사가 사후 정당화가 되기 쉬우므로, 제외 기준을 먼저 적용해 근거로 설명할 수 있는 선택을 만듦

순서탈락 기준판단 근거조치
1기술 판정이 “이번 학기에는 어려움”임4.4 판정 결과제외하거나 핵심 기능을 줄여 재판정함
2목표 사용자를 한 문장으로 쓸 수 없음4.3 타겟 분석의 사용자·상황 칸이 비어 있음제외
3시장·트렌드 근거를 한 건도 확인하지 못함4.1·4.2 조사에서 출처를 찾지 못함제외
4학기 말 시연이 불가능함5장 시연 가능성 점검에서 입력→처리→결과를 보여 줄 수 없음제외
5팀원 전원이 관심을 가지지 않음한 학기 동안 유지할 동기가 없음제외
  • 1~5를 순서대로 적용하고 제외한 후보와 사유를 반드시 기록
  • 기준 적용 후 남은 후보가 2개면 그대로 확정
  • 3개 이상 남으면 6.2 비교표로 좁히고, 1개 이하로 남으면 3장으로 돌아가 후보를 다시 발산함

📦 금주 산출물은 팀 프로젝트 산출물 점수로 평가됨

주차별 팀프로젝트 산출물은 수시 점검하여 팀 프로젝트 산출물 점수로 체크할 예정으로 개인별 작업은 별도 노션 관리, 팀 구성 후 필요한 내용을 팀 프로젝트 문서로 옮겨 지속적으로 관리

팀 프로젝트 산출물은 14주차 최종 산출물에 누락 없이 제출되도록 별도 관리

🎯 위 항목이 모두 체크되면 4주차 실습 완료. 7장은 재실습이 아니라 1~6장에서 누적된 결과물을 한 번에 정리하고 제출 상태를 확인하는 용도로 사용

팀 산출물

  1. 탐색 출발점과 팀원별 담당 경로 기록(1.1)
  2. 문제 후보 목록과 출처·근거 자료(1.2~1.4)
  3. 문제 검증표(1.5) — 근거 수준·팀 경험·현재 대처 방식·제외 사유 포함
  4. 아이디어 정리표(2.3) — 원래 문제·프로젝트 유형·대상 사용자·AI 역할·결과물 형태 포함
  5. 수행 방식 비교 기록(2.2.1) — 데이터 수집·분석, 모델 구현 실습, AI 서비스 체험형 프로젝트
  6. 1차 후보 요약표와 후보별 추가 조사 질문(3.1)
  7. 시장·트렌드·타겟·기술 가능성 분석표(4.1~4.4)
  8. 팀 프로젝트 수행 가능성 점검표(5.1)
  9. 탈락 기준 판정 기록과 최종 후보 비교표(6.1~6.2) — 후보별 평가 근거 포함
  10. 프로젝트 후보 카드 2개(6.3) — 5~6주차에서 발전시킬 최종 후보

단계별 완료 결과 체크

  • 탐색 출발점 결과: 관심 주제·타겟 사용자·최근 변화 중 담당 경로와 탐색 범위가 정리되어 있음
  • 문제 탐색 결과: 1.2~1.4의 문제 후보와 출처·근거가 정리되어 있음
  • 문제 검증 결과: 근거와 팀 경험을 반영한 최종 문제 5~7개와 제외 사유가 정리되어 있음
  • 아이디어 확장 결과: 검증된 문제에서 출발한 아이디어 15~20개가 프로젝트 유형별로 정리되어 있음
  • 수행 방식 결과: 세 가지 수행 방식별 아이디어·필요 데이터·도구·팀 역량·최소 범위가 비교되어 있음
  • 1차 후보 선정 결과: 분석할 후보 3~5개와 후보별 추가 조사 질문이 정리되어 있음
  • 가능성 분석 결과: 후보별 시장·트렌드·타겟·기술 근거가 정리되어 있음
  • 수행 가능성 결과: 기간·팀 역량·데이터·도구 접근성·시연 가능성 판정이 정리되어 있음
  • 최종 비교 결과: 후보별 평가 항목과 판단 근거, 제외 후보 사유가 정리되어 있음
  • 최종 선정 결과: 최종 후보 2개와 프로젝트 후보 카드 2개가 완성되어 있음
  • 다음 주차 연결: 후보별로 7주차 최종 선택 전에 확인할 질문이 2개 이상 정리되어 있음

[참고]

4주차에서 선정한 두 후보는 아직 최종 프로젝트가 아니고, 우선 후보로 선정

  • 5주차: 두 후보의 목표 사용자·문제·AI 담당 구간을 구체화하고, 두 후보에 공통으로 사용할 팀 전용 AI 비서를 제작
  • 6주차: 텍스트·이미지·음성·영상·코드 등 멀티모달 활용 가능성을 시험하며 두 후보의 결과물이 어떤 형태로 나올지 각각 탐색
  • 7주차: 두 후보의 필요성·차별성·실현성·안전성을 비교해 최종 프로젝트 1개를 선택
