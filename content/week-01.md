# 1️⃣ 1교시 \| 인공지능의 개념과 작동 구조 이해
## 1. 인공지능(Artificial Intelligence)이란 무엇인가
인공지능은 컴퓨터가 인간의 지적 활동과 유사한 과제를 수행하도록 만드는 기술과 방법의 집합이다. 중요한 점은 AI를 ‘사람처럼 생각하는 존재’로 단순화하지 않고, **주어진 목적에 따라 데이터를 처리하고 패턴을 찾아 결과를 산출하는 시스템**으로 이해하는 것이다.
현재 상용 서비스에서 사용하는 대부분의 AI는 특정 과제를 중심으로 설계된 좁은 인공지능(Narrow AI)이다. 번역, 얼굴 인식, 수요 예측, 추천, 문서 요약, 이미지 생성 등이 이에 해당한다. 반면 범용 인공지능(Artificial General Intelligence)은 다양한 상황에서 사람과 유사한 수준으로 폭넓게 문제를 이해하고 해결하는 개념으로, 현재 일반적인 상용 AI와 구분해야 한다.
### 왜 이 구분이 중요한가
- AI가 특정 과제에서 높은 성능을 보인다고 모든 과제를 잘하는 것은 아니다.
- 자연스러운 문장이나 이미지가 곧 사실 이해나 책임 있는 판단을 의미하지 않는다.
- 실제 도입에서는 ‘AI가 가능한가’보다 ‘어떤 범위에서 신뢰할 수 있는가’를 먼저 정의해야 한다.
### 적용 사례
내비게이션의 도착시간 예측은 교통 패턴 분석에는 강하지만 갑작스러운 사고·통제·행사까지 항상 정확히 반영하는 것은 아니다. 따라서 AI 성능은 **과제·데이터·환경**을 함께 봐야 한다.
## 2. 인공지능의 대표 기능
AI는 하나의 기능이 아니라 여러 기능을 조합해 서비스에 적용된다. 같은 서비스 안에서도 인식·분류·예측·추천·생성이 동시에 사용될 수 있다.
### 인식(Recognition)
이미지·음성·문자·센서 신호에서 의미 있는 대상을 찾아내는 기능이다. 얼굴 인식, 음성 인식, 문서 문자 추출이 대표적이다.
### 분류(Classification)
입력을 미리 정한 범주로 구분한다. 스팸/정상 메일, 불량/정상 제품, 문의 유형 분류처럼 결과 범주가 비교적 명확한 문제에 사용된다.
### 예측(Prediction)
과거와 현재 데이터를 이용해 미래 값이나 사건의 가능성을 추정한다. 수요, 이탈, 고장, 도착시간 예측 등이 있다.
### 추천(Recommendation)
사용자의 행동·선호·유사 사용자 정보를 이용해 선택 가능성이 높은 항목을 제시한다. 추천 결과는 전체 선택지를 객관적으로 정렬한 것이 아니라 **설계된 목표에 따라 최적화된 결과**라는 점을 이해해야 한다.
### 생성(Generation)
학습한 패턴을 바탕으로 새로운 텍스트·이미지·음성·영상·코드를 만든다. 생성 결과는 새롭게 구성된 출력이므로 사실 검증이 별도로 필요하다.
### 의사결정 지원(Decision Support)
AI가 최종 결정을 대신하기보다 점수·위험 신호·후보·요약을 제공해 사람의 판단을 돕는다. 의료 영상의 의심 부위 표시, 이상거래 경고가 대표적이다.
## 3. 일반 프로그램과 AI의 차이
일반 프로그램은 사람이 명시적으로 작성한 규칙에 따라 입력을 처리한다. 세율 계산이나 회원등급 조건처럼 규칙이 명확한 문제는 일반 프로그램이 더 적합하다.
학습 기반 AI는 사람이 모든 규칙을 직접 작성하기 어려운 문제에서 데이터로부터 패턴을 학습한다.
- 일반 프로그램: **규칙 → 입력 → 결과**
- 학습 기반 AI: **데이터 → 학습 → 모델 → 새로운 입력 → 결과**
실무에서는 둘을 결합한다. 예를 들어 이상거래탐지 시스템은 AI가 위험 점수를 계산하고, 일정 기준 이상일 때 규칙 기반 시스템이 추가 인증을 요구하도록 설계할 수 있다.
### 판단 포인트
AI를 쓰는 이유는 ‘최신 기술이기 때문’이 아니라 규칙을 사람이 모두 작성하기 어렵고, 데이터에서 반복 패턴을 찾는 것이 문제 해결에 실제 도움이 되기 때문이다.
## 4. 데이터(Data)·알고리즘(Algorithm)·모델(Model)의 관계
데이터는 AI가 학습하거나 결과를 만들 때 사용하는 재료다. 텍스트·이미지·음성·숫자·행동 기록이 모두 데이터가 될 수 있다.
알고리즘은 문제를 해결하기 위한 계산 절차이며, 학습 과정에서는 데이터를 어떻게 처리하고 모델 내부 값을 어떻게 조정할지 결정한다.
모델은 학습 결과 만들어진 계산 구조다. 새로운 입력이 들어오면 모델이 계산을 수행해 분류·예측·생성 등의 결과를 낸다.
### 전체 흐름
**문제 정의 → 데이터 준비 → 학습 → 모델 생성 → 새로운 입력 → 추론 → 결과 → 사람 검토**
이 흐름을 이해하면 AI의 결과가 단순히 ‘컴퓨터가 생각한 답’이 아니라 데이터와 설계 조건의 영향을 받은 산출물이라는 점을 알 수 있다.
## 5. 학습(Training)과 추론(Inference)
학습은 데이터를 이용해 모델의 내부 값을 조정하는 과정이다. 목표는 학습 데이터를 단순히 외우는 것이 아니라 새로운 데이터에서도 유용한 패턴을 찾도록 하는 것이다.
추론은 학습이 끝난 모델에 새로운 입력을 넣어 실제 결과를 산출하는 단계다. 사용자가 번역 서비스에 문장을 넣거나 생성형 AI에 질문할 때 경험하는 과정은 대부분 추론이다.
### 실무적으로 중요한 차이
- 학습 단계에서는 데이터 품질·대표성·비용이 중요하다.
- 추론 단계에서는 입력 품질·응답 속도·검증·운영 환경이 중요하다.
- 모델이 학습한 시점과 실제 사용 환경이 달라지면 성능이 떨어질 수 있다.
## 6. AI가 잘하는 일과 어려워하는 일
AI는 대량 데이터 처리, 반복 패턴 탐색, 후보 생성, 일정한 기준의 분류에 강하다. 반면 목적을 정하고 예외의 의미를 판단하며 사회적 영향을 고려하고 최종 책임을 지는 일은 사람의 역할이 중요하다.
### AI에 적합한 영역
- 수천 건의 문서 분류·요약
- 반복되는 패턴 탐색
- 예측 후보와 추천 후보 생성
- 초안·아이디어·대안 생성
### 사람이 중심이 되어야 하는 영역
- 문제와 목적 정의
- 중요한 기준과 우선순위 결정
- 예외 상황의 맥락 해석
- 사실·권리·윤리 검토
- 최종 승인과 책임
## 7. AI 시스템을 평가하는 기본 관점
AI를 평가할 때 ‘정확한가?’ 하나만 묻는 것은 부족하다. 실제 서비스에서는 **목적·데이터·성능·운영·책임**을 함께 평가해야 한다.
### 7.1 목적 적합성
무엇을 해결하려는 시스템인지 먼저 확인한다. 같은 추천 시스템도 클릭률을 높이는 것이 목표인지, 사용자의 새로운 콘텐츠 발견을 돕는 것이 목표인지에 따라 결과가 달라진다.
### 7.2 데이터 적합성
어떤 사람과 상황의 데이터가 포함됐는지, 빠진 집단은 없는지 확인한다. 모델 성능이 높아도 실제 사용 대상과 학습 데이터가 크게 다르면 결과를 신뢰하기 어렵다.
### 7.3 성능과 오류 비용
전체 정확도만 보지 말고 어떤 오류가 발생하고 그 오류가 누구에게 어떤 피해를 주는지 확인한다. 의료 선별처럼 놓치는 오류가 큰 문제와 광고 추천처럼 오류 비용이 낮은 문제는 동일한 기준으로 볼 수 없다.
### 7.4 운영 안정성
실제 서비스에서는 입력 형식 변화, 새로운 사용자 행동, 시스템 장애, 모델 업데이트 등이 발생한다. 따라서 AI는 출시 시점의 성능뿐 아니라 지속적인 모니터링과 수정 체계가 필요하다.
### 7.5 책임 구조
AI가 결과를 냈더라도 결과를 사용하고 실행하는 책임 주체가 사라지는 것은 아니다. 중요한 의사결정에서는 사람이 검토·수정·중단할 수 있는 구조가 필요하다.
<callout icon="💡" color="blue_bg">
	**핵심 질문**: ‘AI가 할 수 있는가?’보다 ‘어떤 조건에서 사용해야 하며, 틀렸을 때 누가 확인하고 수정할 것인가?’를 함께 질문해야 한다.
</callout>

### 심화 해설 \| AI 시스템은 ‘모델’ 하나가 아니라 전체 시스템으로 본다
실무에서 AI를 평가할 때 모델의 성능만 보는 것은 충분하지 않다. 실제 서비스는 데이터 수집, 전처리, 모델 추론, 업무 규칙, 사용자 화면, 사람의 검토 절차, 로그와 모니터링이 결합된 **AI 시스템(AI System)**으로 작동한다. 같은 모델을 사용해도 입력 데이터가 다르거나 후처리 규칙이 달라지면 최종 결과와 위험 수준이 달라질 수 있다.
예를 들어 고객문의 분류 모델이 동일하더라도 한 조직은 분류 결과를 상담원에게 참고 정보로만 보여주고, 다른 조직은 자동으로 담당 부서를 변경할 수 있다. 두 시스템은 모델 정확도가 같더라도 업무 영향과 필요한 통제 수준이 다르다. 따라서 AI를 이해할 때는 ‘어떤 모델인가’와 함께 ‘어떤 업무 흐름에 연결되어 있는가’를 확인해야 한다.
### 심화 해설 \| AI 성능과 비즈니스 성과는 동일하지 않다
모델의 정확도가 높아졌다고 조직의 성과가 자동으로 좋아지는 것은 아니다. 업무에서는 처리시간, 비용, 사용자 만족도, 오류 복구시간, 직원의 검토 부담 등 여러 지표가 함께 영향을 받는다. 예를 들어 자동 분류 정확도가 95%라도 잘못 분류된 5%가 고액 고객이나 긴급 민원에 집중된다면 실제 업무 영향은 매우 클 수 있다.
따라서 AI 도입 전에는 기술 지표와 업무 지표를 분리해서 정의하는 것이 좋다. 기술 지표는 모델의 예측 품질을 나타내고, 업무 지표는 그 결과가 실제 프로세스에 어떤 변화를 만들었는지를 보여준다. 두 지표를 연결하지 않으면 ‘AI 성능은 좋은데 현장에서는 불편한 시스템’이 만들어질 수 있다.
### 심화 해설 \| 입력(Input)과 출력(Output)을 명확히 구분한다
AI를 제대로 설명하려면 무엇이 입력되고 무엇이 출력되는지 먼저 확인해야 한다. 텍스트 분류 모델은 문장을 입력받아 범주를 출력하고, 이미지 생성 모델은 텍스트나 참고 이미지를 입력받아 새로운 이미지를 출력한다. 추천 시스템은 사용자 행동과 상품 정보를 입력받아 추천 순위나 점수를 출력할 수 있다.
입력과 출력이 명확하면 모델의 역할과 한계도 설명하기 쉬워진다. 반대로 ‘AI가 고객을 이해한다’처럼 추상적으로 표현하면 실제로 어떤 정보를 사용했고 무엇을 계산했는지 확인하기 어렵다. 강의에서는 서비스를 볼 때 `입력 → 처리 → 출력 → 사람의 사용` 구조로 분석하는 습관을 만든다.
### 심화 해설 \| 자동화와 지능화를 구분한다
자동화(Automation)는 정해진 절차를 사람이 직접 수행하지 않도록 시스템이 대신 처리하는 것을 의미한다. 지능화(Intelligent Automation)는 여기에 분류, 예측, 생성처럼 데이터 기반 판단이 결합된 형태다. 모든 자동화가 AI는 아니며, 모든 AI가 자동 실행을 의미하는 것도 아니다.
예를 들어 정해진 시간에 이메일을 보내는 기능은 일반 자동화일 수 있고, 이메일 내용을 분석해 고객 유형을 분류한 뒤 상황별 답변 초안을 생성하는 과정은 AI가 결합된 자동화다. 이 차이를 구분하면 ‘AI가 필요하지 않은 문제에 AI를 억지로 적용하는 것’을 피할 수 있다.
### 심화 해설 \| 사람과 AI의 역할 분담을 설계한다
AI를 도입할 때 중요한 질문은 ‘사람을 대체할 것인가’보다 ‘어떤 단계에서 사람이 결정해야 하는가’다. 반복적이고 기준이 명확한 작업은 AI가 보조하기 쉽지만, 책임이 크거나 예외가 많은 판단은 사람의 검토가 중요하다.
역할 분담을 설계할 때는 AI가 제안하는 단계, 사람이 검토하는 단계, 자동 실행 가능한 단계, 문제가 발생했을 때 되돌리는 단계를 구분한다. 이를 통해 AI의 장점을 활용하면서도 오류가 바로 피해로 이어지는 것을 줄일 수 있다.
# 2️⃣ 2교시 \| 디지털 리터러시와 AI 시대의 인간 역량
## 1. 디지털 리터러시(Digital Literacy)란 무엇인가
디지털 리터러시는 기기나 앱을 조작하는 기술만을 의미하지 않는다. 디지털 환경에서 필요한 정보를 **찾고, 이해하고, 평가하고, 생성하고, 소통하며, 안전하고 책임 있게 활용하는 종합 역량**이다.
검색을 잘하거나 프로그램을 빠르게 다루는 것만으로 충분하지 않다. 정보의 출처를 판단하고, 플랫폼이 정보를 배열하는 방식을 이해하고, 자신의 행동이 다른 사람에게 미치는 영향까지 고려해야 한다.
### 주요 구성
- 접근: 필요한 정보와 도구를 찾는다.
- 이해: 텍스트·표·이미지·영상의 의미와 맥락을 읽는다.
- 평가: 출처·근거·최신성·편향을 확인한다.
- 생성: 목적과 대상에 맞는 콘텐츠를 만든다.
- 참여: 디지털 공간에서 근거를 갖고 협업한다.
- 안전과 책임: 개인정보·저작권·타인에게 미치는 영향을 고려한다.
## 2. 정보·미디어·데이터·디지털 시민성의 관계
정보 리터러시(Information Literacy)는 필요한 정보를 찾고 근거와 출처를 평가하는 능력이다. 미디어 리터러시(Media Literacy)는 뉴스·광고·영상·SNS 콘텐츠가 어떤 목적과 방식으로 만들어지는지 해석하는 능력이다.
데이터 리터러시(Data Literacy)는 숫자와 그래프, 데이터 수집 방식과 분석 결과를 비판적으로 읽는 능력이다. 디지털 시민성(Digital Citizenship)은 디지털 공간에서 권리와 책임을 이해하고 타인과 안전하게 참여하는 태도와 행동을 포함한다.
이 영역들은 서로 분리된 과목이 아니라 실제 디지털 문제를 판단할 때 함께 작동한다.
## 3. 인공지능 리터러시(AI Literacy)
AI 리터러시는 AI의 기능과 한계를 이해하고, 적절한 상황에 활용하며, 결과를 검증하고, 사용 결과에 대한 책임을 판단하는 능력이다.
### 네 단계
1. **이해**: AI가 어떤 방식으로 결과를 만드는지 기본 구조를 이해한다.
2. **활용**: 문제에 맞는 AI 기능과 도구를 선택한다.
3. **평가**: 결과의 사실성·편향·누락·위험을 확인한다.
4. **책임**: AI 사용으로 발생할 수 있는 영향과 책임을 고려한다.
AI 도구를 빠르게 다루는 능력과 AI 리터러시는 동일하지 않다. 최신 기능을 잘 사용해도 결과를 그대로 믿거나 민감정보를 무분별하게 입력하면 높은 AI 리터러시라고 보기 어렵다.
## 4. 알고리즘 큐레이션(Algorithmic Curation)과 개인화(Personalization)
디지털 플랫폼은 사용자가 보는 정보를 단순 시간순으로 보여주지 않는다. 클릭, 시청시간, 검색, 구매, 좋아요 등 행동 데이터를 이용해 노출 순서를 조정한다.
개인화는 편리하지만 사용자가 비슷한 정보만 반복해서 접하거나 특정 관점이 과도하게 강화될 수 있다. 따라서 사용자는 ‘내 화면에 보이는 정보’가 전체 정보의 중립적 표본이라고 가정해서는 안 된다.
### 확인 질문
- 왜 이 콘텐츠가 나에게 보였을까?
- 추천 목표는 만족도인가, 클릭률인가, 구매인가?
- 다른 관점이나 원자료를 별도로 확인했는가?
## 5. AI 시대의 인간 역할
AI를 활용하는 사람은 단순 명령 입력자가 아니라 문제를 정의하고 결과를 책임지는 운영자 역할을 한다.
### 문제정의(Problem Definition)
무엇을 해결하려는지, 대상이 누구인지, 좋은 결과의 기준이 무엇인지 정한다.
### 위임(Delegation)
어떤 업무를 AI에 맡기고 어떤 부분을 사람이 직접 수행할지 결정한다.
### 검증(Verification)
결과의 사실, 숫자, 출처, 누락, 위험을 확인한다.
### 최종 승인(Final Approval)
중요한 결과를 실제로 사용할지 결정하고 책임을 진다.
## 6. 자동화 편향(Automation Bias)과 과신(Overreliance)
자동화 편향은 기계가 제시한 결과라는 이유로 자신의 반대 증거나 판단보다 AI 결과를 우선하는 경향이다. 과신은 AI가 잘하는 범위를 넘어 결과를 지나치게 신뢰하는 행동을 의미한다.
반대로 AI를 무조건 불신하는 것도 바람직하지 않다. 중요한 것은 과제의 위험과 시스템의 성능에 맞춰 신뢰 수준을 조절하는 적절한 신뢰(Calibrated Trust)다.
### 사례
AI가 지원자에게 낮은 점수를 줬더라도 담당자는 근거·입력 데이터·예외 사유를 확인할 수 있어야 한다. ‘AI가 그렇게 평가했다’는 말은 최종 판단의 충분한 근거가 아니다.
## 7. 디지털 환경에서의 설계와 사용자 행동
디지털 서비스는 기본값(Default), 알림(Notification), 추천 순서, 화면 배치 등을 통해 사용자의 행동에 영향을 준다. 일부 서비스는 사용자가 원하지 않는 선택을 하도록 유도하는 다크 패턴(Dark Pattern)을 사용할 수 있다.
사용자는 편리함만 볼 것이 아니라 서비스가 어떤 행동을 유도하도록 설계됐는지 이해해야 한다. 알림을 줄이고 사용 시간을 관리하며 정보 소비 방식을 조절하는 디지털 웰빙(Digital Wellbeing)도 리터러시의 일부다.
## 8. 생성형 AI 이후 달라진 정보 생산과 검증
생성형 AI는 누구나 빠르게 대량의 텍스트·이미지·영상 콘텐츠를 만들 수 있게 했다. 생산 비용은 낮아졌지만 사실 오류, 허위정보, 출처 불명, 합성 콘텐츠의 확산 가능성도 커졌다.
따라서 사용자는 정보 소비자뿐 아니라 **정보 공동생산자**가 된다. AI가 만든 초안을 공유하거나 제출하는 순간 그 결과의 정확성·표현·권리 문제에 대한 책임도 함께 발생한다.
## 9. 적용 사례 \| 같은 AI, 다른 사용 수준
### 낮은 리터러시 활용
AI에게 과제를 요청하고 결과를 그대로 제출한다. 출처와 사실을 확인하지 않고 개인정보가 포함된 자료도 그대로 입력한다.
### 높은 리터러시 활용
목적과 조건을 명확히 전달하고, 결과에서 확인이 필요한 부분을 표시한 뒤 원자료와 대조한다. 필요한 부분을 자신의 판단으로 수정하고 민감정보는 제거한다.
### 비교 포인트
도구 사용 여부가 아니라 **문제정의·검증·수정·책임 과정**에서 차이가 발생한다.
## 10. 적용 활동 \| 나의 AI·디지털 리터러시 지도
자주 사용하는 AI 또는 디지털 서비스 2개를 선택해 다음을 분석한다.
1. 서비스가 수행하는 AI 기능
2. 사용하는 것으로 추정되는 데이터
3. 사용자에게 제공하는 편익
4. 잘못된 결과가 발생할 수 있는 지점
5. 사람이 확인해야 하는 지점
6. 이번 학기 개선하고 싶은 리터러시 역량
## ### 심화 해설 \| 디지털 환경에서 ‘선택’도 설계된다
디지털 서비스에서 사용자가 보는 화면과 선택지는 중립적으로 배치되지 않는다. 추천 순서, 기본값(Default), 알림(Notification), 버튼의 크기와 위치는 사용자의 행동에 영향을 준다. 특히 개인화(Personalization)와 알고리즘 큐레이션(Algorithmic Curation)은 사용자가 접하는 정보의 범위를 좁히거나 특정 콘텐츠를 반복적으로 노출할 수 있다.
따라서 디지털 리터러시는 화면에 보이는 정보를 소비하는 능력을 넘어 ‘왜 이것이 나에게 보이는가’를 질문하는 능력까지 포함한다. 추천 결과가 개인 취향을 잘 반영하더라도 전체 정보 환경을 대표하는 것은 아니라는 점을 이해해야 한다.
### 심화 해설 \| AI 리터러시는 도구 숙련도와 다르다
특정 AI 서비스의 메뉴와 기능을 빠르게 사용하는 사람도 결과의 한계를 이해하지 못하면 AI 리터러시가 높다고 보기 어렵다. AI 리터러시는 도구 사용 능력뿐 아니라 결과가 어떻게 만들어졌는지, 어떤 위험이 있는지, 어느 수준까지 신뢰할 수 있는지, 최종 책임은 누구에게 있는지를 판단하는 역량을 포함한다.
실무에서는 AI를 잘 쓰는 사람보다 **AI가 틀릴 수 있는 지점을 알고 확인 절차를 설계하는 사람**이 더 안정적으로 성과를 낼 수 있다. 특히 보고서, 계약, 교육, 의료, 금융처럼 오류 비용이 큰 업무에서는 검증 능력이 사용 속도보다 중요하다.
### 심화 해설 \| 자동화 편향(Automation Bias)과 과신(Overreliance)
자동화 편향은 기계가 제시한 결과를 사람이 자신의 판단보다 우선시하는 경향이다. 화면에 점수나 추천이 제시되면 사용자는 충분한 근거가 없어도 ‘시스템이 계산했으니 맞을 것’이라고 생각할 수 있다.
과신은 AI가 잘했던 경험이 반복되면서 사용자가 점차 검토를 줄이는 현상으로 이어질 수 있다. 이를 줄이려면 중요한 결과에서는 근거를 확인하고, 반대 사례를 찾아보고, 사람이 결과를 수정하거나 거부할 수 있는 절차를 유지해야 한다.
### 심화 해설 \| 적절한 신뢰(Calibrated Trust)
AI를 무조건 믿거나 무조건 불신하는 태도는 모두 바람직하지 않다. 적절한 신뢰는 과업과 상황에 따라 AI의 신뢰 수준을 조정하는 것이다. 맞춤법 수정이나 초안 아이디어처럼 오류 비용이 낮은 작업은 빠르게 활용할 수 있지만, 재무 수치나 정책 해석처럼 오류 비용이 큰 작업은 근거 확인이 필요하다.
학생이 AI를 활용할 때도 같은 원칙을 적용할 수 있다. 아이디어 발상에는 폭넓게 활용하되, 사실 주장·인용·수치·법적 판단은 원자료로 검증하는 식으로 업무 유형별 신뢰 수준을 구분한다.
### 심화 해설 \| 디지털 시민성(Digital Citizenship)
디지털 시민성은 온라인에서 권리와 책임을 이해하고 타인과 안전하게 상호작용하는 태도와 역량을 의미한다. AI 시대에는 단순 게시물 작성뿐 아니라 AI로 생성한 콘텐츠를 공유할 때도 사실성, 저작권, 개인정보, 타인의 권리를 고려해야 한다.
예를 들어 사실 확인이 되지 않은 AI 생성 이미지를 실제 사건 사진처럼 공유하면 정보 왜곡이 발생할 수 있고, 다른 사람의 얼굴이나 목소리를 무단으로 합성하면 권리 침해 문제가 생길 수 있다. 따라서 생성 능력이 커질수록 공유 책임도 커진다.
### 심화 해설 \| 디지털 웰빙(Digital Wellbeing)
디지털 웰빙은 기술을 오래 사용하는지보다 기술 사용이 집중, 감정, 인간관계, 학습, 휴식에 어떤 영향을 주는지 점검하는 개념이다. 무한 스크롤, 반복 알림, 개인화 추천은 사용 시간을 늘리는 데 효과적일 수 있지만 사용자의 목적과 항상 일치하는 것은 아니다.
AI 도구도 마찬가지다. 모든 과제를 AI에게 맡기면 단기적으로는 빠르지만 스스로 문제를 구조화하고 판단하는 경험이 줄어들 수 있다. 중요한 것은 AI를 사용하지 않는 것이 아니라 **어떤 단계에서 사용하고 어떤 단계는 스스로 수행할지 의도적으로 선택하는 것**이다.
## 🔎 핵심 정리
- 인공지능은 특정 목적을 위해 데이터와 모델을 이용해 결과를 산출하는 시스템이며, 사람과 동일한 방식으로 이해하거나 판단하는 존재로 볼 수 없다.
- AI의 핵심 흐름은 **문제 정의 → 데이터 → 학습 → 모델 → 추론 → 결과 → 인간 검토**로 이해할 수 있다.
- 디지털 리터러시는 정보 탐색·평가·생성·참여·안전까지 포함하며, AI 리터러시는 AI의 기능·한계·검증·책임에 더 집중한다.
- AI 시대의 핵심 역량은 도구 사용 속도보다 문제정의, 적절한 위임, 결과 검증, 최종 판단과 책임에 있다.
## 🔎 추가 심화 학습 \| AI를 보는 다섯 가지 관점
AI를 실제로 이해하려면 하나의 정의만 외우기보다 서로 다른 관점에서 시스템을 바라보는 연습이 필요하다. 첫째, **기술 관점**에서는 어떤 모델과 데이터가 사용됐는지를 본다. 둘째, **업무 관점**에서는 어떤 과제를 얼마나 잘 해결하는지를 본다. 셋째, **사용자 관점**에서는 결과를 이해하고 통제할 수 있는지를 본다. 넷째, **운영 관점**에서는 오류·비용·속도·유지보수를 본다. 다섯째, **사회 관점**에서는 권리·책임·공정성을 살핀다.
### 기술 성능과 업무 성과는 다르다
모델 정확도가 높다고 실제 업무 성과가 자동으로 좋아지는 것은 아니다. 예를 들어 상담 분류 모델의 정확도가 95%여도 잘못 분류된 5%가 모두 긴급 민원이라면 업무 위험은 매우 클 수 있다. 반대로 정확도가 조금 낮더라도 사람이 빠르게 검토하고 수정할 수 있는 구조라면 실제 운영 성과는 더 좋을 수 있다.
### 자동화와 지능화의 차이
자동화(Automation)는 정해진 절차를 사람이 직접 반복하지 않도록 시스템이 수행하게 만드는 것이다. 지능화(Intelligence Augmentation)는 데이터와 AI를 이용해 판단의 범위·속도·질을 높이는 것이다. 두 개념은 함께 사용될 수 있지만 동일하지 않다. 예를 들어 단순 이메일 발송 예약은 자동화지만, 고객 특성에 따라 메시지를 추천하고 우선순위를 정하는 것은 지능화에 가깝다.
### AI 시스템의 입력·처리·출력
AI 서비스를 분석할 때는 `입력(Input) → 처리(Processing) → 출력(Output) → 피드백(Feedback)` 흐름으로 보는 것이 유용하다. 입력에는 데이터와 사용자 요청이 포함되고, 처리 단계에서는 모델과 규칙이 작동하며, 출력은 예측·분류·추천·생성 결과로 나타난다. 이후 사용자의 수정이나 실제 결과가 다시 데이터로 축적되면 시스템 개선에 활용될 수 있다.
### 사람과 AI의 역할을 분리하는 기준
사람에게 남겨야 할 역할은 단순히 ‘최종 확인’이 아니다. 문제 정의, 중요한 기준 설정, 예외 해석, 가치판단, 책임 있는 승인처럼 맥락이 필요한 업무는 사람이 중심이 되어야 한다. AI는 탐색·정리·후보 생성·패턴 분석처럼 반복성과 규모가 큰 영역에서 강점을 가진다.
### 실패 사례에서 배우는 방법
AI가 잘못된 결과를 냈을 때 모델만 탓하면 원인을 놓칠 수 있다. 실제 실패 원인은 잘못된 목표 설정, 부적절한 데이터, 잘못된 입력, 운영환경 변화, 사용자 과신, 검토 절차 부재 중 하나일 수 있다. 따라서 문제 발생 시 `문제 정의 → 데이터 → 모델 → 입력 → 출력 → 사람의 사용 방식`을 순서대로 점검해야 한다.
## 🔎 추가 심화 학습 \| 디지털 리터러시를 행동으로 보는 법
디지털 리터러시는 지식을 알고 있는 상태보다 실제 행동으로 나타나는 능력이 중요하다. 같은 정보를 보더라도 누구는 제목만 읽고 공유하고, 누구는 출처·날짜·원자료를 확인한 뒤 판단한다. 같은 AI 결과를 보더라도 누구는 그대로 제출하고, 누구는 근거·맥락·권리를 확인한다. 이 차이가 리터러시 수준을 만든다.
### 정보 소비자에서 정보 공동생산자로
디지털 환경에서는 사용자가 단순히 정보를 소비하지 않는다. 검색, 댓글, 공유, 생성형 AI 활용을 통해 새로운 정보의 유통과 생산에 참여한다. 따라서 잘못된 정보를 공유하거나 AI 결과를 검증 없이 재사용하는 행위도 정보 생태계에 영향을 준다.
### 알고리즘 큐레이션(Algorithmic Curation)
플랫폼은 사용자가 볼 콘텐츠를 전부 같은 순서로 보여주지 않는다. 클릭·시청시간·관심사·과거 행동을 이용해 노출 순서를 조정할 수 있다. 이 과정은 편리하지만 사용자가 비슷한 관점만 반복해서 접하게 만들 수 있으므로, 중요한 사안에서는 추천 결과 밖의 자료를 의도적으로 찾아볼 필요가 있다.
### 자동화 편향(Automation Bias)
자동화 편향은 기계나 AI가 제시한 결과를 사람이 과도하게 신뢰해 반대 증거나 자신의 판단을 무시하는 현상이다. 특히 숫자·점수·순위처럼 객관적으로 보이는 결과일수록 이러한 경향이 강해질 수 있다. 따라서 중요한 판단에서는 ‘AI가 무엇을 근거로 이 결과를 냈는가’와 ‘반대 증거가 있는가’를 함께 확인해야 한다.
### 적절한 신뢰(Calibrated Trust)
AI를 무조건 믿거나 무조건 불신하는 태도는 모두 바람직하지 않다. 과제의 위험, 검증 가능성, 데이터 품질, 결과의 가역성을 고려해 신뢰 수준을 조절하는 것이 중요하다. 아이디어 초안처럼 오류 비용이 낮은 작업은 비교적 자유롭게 활용할 수 있지만, 평가·채용·의료처럼 영향이 큰 작업은 더 높은 검증 기준이 필요하다.
### 디지털 시민성(Digital Citizenship)
디지털 시민성은 온라인 공간에서 권리와 책임을 함께 고려하는 태도다. 타인의 개인정보를 보호하고, 출처를 존중하며, 혐오·비방을 피하고, AI를 이용해 만든 콘텐츠가 다른 사람에게 미칠 영향을 고려하는 행동이 포함된다.
### 디지털 웰빙(Digital Wellbeing)
디지털 기술을 잘 활용한다는 것은 오래 사용하는 것이 아니라 목적에 맞게 통제할 수 있다는 뜻이다. 과도한 알림, 무한 스크롤, 추천 알고리즘, 생성형 AI 의존이 집중력과 판단에 어떤 영향을 주는지 스스로 점검할 필요가 있다.

## 📌 학습 요약
- 인공지능(Artificial Intelligence)은 데이터를 바탕으로 인식·분류·예측·추천·생성 등의 기능을 수행하는 시스템이며, 특정 과제에 강점을 가진다.
- 데이터(Data)·알고리즘(Algorithm)·모델(Model)·학습(Training)·추론(Inference)의 흐름을 이해하면 AI 결과가 어떤 조건에서 만들어지는지 설명할 수 있다.
- 디지털 리터러시(Digital Literacy)와 인공지능 리터러시(AI Literacy)는 정보를 비판적으로 이해하고 AI 결과를 검증하며 책임 있게 활용하는 역량으로 연결된다.
- AI 활용에서는 기술 성능만이 아니라 목적 적합성, 데이터 품질, 오류 비용, 사람의 검토와 최종 책임까지 함께 고려해야 한다.
