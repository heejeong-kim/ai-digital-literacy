[참고] 교재 용어설명

1. 이미지 그리기: ChatGPT 기능을 사용하여 사용자의 프롬프트를 바탕으로 이미지를 생성하는 기능

2. 캔버스 (Canvas): ChatGPT 환경 내에서 그림 그리기, 글쓰기, 코딩 등 다양한 창작 활동을 통합적으로 지원하는 기능

3. 이미지 이해 능력: 이미지 안에 있는 글자, 차트, 표, 기호 등을 정확하게 인식하고 해석하는 인공지능의 능력

4. 프롬프트 (Prompt): 인공지능 모델에게 특정 작업(이미지 생성, 글쓰기 등)을 수행하도록 지시하는 입력 문구 또는 설명. LLM(Large Language Model)에 사용자의 의도를 전달하기 위해 입력하는 명령·질문·지시문을 뜻하며 AI의 응답 품질을 결정하는 중요한 요소임

5. 스타일 키워드: 이미지 생성 프롬프트에서 특정 예술적 화풍, 분위기, 색감 등을 지정하기 위해 사용하는 단어 또는 구문 (예: 극사실주의, 사이버펑크, 지브리 스타일)

6. 인페인팅 (Inpainting): 이미지의 특정 영역을 선택하여 해당 부분을 수정하거나 새로운 요소를 추가하는 이미지 편집 기술

7. 미드저니 스타일 (MidJourney Style): 디지털 아트 생성 AI 플랫폼인 미드저니 특유의 시각적 미학을 지칭하는 용어로, 현실과 환상이 섞인 고해상도 질감과 회화적인 표현이 특징임

8. 독해 수준 (Read Level): 작성된 글의 난이도를 분석하여 독자가 이해하기 쉬운 정도를 평가하는 기능

9. 길이 조절 (Length Adjustment): 작성된 글의 길이를 자동으로 줄이거나 늘리는 기능

10. 편집 제안 (Edit Suggestions): ChatGPT가 글의 문법이나 스타일에 대해 자동으로 수정 제안을 제공하는 기능

11. 마지막으로 다듬기 (Final Polish): 작성된 글을 최종적으로 검토하고 완성하는 기능

12. 코딩 (Coding): 컴퓨터 프로그램이나 소프트웨어를 작성하는 작업

13. 댓글 추가 (Add Comments): 코드나 문서의 특정 부분에 주석이나 피드백을 자동으로 추가하는 기능

14. 코드 검토 (Code Review): 작성된 코드의 품질, 효율성, 가독성 등을 분석하고 개선점을 제안하는 기능

15. 변경 사항 표시 (Show Changes): 코드 뷰에서 이전 버전과 현재 버전 코드 간의 차이점을 시각적으로 표시하는 기능

16. ChatGPT ‘작업’ (Tasks): ChatGPT의 기능 중 하나로, 사용자가 지정한 스케줄에 따라 주기적으로 특정 작업을 자동으로 수행하도록 예약할 수 있는 기능. 현재 ‘GPT-4o 일정 예약 베타’ 모델에서 유료 사용자에게 제공됨

17. GPT-4o 일정 예약 베타: ChatGPT의 특정 모델로, ‘작업’ 기능과 같은 일정 예약 및 자동 반복 작업을 지원하는 베타 서비스 모델

18. 생성형 AI (Generative AI): 텍스트, 이미지, 코드 등 새로운 콘텐츠를 생성할 수 있는 인공지능 기술

19. LLM (Large Language Model): 대규모 텍스트 데이터로 학습되어 인간의 언어를 이해하고 생성하는 능력을 가진 인공지능 모델

20. Prompt Engineering: LLM으로부터 원하는 결과를 얻기 위해 프롬프트를 효과적으로 설계하고 개선하는 기술

21. 지시형 프롬프트 (Instruction Prompt): AI에게 특정 행동이나 작업을 직접 명령하는 형태의 프롬프트

22. 질문형 프롬프트 (Question Prompt): AI에게 정보나 설명을 요청하는 형태의 프롬프트

23. 역할 기반 프롬프트 (Role-based Prompt): AI에게 특정 역할이나 페르소나를 부여하여 해당 역할에 맞는 톤과 스타일로 응답하도록 유도하는 프롬프트

24. 샘플 포함형 프롬프트 (Few-shot Prompt): 프롬프트에 몇 가지 예시 질문과 답변을 함께 제공하여 AI가 특정 패턴이나 스타일을 따르도록 유도하는 방식

25. Zero-shot 프롬프팅: 어떠한 예시도 제공하지 않고 프롬프트만으로 AI에게 작업을 요청하는 방식

26. One-shot 프롬프팅: 하나의 예시 질문과 답변을 제공하고 작업을 요청하는 방식

27. Chain of Thought 프롬프트: AI에게 단계별 사고 과정을 거쳐 결론에 도달하도록 유도하는 프롬프트 방식 (예: “단계별로 생각해 봐” 또는 “step by step”)

28. GPT 탐색 (GPT Explorer): ChatGPT 플랫폼 내에서 다양한 목적과 기능에 특화된 사용자 맞춤형 GPT를 찾아보고 사용할 수 있는 기능

29. SlidesGPT: AI 기반으로 프레젠테이션 슬라이드를 자동으로 생성해주는 외부 유료 서비스. ChatGPT와 연동하여 사용할 수 있음

30. Felo (felo.ai): ChatGPT 기술 기반으로 프레젠테이션 등 다양한 콘텐츠 생성을 지원하는 AI 플랫폼

31. Gamma (Gamma.app): 아이디어 또는 텍스트를 기반으로 프레젠테이션·문서·웹사이트 등을 자동으로 생성해주는 생성형 AI 도구 플랫폼. ‘텍스트로 붙여넣기’ 또는 ‘생성’ 기능을 통해 슬라이드를 만들 수 있음

1.4 이번 학기 프로젝트 유형 3가지

이번 학기 팀 프로젝트는 아래 세 가지 유형 중 하나로 진행하는데 유형은 아이디어의 좋고 나쁨을 가르는 분류가 아니라 무엇을 만들어 무엇으로 시연할 것인가를 정하는 구분이며, 유형이 정해져야 MVP 범위·필요 역량·검증 방법이 결정

3. 최종 프로젝트의 방향성 검증

3.1 필요성 검증

핵심 확인 3가지

  • 실제 사용자가 겪는 문제인가?
  • 현재 해결 방식과 가장 큰 불편은 무엇인가?
  • 이 문제를 해결하면 사용자의 결과가 어떻게 달라지는가?

선정한 프로젝트가 해결하려는 문제가 실제인지 다시 확인하는 단계로 아래 내용으로 체크하여 정리함

  • 실제 사용자가 겪는 문제인지 확인함
  • 현재 해결 방식과 가장 큰 불편을 기록함
  • 문제를 해결했을 때 달라지는 사용자 결과를 기록함

시장 문제와 목표 사용자는 함께 정의하는 것으로 먼저 타겟을 임의로 정하고 문제를 끼워 맞추는 것이 아니라, 실제로 관찰한 문제를 가장 자주·크게 겪는 사람이 누구인지 근거를 통해 좁혀 감

3.2 차별성 검증

핵심 확인 3가지

  • 비슷한 서비스나 해결 방식이 있는가?
  • 기존 방식과 비교해 사용자의 결과가 어떻게 달라지는가?
  • 차별성이 약하면 문제나 사용 상황을 어떻게 좁힐 것인가?

후보와 비슷한 서비스 또는 사용자의 현재 해결 방식을 1개 이상 찾아보고, 우리 프로젝트가 기존 방식보다 달라지는 점을 한 문장으로 정리

  • 비슷한 서비스나 기존 해결 방식 1개 이상을 확인함
  • 기존 방식과 비교해 사용자의 결과가 어떻게 달라지는지 기록함
  • 차별성이 약하면 문제나 사용 상황을 더 좁힘

차별성은 기능을 많이 넣는 것이 아니라 기존 방식과 비교했을 때 사용자의 시간·비용·품질·경험 중 무엇이 달라지는지 설명할 수 있어야 하는 것으로 차이가 확인되지 않으면 새로운 기능을 추가하지 말고 문제와 사용 상황을 더 구체적으로 좁힘

3.3 생성형 AI 필요성 검증

핵심 확인 3가지

  • 생성형 AI가 맡는 작업은 무엇인가?
  • AI 없이 해결하는 방법과 비교해 어떤 가치가 생기는가?
  • AI 결과 중 사람이 확인해야 할 것은 무엇인가?

후보의 핵심 작업을 생성형 AI로 해결하는 방식과 AI 없이 해결하는 방식을 나란히 적고, 두 방식의 차이를 비교

  • 생성형 AI가 맡는 작업과 AI 없이 해결하는 방법을 각각 적음
  • 두 방식의 시간·비용·품질 차이를 비교함
  • AI 결과의 위험과 사람이 확인할 지점을 기록함

AI를 사용할 수 있다는 이유만으로 필요한 것은 아니며 AI 없이도 같은 결과를 더 쉽고 안전하게 만들 수 있다면 AI 활용의 필요성을 다시 검토하고 AI를 사용한다면 AI가 맡는 작업과 사람이 최종 확인할 지점을 분명히 나눔

3.4 실현성 검증

핵심 확인 3가지

  • 필요한 데이터·도구·사용자를 확보했는가?
  • 팀의 역량과 남은 기간 안에 핵심 기능을 만들 수 있는가?
  • 선택한 프로젝트 유형의 필수 조건을 갖추었는가?

선택한 프로젝트를 남은 기간과 팀의 현재 조건 안에서 만들 수 있는지 점검

  • 필요한 데이터·도구·사용자와 프로젝트 유형의 필수 조건을 확보했는지 확인함
  • 핵심 기능을 남은 기간 안에 만들고 테스트할 수 있는지 확인함
  • 확보하지 못한 조건은 범위를 줄이거나 유형을 다시 검토함

실현 가능성은 만들고 싶은 기능의 수가 아니라 실제로 확보한 데이터·도구·시간을 기준으로 판단하는 것으로 필수 조건을 확보하지 못했다면 범위를 줄이거나 대체 방법을 기록함

3.5 안전성 검증

핵심 확인 3가지

  • 개인정보·저작권 문제가 생길 수 있는가?
  • AI 오류나 편향이 사용자에게 피해를 줄 수 있는가?
  • 서비스 중단·비용·사용량 제한에 어떻게 대응할 것인가?

선택한 프로젝트에서 실제로 발생할 수 있는 위험을 골라보고, 문제가 생겼을 때 팀이 어떻게 예방·확인·대응할지 기록

  • 프로젝트에 해당하는 위험을 선택함
  • 위험이 발생하는 상황과 대응 방법을 기록함
  • 사람이 최종 확인할 결과와 제한 조건을 정함

안전성 검증은 위험이 없다고 선언하는 과정이 아니며 입력하지 않을 자료, 사람이 확인할 결과, 문제가 생겼을 때의 수정 방법을 미리 정하는 과정

## 1. 프로젝트 개요

- 프로젝트명: 대학생 통학 불편 데이터 분석 서비스

- 프로젝트 유형: ① 데이터 수집·분석 중심

- 한 문장 정의: 대학생의 통학 시간과 불편 요소를 조사·분석해 통학 개선에 필요한 정보를 제공하는 프로젝트

- 최종 결과물: 설문 데이터셋, 분석 결과, 간단한 시각화 리포트

## 2. 해결하려는 문제와 목표 사용자

- 목표 사용자: 통학하는 대학생

- 해결하려는 문제: 통학 시간과 불편 요소가 개인별로 다르지만, 이를 비교하거나 개선에 활용할 수 있는 자료가 부족함

- 주요 상황: 긴 대기 시간, 환승 불편, 교통비 부담, 혼잡 시간대 등

- 사용자가 현재 해결하는 방법: 개인 경험에 의존하거나 주변 사람에게 물어봄

## 3. 문제 근거와 시장 상황

- 학생별 통학 시간과 교통수단을 설문으로 수집함

- 통학 시간, 환승 횟수, 비용, 불편 요소를 비교함

- 학교 주변 교통 정보와 대중교통 공개자료를 참고함

- 아직 학교 전체 학생의 통학 문제를 대표한다고 보기는 어려우므로 표본의 한계를 기록함

## 4. 기존 해결 방식과 차별성

- 기존 방식: 개인이 직접 검색하거나 자신의 경험만으로 판단함

- 기존 방식의 한계: 학생 전체의 공통 문제와 시간대별 차이를 파악하기 어려움

- 프로젝트의 차별성: 학생들의 실제 응답을 모아 통학 불편을 항목별·시간대별로 비교함

- 새로운 서비스를 만드는 것보다, 흩어진 학생 경험을 하나의 분석 결과로 정리하는 데 초점을 둠

## 5. 핵심 사용자 가치

- 학생: 자신의 통학 시간이 다른 학생과 비교해 어느 정도인지 확인할 수 있음

- 학교: 학생들이 많이 겪는 통학 문제를 파악할 수 있음

- 핵심 가치: 개인의 경험을 데이터로 정리해 통학 문제를 구체적으로 확인할 수 있음

## 6. 생성형 AI의 역할과 사용 흐름

- 데이터 수집 문항 초안 작성

- 설문 응답의 불편 유형 분류 보조

- 분석 결과를 이해하기 쉬운 문장으로 요약

- 시각화 코드 작성 보조

- 사람이 확인할 부분: 응답 분류의 오류, 분석 결과의 과도한 일반화, 개인정보 포함 여부

사용 흐름:

설문 응답 수집 → 데이터 정리 → AI를 활용한 분류·요약 → 사람이 결과 확인 → 그래프와 리포트 작성

## 7. MVP 범위와 핵심 기능

핵심 기능은 3개 이내로 제한함.

1. 통학 관련 설문 수집

2. 통학 시간·교통수단·불편 요소 분석

3. 분석 결과를 그래프와 요약문으로 제공

하지 않을 것:

- 실시간 교통 안내

- 개인별 최적 경로 추천

- 모바일 앱 개발

- 학교 공식 정책 제안 자동화

## 8. 프로젝트 유형과 구현 방법

- 선택 유형: ① 데이터 수집·분석 중심

- 확보할 것: 설문 응답 데이터, 분석 기준, 시각화 도구

- 구현 방법: 설문 도구와 스프레드시트 또는 분석 도구를 활용해 데이터를 정리하고 결과를 시각화함

- 생성형 AI는 데이터 분류·요약·분석 코드 작성 보조에 활용함

## 9. 필요한 데이터·도구·일정

- 데이터: 대학생 통학 설문 응답

- 보조자료: 대중교통 공개자료, 학교 주변 교통 정보

- 도구: Google Forms, Google Sheets, ChatGPT, 스프레드시트 차트 기능

- 일정:

- 9주차: 설문 문항과 분석 기준 확정

- 10주차: 설문 수집 및 1차 분석

- 11~12주차: 분석 결과 정리와 시각화

- 13주차: 사용자 확인 및 수정

## 10. 위험 요소와 대응 방법

- 개인정보: 이름·학번·연락처를 수집하지 않음

- 표본 편향: 조사 대상과 응답 수를 명시함

- 과도한 일반화: 조사 결과를 전체 학생의 사실로 단정하지 않음

- AI 오류: AI가 분류한 결과를 사람이 일부 표본과 대조함

- 저작권: 공개자료의 출처와 이용 조건을 기록함

- 예: ChatGPT(내용 구성) → Gamma(슬라이드 제작) → Canva AI(시각자료 제작)

- 각 AI 도구가 담당하는 역할을 구분하고, 하나의 발표 결과물로 연결함

- 발표 주제·참고자료·발표 시간·청중 조건을 반영한 결과물을 완성함

- 발표자료의 핵심 내용이 참고자료와 일치하고, 사실 오류가 없음

- 학생 3~5명이 생성된 발표자료와 대본을 이해하고 수정할 수 있음

- 기존 방식보다 발표 초안 작성 시간이 줄어듦

- 사용자의 80% 이상이 발표 준비에 도움이 된다고 평가함
